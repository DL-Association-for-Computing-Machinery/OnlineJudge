# 服务端存储与 Worker 缓存设计

日期：2026-10-27。版本：0.7。状态：M0 已有固定材料授权读取；[本地不可变材料存储](material-store.md)已验证流式写入、不覆盖提交、快照、并发及故障恢复原语。逻辑备份捕获与恢复材料核验已用受控夹具验证，独立故障域和生产演练仍待验收。正式题目材料发布与 Worker 持久缓存仍待推进。M0 历史证据见[M0 记录](../acceptance/m0-experiment.md#有效租约限定的材料入口)。关联 [总体架构](system-design.md)、[ADR-001](001-go-gin.md) 与 [需求验收](../development/requirements.md)。

## 1. 决策与取舍

用户明确要求：“先采用数据库保存小数据＋校内本地磁盘保存大文件＋Worker 本地缓存，预留以后迁移到对象存储的接口”。

- 首期减少独立存储服务的部署与维护，核心材料在校内可用；Worker 复用固定版本材料，减少重复下载。这是设计理由，不是容量实测结论。
- 主控磁盘承担大文件的权威存储，存在主机、磁盘与网络故障点；同机 API 多副本及 Worker 缓存不提供主控容灾。备份必须使用独立故障域的存储，并演练恢复。
- NFS/NAS 和校内对象存储作为后续统一存储后端备选，本轮不引入。公有云不能成为断外网校赛的唯一材料来源；不把全部大文件放进业务数据库。
- 数据库仍按已确认的 PostgreSQL＋持久化任务表路线优先验证，尚未完成正式组件准入；本次选择不等于数据库或沙箱已经验证。

## 2. 数据归属

| 数据 | 首期权威位置 | 约束 |
| --- | --- | --- |
| 用户、权限、题目/比赛元信息、提交状态、结果、任务 | 数据库 | 按所属业务模块和事务管理 |
| 活动登录会话 | Redis | 已确认共享 Session；账号状态与权限仍归数据库，会话丢失不丢提交，恢复须防撤销回退，见 [会话设计](session-design.md) |
| 受大小限制的提交源代码 | 数据库，与提交/任务接收事务一起持久化 | 按实际字节及编码规则校验；大于上限明确拒绝，不静默改走临时文件；限制值待定 |
| 题目测试输入、标准答案、图片、附件和原始题目包 | 主控机上的校内持久化目录 | 数据库保存逻辑文件标识、大小、哈希、所属题目版本及权限；不保存用户可控的宿主绝对路径 |
| Worker 下载的固定版本材料 | Worker 本地缓存 | 可删除后重建，不是唯一副本或备份；有容量与下载并发上限 |
| 编译产物、运行输出、临时日志 | 任务临时目录 | 按任务限制大小和生命周期；需留存的诊断材料显式转入受控持久化存储 |
| 选手未提交代码草稿 | 当前浏览器 IndexedDB＋idb | 按账号/题目/比赛/语言隔离，保存/恢复/冲突/清理按 [草稿规则](frontend-sandbox-options.md#32-已确认的-indexeddb-本地草稿规则)；不新增服务器同步或跨设备恢复 |

“小/大”不是由扩展名自动决定：按数据用途、大小限制与保留策略分类。大小上限、缓存额度、日志保留及备份容量在硬件核验后设定。

## 3. 拓扑与授权

```mermaid
flowchart LR
    C[浏览器] --> E[校内入口]
    subgraph H[首期可信主控机]
        E --> A[Go API 副本 1 至 N]
        A --> D[(数据库与小数据)]
        A --> S[文件存储适配器]
        S --> F[(同一持久化大文件目录)]
    end
    W[其他机器上的 Worker] -->|任务授权请求| E
    A -->|授权材料流| W
    W --> K[(按版本与哈希缓存)]
    K --> T[任务专用材料目录]
    T --> X[受限编译 / 运行 / 检查]
```

- 首期 API 副本在同一主控机共享同一持久化目录；容器部署时也必须映射同一持久化位置，不能各写容器临时层。数据库的具体部署位置仍由硬件预算确定，图示不是已部署拓扑。
- Worker 可分布多机，通过受认证、任务范围内的材料接口下载；不直接挂载整个主控私有题库，不获取业务数据库凭据。下载实现可评估成熟 HTTP 文件传输能力，不自研通用分布式文件系统。
- API **跨主机扩展之前**，必须使所有副本经统一材料服务或共享/对象存储后端访问同一份权威材料；不能依靠负载均衡、粘性会话或人工复制目录掩盖数据缺失。
- 每次读取先校验题目/比赛授权或有效 Worker 任务授权；命中缓存不能绕过授权。猜中逻辑标识或内容哈希不授予访问权。
- 选手进程只能访问当前执行阶段所需材料：运行阶段不暴露标准答案、其他测试数据或整个缓存；检查阶段按需提供答案和输出。缓存根目录及服务凭据不进入选手沙箱。

## 4. 文件发布与一致性

数据库与文件系统不共享一个原子事务，按“先完整保存材料、再发布数据库引用”设计：

1. 校验上传者权限与大小预算，在受控暂存位置流式写入；文件名由服务端生成。解包时限制展开体积、文件数及路径，不接受越界路径或可访问宿主文件的链接。
2. 校验实际长度、内容哈希和材料清单，完成持久化后才转为不可变文件；具体文件系统的崩溃一致性与并发写入语义须验证。并发写同一材料时不可暴露半文件或覆盖已发布内容。
3. 在数据库事务中发布题目版本及其完整材料引用；发布失败时材料可以成为暂存孤儿，不能反过来先发布引用再补写文件。
4. 未发布或未引用材料按保留期回收，回收与正在发布的文件有协调机制；存在有效题目版本、历史提交、备份保留或进行中任务引用时不能删除。引用判定不能仅依赖一次无锁快照。

已确认原始题包只读保留并记录哈希、来源及使用依据，仍为受限材料；内部转换、修正和重新导入不覆盖原包，原包与发布材料按引用/保留策略纳入备份，详见 [题包设计](problem-package-design.md)。已发布题目材料不原地修改，新数据产生新版本。磁盘不足、哈希失败或写入中断时，上传/发布返回明确失败；材料读取失败属于系统错误，不能判成选手答案错误。

## 5. Worker 缓存

- 缓存键关联不可变材料标识与哈希；题目版本或材料变化不复用旧内容。下载到暂存文件，校验完整性后再标记可用，同节点重复下载需合并或协调。
- 正在使用的缓存不得被回收。缓存目录由 Worker 控制，避免选手输出反向污染；每个任务分别准备目录并限制可见文件。
- 缓存有磁盘上限、水位、下载并发及清理策略；缓存清空、损坏、Worker 重启后可以重新下载。赛前可预热正式比赛材料，但预热不代替在线授权和校验。
- 主控存储失效时，已缓存材料可能继续供已授权任务使用，但不能保证整个判题链路可用；任务领取、代码、结果回报与新材料仍有服务依赖。

## 6. 对象存储迁移接口

应用只依赖小型文件存储接口：不可变写入、读取元信息、流式读取；清理由受控保留流程调用。接口返回逻辑标识、大小和内容哈希，明确不存在、无权限、完整性失败与服务不可用等错误。调用需要取消/超时，不能要求一次把大文件读入内存。

首期用本地目录适配器实现；数据库中的物理位置归存储模块管理。业务模块、Worker 协议和题目版本只引用稳定逻辑标识，不依赖磁盘路径、S3 bucket URL 或供应商 SDK。保留对象存储适配位置，不提前实现多套后端，也不假定所有对象存储支持相同的版本控制功能。

未来迁移作为独立运维任务：备份 → 在受控窗口暂停材料变更 → 按清单复制 → 核对数量/大小/哈希 → 更新位置映射 → 验证授权读取和重判 → 保留旧材料一段回退期。切换失败可按记录恢复旧映射；切换后若已接受新写入，回退必须先处理新增材料。是否采用在线迁移届时另行设计，本轮不承诺无停机迁移或自动双写。

## 7. 备份与验收

备份包括数据库快照、对应版本的材料清单及全部被引用文件；恢复时核对引用完整性和内容哈希。相同磁盘的另一个目录、Worker 缓存以及同机副本都不作为独立备份。已确认一致性恢复集合＋独立副本＋定期恢复演练，pgBackRest/restic 分别优先验证数据库和大文件；恢复代次、会话/令牌撤销及分类两阶段回收见 [运维设计](../operations/operations-design.md)。频率、保留时间、RPO/RTO 与备用设备等待学校条件和恢复目标确定。

`toolchain db` 中的 `TestRestoreSubmissionAndMaterials` 使用静止的固定判题夹具。它把源 schema 的逻辑备份和按摘要命名的文件复制到暂存目录，再恢复到一个新建、仅监听私有 Unix socket 的 PostgreSQL 集群和独立材料目录。目标端不重跑迁移或重建夹具；测试核对历史源码字节、终态和原键回执，领取备份中已接收的排队任务，并经材料服务核对其冻结清单和全部输入/答案。材料缺失或内容损坏时不给 Worker 返回文件。

`restore-loop` 在本地固定离线 Desktop 沙箱先判出一个合成 AC，再用 `capture-backup` 捕获静止的源库与材料，并在复制前记录源端完成清单摘要。确认源库已停止后，目标容器用 `verify-backup` 核验接收副本，再运行 `pg_restore`，并在独立的运行目录核验恢复库引用的材料。`fence-restored-leases` 对这份只含已完成任务的夹具应零变更。测试在目标库开启原提交的新判题代次；新 mTLS 控制端与 Worker 使用从已核验运行目录取出的材料再判为 AC，核对历史结果和源码字节不变、没有重新提交。该专项未验证活动写入、旧凭证隔离或产品重判入口；同机容器与临时目录不构成独立故障域。

[A+B 恢复重判](../acceptance/delivery-evidence/aplusb-restored-rejudge.md)复用这套流程，额外在恢复后验证 17 点的全部 34 条引用。原始运输清单和可信摘要由测试操作员单独提供，不从接收侧文件重新建立信任；恢复用的输入和答案只能来自已核验的运行目录。缺失任一引用文件即拒绝恢复材料验收。

### 恢复材料核验

在隔离的恢复库和静止的材料目录上执行 [环境配置与恢复维护 的核验命令](../operations/runtime-maintenance.md#会话恢复维护)。命令只使用显式恢复 DSN，并确认实际库名及兼容 schema。所有数据库读取来自同一个只读快照；文件只读，不生成匿名副本、修复材料或改变数据库。隔离和文件在检查期间不变仍由运维保障。

- 判题：校验已注册清单的规范编码、摘要、版本、语言和测试点，按摘要读回每个输入和答案。
- 私有草稿：用文档及完整引用清单重算导入修订，发现缺失或替换的引用行；按大小和摘要核对全部对象。
- 冻结计划：校验正式计划及存在的对拍计划的编码、摘要、原申请与草稿绑定。原来源锁须与草稿文档匹配，每个对象的摘要和大小须出现在原草稿清单中。不按当前执行环境重新准入旧计划，也不重新生成题意、用例或结果。
- 已发布题面：从发布记录枚举所有修订的封存题面，按大小和摘要核验对象；旧修订与本机限定发布同样纳入。题面对象计入私有材料引用。

全部通过才输出清单、草稿、计划和引用计数；共享对象可重复计入引用数，读文件的去重缓存有界。缺文件、坏字节、坏清单或错绑都失败；保持隔离，换用匹配的数据库及材料集合后复查。此命令不证明独立故障域、备份捕获时点或保留策略，也不核验私钥、所有业务历史、沙箱执行和 RPO/RTO。没有 schema 迁移。

### 捕获逻辑备份

[捕获命令](../operations/runtime-maintenance.md#捕获逻辑备份)支持应用 schema 位于 `public` 的专用数据库。读取方开启只读可重复读事务，导出快照并维持到 `pg_dump --snapshot` 和材料清单完成。两客户端固定同一 Unix socket、端口、数据库和角色；复制文件时对实际写出的字节计算哈希，私有对象同时核对长度。新提交可以继续写入不可变的新材料，快照之后的引用不进入本轮；捕获期间不得执行会删改文件、变更 schema 或更换端点的操作。长快照会推迟数据库旧行回收，时限和空间按实际负载验证。

目录包含 `postgres.dump`、`judge/`、`private/` 和 `materials.jsonl`。清单按材料目录和摘要记录每份已校验文件的长度；相同目录内重复引用只复制一次。所有文件和目录同步后才以不覆盖方式发布 `manifest.json`，其中包含归档和清单的长度与 SHA-256。归档包含私有数据库内容，按备份权限管理整组文件。输出须位于可信父目录及支持文件、目录同步与硬链接的 Linux 文件系统；使用专用凭据文件时，保持其内容不变。凭据文件、发布配置、密钥和 Redis 不纳入这组文件，按现有流程独立保管。

失败时没有完成标记的目录不可用；在新目录重试，不复用部分输出。若完成标记已经发布但命令报告持久性不确定，保持隔离，先按下节核验完整性。独立设备转运、介质保护、保留策略及恢复时间仍须验证。

备份格式未变。旧包的传输核验仍可读取原清单；如果旧包漏收了数据库引用的题面，恢复材料核验会报缺失。应从匹配的可信材料副本补齐后复验，或重新捕获备份。

### 核验收到的逻辑备份

[接收端命令](../operations/runtime-maintenance.md#核验收到的逻辑备份)先用独立取得的 SHA-256 绑定完成清单，再按其校验 `postgres.dump` 和 `materials.jsonl` 的大小与哈希，核对两套材料的路径范围、实际文件、长度、摘要和数量。目录必须正好匹配清单；拒绝多余文件、重复条目、未封存包、符号链接和非普通文件。捕获与核验最多支持两套材料共 100 万个独立文件；材料清单逐行处理，大文件流式读取。目录 `0700` 或 `0500`，文件 `0600` 或 `0400`。核验期间及核验到还原之间，由运维阻止其他进程写入备份。

成功仅证明接收字节与受信摘要绑定的集合一致。命令不修改备份、不连接 PostgreSQL，也不检查归档内的数据或证明来源可信。成功后再在隔离库演练 `pg_restore --single-transaction --no-owner --no-privileges`，按恢复存储要求布置两套材料并执行[恢复材料核验](#恢复材料核验)。独立介质、来源认证和生产恢复时间不由此项证明。

### 完整验收目标

以下为完整验收目标，对应 AC06、AC16—20 及新增 AC22；M0 仅完成有效租约范围内读取、固定哈希、异常文件拒绝及同机双控制端读取子项，不能视作全部通过：

- 多个同机 API 副本上传后互相可读；重启或重建后引用及文件仍完整。
- 写入/发布各阶段中断、并发写入、磁盘不足与孤儿回收不产生可见半文件、丢失引用或误删。
- Worker 缓存冷启动/命中/损坏/清空/回收时结果一致；实际选手沙箱不能读取标准答案或整个缓存。
- 未授权用户、过期/无效任务及目录穿越请求不能取得私有材料；缓存命中也不能越权。
- 用独立备份恢复数据库及文件，再运行既有题目版本和重判，确认材料与成绩可追溯。
- 硬件确定后测量冷/热缓存网络流量、磁盘 I/O、下载延迟和空间水位；不以人数或组件存在推导容量达标。

首次实现只验证本地适配器及逻辑接口契约；真正引入对象存储时，必须对该后端另做一致性、迁移、回退与权限验证。
