# 首期题型与答案检查设计

日期：2026-10-25。版本：0.8。状态：首期规则已确认；M0 已实现有界文本比较，并在独立 Linux VM 验证 GNU++17 编译、逐点比较、错误/超限及隔离分项。完整 Worker 编排、浮点/testlib、统一异常归因和生产预算待验证，详情见[M0 记录](../m0-experiment.md)。关联 [总体架构](system-design.md)、[需求与验收](../requirements.md)、[Worker 与沙箱](frontend-sandbox-options.md#4-判题-worker-与沙箱的职责)及 [存储设计](storage-design.md)。

## 1. 已确认范围与取舍

用户确认首期支持标准输入输出式算法题，提供文本比较、浮点容差和受限 SPJ（自定义答案检查器）；交互题与直接提交答案题后续扩展。沿用 ICPC／ACM 通过/失败模式，全部要求的测试通过才 AC，不引入部分分。

| 场景 | 首期行为 | 边界 |
| --- | --- | --- |
| 普通文本答案 | 默认按空白分隔 token，逐项比较，接受 ASCII 大小写差异，忽略空白数量及换行差异 | 题目明确要求大小写时显式配置；token 数量与内容须匹配，不忽略额外输出 |
| 浮点答案 | 每题显式开启，配置绝对容差、相对容差或两者；同时配置时满足任一个即可 | 没有全站通用误差；未启用时仍按文本比较，详见第 3 节 |
| 非唯一答案及复杂校验 | 提供版本固定、经验证的受限 SPJ | 检查输出是否满足题目要求，不要求与某一参考输出完全相同 |
| 严格区分整数与浮点字段的混合输出 | 使用自定义检查器 | 不因开启全局浮点比较而放宽本应精确的整数要求 |
| 交互题、直接提交答案题 | 后续扩展 | 首期不接受为已支持题型，不由沙箱接口推导支持 |

选择理由：比纯文本比较覆盖更多训练与校赛题目；代价是维护浮点边界、检查器构建/运行/结果映射及出题验证。可以先打通文本判题，再逐项实现浮点与 SPJ；首期整体交付仍需覆盖三类已选能力及首批语言，不能用文本闭环通过代替全部范围验收。

## 2. 文本比较规则

- 输出与参考答案均按约定空白分隔为有序 token；忽略前后空白、空白数量及 token 之间换行位置。token 数或内容不同为 WA，超限输出另按执行限制分类，不无限读取。
- 后续用户要求对标官方 ICPC／ACM，默认接受 ASCII 字母大小写差异；替代此前默认区分大小写的提案。题目明确要求时显式固定大小写敏感配置并验证；不自动数字化、合并 token 或忽略额外文字。M0 实现按 ASCII 空格/TAB/LF/VT/FF/CR 分词，只折叠 A-Z；合法 UTF-8 的非 ASCII 内容按字节比较。参考畸形字节/超限为材料错误，选手畸形字节为不匹配、输出超限单独返回；检查器上限 1 MiB、单 token 64 KiB，生产参数仍须按题环境固定。不依赖 locale 或 Unicode 大小写折叠，测试见 `internal/judging/text_test.go`。

| 参考答案 | 选手输出 | 默认文本比较 |
| --- | --- | --- |
| `1 2` | `1` 与 `2` 分两行 | 相同 token，内容正确且其他执行条件通过时可 AC |
| `YES` | `yes` | 默认匹配；显式大小写敏感题为 WA |
| `1 2` | `12` 或 `1 2 3` | WA |
| `1` | `1.0` 或 `001` | WA；文本模式不自动转换数字 |

题面样例保留原始空格/换行的展示约定与此默认判题容忍度分别管理；渲染器不能预处理选手输出或改变正式答案。需要精确文本布局的题目使用经过验证的自定义检查器，不静默修改本站默认比较策略。

## 3. 显式浮点容差

2026-10-25 用户确认以下比较语义及配套约定。每题按答案语义显式开启浮点模式，配置绝对容差 `A`、相对容差 `R` 或两者；没有全站默认误差，不在运行时套用未声明的 epsilon。参数须为有效、有限、非负值，至少配置一项，题面明确容差；缺失或非法配置阻止发布，不能为迁就错误答案放宽规则。具体误差值由每题确定，本次没有选定全局阈值或数值库。

设参考值为 `a`、选手值为 `s`，规则为：

| 配置 | 数值 token 通过条件 |
| --- | --- |
| 仅绝对容差 `A` | `abs(s - a) <= A` |
| 仅相对容差 `R` | `abs(s - a) <= R * abs(a)` |
| 同时配置 `A` 和 `R` | 上述任一个条件成立，即 OR，不要求同时成立 |

边界取等号。相对误差以参考值为基准，不改成以选手值或双方最大值为分母；当参考值为零时，相对项右侧为零，因此接近零且需要容忍误差的题目通常需要配置绝对容差。

- **数值识别**：沿用有序 token 比较；浮点模式中，以参考 token 是否为数值决定该位置的比较方式。数值支持带可选正负号的十进制与科学计数法，只接受有限值；数值位置的选手 token 非法或为 `NaN`/正负无穷大时判 WA，不将它们作为有效数字参与比较。
- **混合文本**：参考非数值 token 仍按题目固定的文本规则（默认接受 ASCII 大小写差异，显式要求时敏感）比较，不把所有 token 强制转为浮点。`NaN` 等若被用作普通文字，不因此获得数值含义；预期为数值却给出无效标准答案，应在出题验证时阻止发布，不能悄悄降级成文字使其通过。没有字段类型的通用比较器不能自行判断出题意图，需结合标准答案与验证材料审核。
- **整数边界**：浮点模式中，可解析的整数 token 也按容差比较；严格整数与浮点字段混合用 SPJ 分别校验。未启用浮点时，`1` 与 `1.0` 仍按文本判不同；额外或缺失 token 仍为 WA。
- **配置和发布**：容差、比较模式及实际比较实现版本绑定不可变题目版本。非法配置、无效标准答案或必要边界验证失败阻止发布；运行时材料损坏或比较器故障归系统错误，不能算选手 WA。配置变更须生成新版本并重新验证，历史提交/重判使用明确记录的版本。

验证集须覆盖仅绝对/仅相对/两者组合、边界内/等于/外（包括只满足其中一项）、零/接近零/负数、科学计数法、非法数字/NaN/无穷大、非数值 token 大小写、额外/缺失 token、未开启浮点与严格整数混合；参考答案和配置错误应阻止发布，选手非法数值应为 WA。

数值表示精度、解析器、溢出/下溢和超长 token 的有界处理、不同节点及所选 testlib 适配的一致性仍须定版并验证；不能让有限数字静默变成无穷大或零后误判，也不能依赖 locale/库的未经核验默认值。尚无数值运行测试，不宣称支持任意精度或完整 2025-09 兼容。依据为 [ICPC 2025-09 浮点 token 比较](https://icpc.io/problem-package-format/spec/2025-09.html#comparing-floating-point-tokens)，2026-10-25 只读核对；本站后续按 ICPC 对标确认默认接受 ASCII 大小写差异，题目要求时显式配置敏感模式。

选择理由：绝对与相对容差兼顾接近零及不同数量级答案，OR 语义便于与所选题包子集映射；代价是维护边界验证和数值实现一致性。没有采用全站统一误差或将两项强制 AND，也不直接继承第三方比较器默认行为。未通过数值边界验证前不能声明浮点题支持完成。

## 4. SPJ 的职责与隔离

SPJ 根据本测试输入、必要的参考材料和选手输出作出正确/错误判定。它不负责执行选手程序，不决定比赛罚时或把判题尝试直接写入榜单；应用层仍按当前租约与重判代次接收结果。

- 检查器程序、构建环境、参数和材料哈希绑定不可变题目版本；更新须新建版本并重新验证，重判使用明确记录的配置，不就地替换历史检查器。
- 编译和运行均进入受限执行环境；限定时间、内存、进程、输出及临时盘，按任务提供最小材料，不授予数据库账号、网络访问、宿主路径或整个私有题库。编译器/检查器本身也不作为可信业务进程运行。
- 选手输出不满足题目约束可判 WA；检查器构建失败、崩溃、超时、资源超限、材料不可读或协议结果无效属于系统错误，不能直接判选手 WA 或计罚时。有限重试和人工处理沿用任务恢复协议，重复失败不得无限占用正式赛资源。
- 出题验证应包含多个正确输出、代表性错误输出、边界/畸形输出及检查器自身失败；参考程序通过不代表检查器一定正确，非唯一答案须验证多种合法结果。反馈按比赛授权和大小预算呈现，不泄漏正式测试数据。

用户后续确认 ICPC 输出验证器协议、testlib 优先验证及首批 GNU++17 SPJ，详见第 4.1 节。构建制品分发、完整 testlib 适配映射、精确版本及资源预算仍待验证，不因接口选定而声明完整题包兼容或检查器已可运行。

### 4.1 已确认的 SPJ 协议与 testlib 验证路线

2026-10-25 用户确认采用 ICPC／Kattis 输出验证器协议，优先验证 testlib，首批 SPJ 使用 GNU++17，并接受版本固定、行为核验、诊断权限及依赖准入约定。协议与检查器语言已选，testlib 仅确定验证顺序，尚未安装或正式准入。

| 边界 | 已确认规则 |
| --- | --- |
| 调用参数 | 依次提供测试输入文件、参考答案文件、反馈目录及受控附加参数；选手输出通过标准输入提供 |
| 原生协议正常退出 | 42 表示本测试答案检查通过；43 表示答案错误；其他退出码（包括 0）属于检查器系统错误 |
| 异常执行 | 构建失败、信号终止、超时、资源超限、材料/接口异常为系统错误，不能仅看数字退出码放行 |
| 复用路线 | 优先验证 testlib，通过明确适配接入上述统一边界，不能直接混用原始调用或默认退出码 |
| 首批检查器语言 | GNU++17，复用已选 GCC 15 工具链；其他检查器语言后续评估，不改变选手 C／C++、Java、Python 的既有范围 |

以上 42 仅表示本测试答案检查通过，不直接意味着整份提交 AC；应用仍须核对执行限制、全部要求测试及有效任务租约/重判代次。检查器 stdout 或错误文字不是判定指令；异常状态不能被写出的反馈或偶然相同退出码覆盖。

testlib 提供 C++ 检查器编写能力，其默认调用使用输入、选手输出和参考答案文件，默认结果码也不同于原生 ICPC 协议。适配器须显式识别所用模式，在受限环境将选手输出准备为该模式所需输入，并按已固定版本/构建选项解释原始结果，再规范化为正确、错误或系统错误。原生模式退出 0 不能被自动猜测为 testlib 成功；适配配置缺失、模式不符或未知结果须失败可见，不能依次尝试多种含义直到得到通过。

完整原始结果映射（包括格式错误、额外输出、意外 EOF 和部分分）、反馈文件及构建封装仍待实施设计并回归验证；本站首期无部分分，不支持的结果不能默认为正确。检查器/适配器自身失败仍归系统错误；选手错误由受支持且验证过的结果明确表示，不从自由文本猜测。

版本与准入要求：

- 固定 testlib、适配器、编译器构建、编译参数和构建制品哈希，随不可变题目版本记录；更新须重新验证，运行期间不按浮动分支下载头文件或切换结果映射。
- 验证读取/比较行为符合本站已确认的大小写、空白、每题浮点容差与严格整数规则；testlib 的现成比较器不因可编译就自动符合本站语义，不直接套用未核验默认值。
- 原始诊断默认供裁判排障，选手反馈按比赛授权过滤并限制大小；消息作为不可信文本呈现，不泄漏测试输入、答案、内部路径或原始凭据，不把诊断里的程序指令当作执行请求。
- 核验精确 testlib/传递依赖及适配代码的许可证、兼容性与安全信息，并在隔离 Linux 节点验证构建、调用、限制、材料可见性和故障行为后才能正式引入。具体版本、适配实现和资源数值待定，本轮仅文档，不编译检查器或执行程序。

选择理由是统一 Worker 的检查器接口，同时复用 C++ 检查器编写能力；代价是维护适配器、固定工具链、许可检查与样例回归。将首批 SPJ 限定 GNU++17 可控制验证矩阵，不由格式规范允许更多程序语言推导本站已支持。

验收关联 AC05/06/16/17/18/20：原生 42/43/0/未知码、信号/超时/超限与反馈矛盾；testlib 正确/错误和未知模式、原始/规范结果不混用；大小写/空白/浮点语义，合法/畸形输出与检查器自身故障；固定制品重判、多节点一致、诊断权限及断外网运行。testlib 适配未通过不能报告正式准入，也不能以更改已有判定规则使验证通过。

依据：[ICPC／Kattis 调用与结果协议](https://icpc.io/problem-package-format/spec/2025-09.html#invocation)、[testlib 官方项目](https://github.com/MikeMirzayanov/testlib)、[testlib 调用及可配置退出码](https://github.com/MikeMirzayanov/testlib/blob/master/testlib.h)。2026-10-25 只读核对；master 链接不是项目锁定版本，不证明适配已运行。

## 5. 判定与验收

选手编译/运行条件、答案检查和调度状态分别记录。全部要求的测试执行及检查通过才 AC；任何要求测试未完成、失败或系统错误不能标 AC。跨点顺序按第 5.1 节；单点按第 5.3 节的阶段和可信异常证据归因，不用回报先后决定结果。具体沙箱/testlib 原始结果映射须锁版本回归验证。

### 5.1 已确认的测试顺序与提前停止

2026-10-25 用户确认首期采用固定顺序＋单份提交串行测试＋首次失败停止，并接受编译复用、运行隔离、系统错误与统计约定。

| 环节 | 已确认行为 |
| --- | --- |
| 顺序与版本 | 发布题目时保存明确的必需测试点有序清单，顺序与题目版本固定；重判使用对应版本配置，不由目录枚举或节点完成先后临时决定顺序 |
| 编译与运行 | 需编译的语言每次判题尝试编译一次，成功制品在该尝试内复用；解释型语言按固定语言配置准备，不强造编译步骤。按顺序逐个执行并检查，前一点通过后才开始下一点；每个测试点使用新的隔离运行环境，不能继承上一点运行产生的可变文件或进程 |
| 任务并行 | 单份提交的一次有效尝试串行测试；不同提交仍按 Worker 并发及资源预算调度，不把串行规则扩大为整个集群只能判一份提交 |
| 首次选手失败 | 首个 WA、运行错误或已确认的资源超限结果立即停止后续测试，以该点结果汇总；不继续寻找后面可能出现的另一种错误，也不跨测试点按错误种类覆盖首个失败 |
| 全部通过 | 只有全部要求测试执行及检查通过且当前租约/重判代次有效时才能 AC；一个测试通过或进程正常结束均不代表整份提交 AC |
| 系统故障 | 检查器故障、材料损坏、Worker 异常等中止本次尝试，按既定任务恢复协议有限重试或人工处理；不作为选手失败或计罚时，不为得到选手结果继续测试或无限重试 |
| 结果和统计 | 保留实际执行结果，剩余标未执行，不能填零或假造全量通过率；汇总最大已运行点 CPU 时间及最大进程组峰值内存，编译单列，未知/截断明确标记；展示权限按第 7 节 |

例如按固定顺序第 2 点 WA，本次尝试即返回 WA，第 3 点及以后未执行；不因猜测第 5 点可能 TLE 而继续运行或改判。顺序变更须形成新题目版本并重新验证，历史尝试及重判记录可追溯相应清单。该规则只规定跨测试点汇总，不提前决定同一点内资源原因、信号和答案检查结果冲突时的优先级，也不把编译器/基础设施故障混同选手编译错误。

编译复用限于本次尝试，不自动引入跨提交编译缓存；缓存、失败重试的断点复用及运行环境池实现须另行设计验证。重领任务或重判仍遵守租约/代次与固定版本规则，不能因“单份提交串行”假设不存在掉线后旧 Worker 的迟到回报。

选择理由：减少已确定失败提交的后续资源消耗，固定顺序使结果选择规则不依赖完成时序；代价是一次判题不收集所有测试点错误。首期未采用全量测试后按错误种类汇总、提交内并行测试或裁判全量诊断模式，后续扩展须另行确认，不改写已有通过/失败定义。

依据：[DOMjudge 提前停止与结果优先级说明](https://www.domjudge.org/docs/manual/main/judging.html#lazy-judging-and-results-priority)，2026-10-25 只读核对。该文档作为资源取舍参考；本站固定顺序与首次失败语义由用户确认，不宣称继承 DOMjudge 全部优先级、并行或配置行为。

### 5.2 验收与尚未验证项

关联 AC05/06/16/17/18/20：

- 文本空白、大小写、token 数量与内容边界；浮点开启/关闭、每题参数、数值边界和混合字段约束。
- SPJ 多种正确输出、错误与畸形输出、失败/超时/非法协议状态、材料保密及有限资源；固定版本更新、旧配置重判与多节点结果一致。
- 全部测试通过才 AC、系统错误不算选手错误或罚时、重复/迟到回报不重复计分，以及断外网、Worker 掉线后的恢复。
- 固定有序清单及历史版本重判；每尝试编译一次/逐点新环境，前一点未通过不得启动下一点；不同提交有界并行。首点/中间点/末点失败后停止且保留未执行状态，不跨点改判；全通过才 AC，系统故障中止及有限恢复，乱序/重复/迟到回报不能覆盖有效结果。
- 已执行测试的耗时/内存范围准确，未执行点不填造数值；编译复用不能携带上一次测试可变文件或进程，隔离/清理失败可见。以上须用真实编排及隔离节点验证，文档示例不是执行证据。

以上为待实现验收，当前没有安装组件、编译检查器、执行选手程序、Linux 隔离测试或性能实测。输出上限、语言资源规则、SPJ 适配/构建制品/精确版本仍待验证，ICPC 协议及 GNU++17 已定、testlib 优先验证；统一模型及 2025-09 子集导入路线后续已确认，兼容矩阵待验证，见 [题包设计](problem-package-design.md)；新文档不改变已经确认的语言与存储范围。

### 5.3 统一结果分类与单点异常归因

排队、编译中、运行中、待恢复是过程状态；AC/WA/CE/RE/TLE/MLE/OLE/SE 为规范结果。SE 是可恢复或待人工处理的系统异常，不算选手错误，也不计罚时；不设 PE，已支持且明确的格式错误归 WA，未知结果不能猜成 WA 或 AC。

| 阶段/证据 | 归因 |
| --- | --- |
| 提交结构、入口、大小不合法 | 接收前拒绝，不创建 CE 结果 |
| 选手源码编译失败，或超过公布的编译预算 | CE；编译器缺失/执行服务或宿主故障为 SE |
| 运行阶段有可信资源终止原因 | CPU/墙钟时间限制为 TLE、进程组内存限制为 MLE、stdout 硬上限为 OLE；依据实际证据，不仅看退出信号 |
| 无已证实资源超限的程序异常终止 | RE；无法区分宿主故障或证据矛盾则 SE，不靠诊断文字猜测 |
| 正常运行及限制均通过 | 才进入文本/浮点/SPJ；明确错误为 WA，通过仍须全量必需测试通过才能 AC |
| 检查器、材料、节点或协议故障 | SE，停止本次尝试，有界重试/人工处理 |

先按阶段区分选手和系统故障，资源管理器明确记录的终止原因优先于随之出现的信号，不能以“信号非零”覆盖为 RE。多种原因同时存在而无法可靠判断时归 SE，不设计跨点通用错误优先级；通过时间轮询巧合或到达先后无法证明原因。沙箱映射及节点一致性锁定版本后通过故障注入验证。

testlib 的已支持格式错误、额外输出、意外 EOF 等选手错误经明确适配为 WA；原始部分分/未知结果不默认通过，不支持的模式阻止准入或报 SE。原生 ICPC 42/43 与 testlib 原始模式严格分开，信号/超时等异常仍优先于偶然退出码。

### 5.4 资源限制原则

每测试点 CPU 为主、墙钟为兜底，统计进程组总内存（含 JVM 等运行时），限制 stdout、stderr、进程/线程、临时盘和文件，默认禁网。stdout 硬限对应 OLE，stderr 独立截断/限制，不无条件把 stderr 截断映射 OLE；精确映射按固定协议验证。

编译、选手运行、答案检查各有独立预算；检查器超限为 SE，选手编译预算按已公布规则归 CE。排队、下载及系统等待不混入选手 CPU 时间，整体任务另设硬时限。语言资源参数经真实环境校准并公开，不采用未经验证的统一倍数；题目和运行环境版本固定，数值待硬件明确后测试。资源和异常不能因输出看起来正确而忽略。

验收覆盖单点资源/信号/退出码冲突、编译与检查器故障、语言进程组计量、OOM/输出限制、实际时间统计及多节点一致性，并与首次失败、重测候选和迟到回报规则联合验证；当前未执行。

## 7. 提交文件集、反馈与自定义输入

### 提交文件集

统一内部源码文件集、显式语言入口；训练试用仅开放单文件编辑与单文件上传。审计后将多文件/ZIP 及至少 10 个源文件目标移出训练首版必需范围，保留为后续增强，按实际题库需要排期，见 [交付边界](../delivery-plan.md)。下述多文件/ZIP 规则在启用对应能力前必须实现验证，不以延期宣称支持。

- 固定文件清单、原始字节哈希、语言与入口，不自动格式化、改名或修复编码；编辑器 UTF-8，导入不支持编码明确拒绝。ZIP 在接收前检查压缩/展开体积、路径、链接、重复和大小写碰撞及文件类型。
- C/C++ 按固定源文件编译规则及 main 入口，允许所需头文件；Java 显式完整主类名，默认 Main.java/Main；Python 显式入口脚本并支持允许的模块文件。精确编译命令、扩展名规则与大小写行为在 Linux 离线验证。
- 缺入口、非法结构或超限在接收前拒绝，不伪造成 CE；已接收源码的正常编译失败为 CE。只允许公布的标准/公共库与提交材料，不运行用户自定义构建脚本、联网安装或 pip。
- 提交前可核对文件集、语言和入口；本地草稿升级为原子版本化文件集及入口，旧单文件草稿保留迁移路径，不扩大为服务端草稿。

### 反馈与自测

训练试用保留真实判题反馈，自定义输入自测随训练增强交付；下述训练默认开启指自测功能正式交付后的默认配置，不要求骨架或 1A 提前实现第二条执行路径。

采用正式赛最小反馈、训练按题配置、裁判完整诊断。正式赛默认展示本队判定及过滤限长编译错误；隐藏失败点、测试数、正式 I/O/差异、精确运行资源，若公开资源汇总则赛前统一声明。训练默认保护私有数据，比赛配置覆盖日常配置；系统错误展示参考编号及恢复/人工状态。所有 API、通知和下载统一过滤，诊断转义、限制大小并标记截断；候选重测不代替当前有效结果。

自测采用受限任务、独立配额和临时结果：点击运行时固定源码/语言/入口及自有输入或公开样例，执行后收集编译信息、stdout/stderr、运行状态和资源指标；可选比较用户提供期望输出，不能称为正式 AC/WA，不调用私有数据、SPJ 或标程充当答案服务。训练默认开，正式赛默认关，可赛前统一公布开启，热身可用。

自测仅当前用户/当时队伍及授权诊断人员访问，低优先有界排队、限额、临时保留和空间清理；不影响成绩、罚时、成长或气球。重复点击幂等，取消后终止并回收资源，迟到结果不能覆盖当前界面；首期无交互 TTY、断点调试或常驻运行时。保存执行快照不等于新增服务端草稿同步。
