# API、事件与 Worker 协议

日期：2026-10-28。版本：0.10。状态：M0 提交/租约、mTLS、材料授权、固定 v2 环境、受限编排、租约守护及结果回报已实测；单槽 Worker 循环已串联客户端，可信 M0 宿主适配器通过真实执行与停止确认。常驻命令入口、跨进程独占、生产宿主、缓存和产品 API 仍待完成。协议见 [Worker OpenAPI](../../api/worker.openapi.yaml)，证据、模块边界及预算见[M0 记录](../m0-experiment.md)。关联 [总体架构](system-design.md)、[判题](judging-design.md)、[存储](storage-design.md)。

## 1. 契约与错误

采用 REST＋JSON＋OpenAPI 3.1 契约优先，前端类型优先验证 openapi-typescript；生成类型不代替运行时输入验证。接口按 `/api/v1` 分组，DTO 与数据库模型分离。当前 [健康契约](../../api/openapi.yaml)及默认关闭的 [M0 实验契约](../../api/experiment.openapi.yaml)已实现，实验凭据仅供受控本机客户端，前端仍只有健康响应检查；业务前端与生成类型待接入。

- 错误采用 RFC 9457 Problem Details 结构，保留稳定业务错误码、请求编号和适用字段错误；HTTP 状态表达认证、授权、冲突、限额等语义，内部根因只进受控诊断。
- ID 用字符串，时间以 UTC 传输并在界面按时区展示；列表分页及响应大小有界，增长列表优先游标，榜单分页绑定同一结果版本/快照。
- 异步接收返回任务/提交 ID，不把入队成功当成执行成功；可查询最终接收状态。未知回执沿用原幂等键查询，不能自动换键重发。
- 幂等键按主体和上下文限定，同键同内容返回原编号，同键不同内容冲突；写操作无盲目自动重试。并发编辑带版本条件，冲突显式返回。
- 契约、生成类型及关键响应行为纳入 CI。演进保留兼容窗口；语义破坏显式升级。官方 ICPC Contest API 是独立适配器，只声明实测支持子集。

## 2. Outbox 与投影

采用事务 Outbox、可重复投递、幂等消费和可重建投影；首期优先 PostgreSQL 持久化，不增加独立消息代理。Outbox 随首个异步派生消费者引入；训练提交结果可直接查询权威结果，不为不存在的榜单/成长/气球提前搭通用事件平台，也不将普通同步模块调用强制事件化。

- 权威事实与待发事件同事务保存；事件只携带必要 ID、类型和版本，不附源码、测试数据或凭据。
- 每个消费者维护独立处理状态；在可行范围内将去重记录与投影变更同事务提交。按对象版本防旧事件覆盖新值，必要时基于最新事实重算，不承诺全局严格有序或执行恰好一次。
- 重试有次数/时间预算，失败进入可见的人工处理状态，不静默丢弃；延迟、积压和投影版本可观测。关键资格与提交接收不能依赖滞后投影。
- 重建榜单、成长不能重复发邮件或生成气球，也不能重置已发放状态；不可重放副作用与可重建投影明确分开。
- 数据库通知只能作唤醒优化，持久化扫描负责断线恢复；邮件沿用既定 River/专用表验证路线，Outbox 与邮件任务创建明确唯一责任，不双路创建同一业务任务。
- 批量、轮询、重试与事件保留数值后续验证。原始事实、必要游标和备份恢复点协调，不能清理到失去重建依据。

## 3. 节点身份与任务范围授权

Worker 主动拉取，每节点独立身份，mTLS 双向证书认证优先验证；节点注册、能力和容量由管理员核准，不接受节点自报后无限提高权限。

`internal/worker` 负责单槽应用流程，通过 Claim、Fetch、JudgeReport、Report 小接口串联既有组件，不访问数据库或创建沙箱。每题确认回报后再领取；空队列等待 1 秒，未知回报最多 3 次且间隔 1 秒、始终复用原令牌和结果。其他错误或取消停止循环，实例不可重入/重启；取消等待执行器停止确认和排空，失败保留 ErrStopUnconfirmed。其内存重试不提供崩溃持久性，也没有实现下述产品级平滑下线。调用方必须独占依赖、核验环境，并在 Run 返回后关闭传输；详细边界见[生命周期实验](../m0-experiment.md#单槽-worker-生命周期)。

M0 已验证子集：[Worker 契约](../../api/worker.openapi.yaml)提供独立 loopback TLS 1.3 领取/续租/回报及逐次授权材料入口。证书唯一 URI SAN 绑定节点 ID 与凭据版本，逐请求重验证书、逐事务校验节点记录，拒绝代理头/JSON 自报身份；原租约令牌关联节点、尝试及代次，无新增数据库模型。真实控制端进程和 TLS 客户端的证据见 M0 记录。证书生命周期工具与真正执行 Worker 仍未交付。

M0 执行端增加 `workerclient.Renewer` 和 `execution.LeasedRunner`：前者负责有界 mTLS 续租，不依赖数据库；后者通过续租/停止小接口监督独占执行槽，不耦合 HTTP 或 Docker。执行前续租、每 5 秒刷新，从请求前的单调时间计算 25 秒本地预算（控制端固定 30 秒契约），失败或状态未知取消。独立停止确认后仍永久停用旧执行器，禁止把取消 HTTP 当作远程终止。`internal/workerhost` 实现专用 M0 宿主检查、传输及整容器停止/PID 核验，依赖 `experiment` 固定配置，不反向依赖 Worker 编排；调用方通过现有小接口注入。Worker 入口与跨进程独占未接入，详见[宿主适配器](../m0-experiment.md#可信宿主适配器)。

真实结果通过 `LeasedRunner.JudgeReport` 在执行/清理成功后形成绑定尝试及材料的 `submission.Result` 摘要值；`workerclient.Reporter` 只负责有界 mTLS 发送与确认分类，不依赖数据库或沙箱。原契约与存储指纹不变；只有 204 确认成功，状态未知保留原租约/原结果供显式重报，不自动重跑选手代码。执行错误不产生回报，详细证据归档及待回报持久化尚未实现。摘要语义、真实数据库/沙箱联合证据和测试夹具边界见[真实结果回报](../m0-experiment.md#真实结果回报)。

实验版本由 `OJ_EXPERIMENT_MATERIAL_VERSION` 显式选择，默认 v1；v2 把本机镜像身份、平台/内核、工具版本、启动参数与预算纳入清单摘要。提交入口和控制端必须匹配版本，旧任务不重标，历史回执仍可查询。未来执行端只能消费已核验的已知配置，不能把清单中的命令当成任意可执行输入；当前仅独立沙箱测试执行环境核验。配置归 `internal/experiment`，SQL/租约模型不变，详见[M0 固定环境](../m0-experiment.md#固定执行环境与新材料版本)。

- 服务端每次领取、续租、下载和回报均检查节点启用状态、凭据版本及授权，不能只在 TLS 握手时检查。证书签发、续期、轮换、吊销和到期告警须支持校内离线运维，具体工具和窗口待验证。
- 私钥及节点凭据不进入选手沙箱、普通日志或公开离线交付包。Worker 不持有数据库凭据，不使用浏览器 Session，不获取全私有题库。
- 领取后仅授权当前节点、任务、尝试、有效租约、重测代次和恢复代次所需材料；服务端核验组合条件后才能生效，猜中 ID/哈希不赋权。
- 平滑下线停止新认领，允许有效任务完成；紧急撤销使旧身份及旧租约不再获授权，旧回报无效，任务有界恢复。重新启用先核验环境与自检。
- go-judge 等执行服务仅节点本地受控访问，按所用组件能力配置独立认证/隔离，不开放给选手网络；不得沿用公开示例的宽松配置。

## 4. 调度与过载

`workerclient.Acquirer` 负责一次领取及当前租约的材料准备，通过已有 POST 接口交互，不依赖数据库或沙箱。204 表示无可领任务；领取回执未知不自动重领。`Fetch` 只接受执行器支持的固定 v2，核对提交归属、源码/清单及逐文件哈希，全部成功后返回内存描述与材料集合。每请求 3 秒、整次下载 15 秒；与续租独立连接预算，执行前仍须由 `LeasedRunner` 重新续租。无持久缓存或自动恢复；详细预算与失败语义见[客户端实验](../m0-experiment.md#领取与材料客户端)。

采用比赛优先、参与者公平排序、有界队列。后续用户要求参考 DOMjudge 后，公平性采用其虚拟排队时间思路，替代早期严格逐参与者轮转提案；不是复制完整实现或固定常数。

- 普通模式为训练保留最低服务份额；明确启用比赛专用模式时可暂停新的训练执行，已接收任务保留、展示原因并于恢复后继续，不静默饥饿或丢弃。
- 公平主体为团队赛参赛队/个人赛个人，同主体保留提交先后。持续密集提交的后续任务在虚拟时间上后移，旧的基础设施阻塞任务不能永久提高该主体惩罚。虚拟时间不改变实际接收时间、罚时或排名。
- 按优先级、能力、节点预算选择可运行任务；不抢占正在执行的提交、不超量预取。批量重测和自测有界、低优先，紧急重测须显式授权。
- 用户/团队、比赛及全局限速和积压额度跨 API 共享原子状态，不能仅按校园出口 IP。压力过高在接收事务提交前明确拒绝；事务成功后不删除、不覆盖为“只判最新提交”。重复幂等请求返回原提交。
- 算法、公平等待、训练份额、扫描窗口和负载参数须用真实混合负载验证。[DOMjudge 服务源码](https://github.com/DOMjudge/domjudge/blob/main/webapp/src/Service/DOMJudgeService.php)是既有讨论参考，分支可变，其中 60 秒常数不是本站已定参数。

## 5. 验证要求

覆盖多 API/Worker 并发认领、节点撤销与轮换、租约到期/恢复代次、重复及迟到回报、未知接收回执、乱序事件、消费者崩溃重放、投影重建、重测冲突与副作用去重。至少两个 API 和两个 Worker 验证跨实例协议；同机实例不证明物理高可用。

组件与协议一手参考入口：[OpenAPI 3.1](https://spec.openapis.org/oas/v3.1.2.html)、[Problem Details](https://www.rfc-editor.org/rfc/rfc9457.html)、[openapi-typescript](https://openapi-ts.dev/introduction)、[Go TLS](https://pkg.go.dev/crypto/tls#Config)、[PostgreSQL NOTIFY](https://www.postgresql.org/docs/current/sql-notify.html)。本轮不重新联网或引入依赖；实现前核验适用版本、许可、安全与行为，文档链接不是运行证据。
