# 比赛、报名与成绩发布设计

日期：2026-10-25。版本：0.1。状态：本轮对话已确认的产品与架构基线；未实现、未联调、未做比赛演练。关联 [需求](../requirements.md)、[总体架构](system-design.md)、[判题](judging-design.md)和 [接口与任务](api-worker-design.md)。

## 1. 身份、授权与报名

首期不区分计算机协会成员，不建设成员申请、现役/退役状态或飞书成员导入。普通账号、平台角色、资源范围及具体操作构成权限依据；“毕业或退出后保留账号，以退役等标识表示”的要求只保留为未来成员模块约束，不实施注销流程。

- 平台运维角色不隐式获得全部题目、源码等业务读取权限；组织者、出题人、审核人、裁判和气球人员按资源与操作授权，默认拒绝。裁判发起重测、审核生效、确认最终结果和解封分别授权。下载、导出、后台任务及缓存命中均检查当前权限。
- 长期战队与单场参赛队分离，每人同时最多一个长期战队、同场最多一个计分身份（个人或团队）。邀请由本人接受并原子校验唯一性；队长离队前转让，空队可归档，恢复时重新检查现有成员关系，不自动拉回旧成员。
- 团队报名须成员逐一确认同一名单版本；变更名单使原确认与审核失效。赛前按公布时间冻结名单，冻结后仅允许依赛事规则授权修正并审计。历史成员、成绩和源码访问依据当时快照，未来新成员不自动取得旧源码。
- 每场独立配置开放申请、定向邀请或管理员导入；公布报名窗口、个人/团队形式、人数、资格、容量及奖项范围。管理员导入不绕过名单确认与资格审核，例外须显式授权留痕。
- 自动校验时间、人数和重复参赛等明确条件；学籍等无法可靠自动核验的信息交人工审核。状态区分待审核、需补充、已通过、未通过、已撤回，保留原因、操作者和时间。
- 通过后分配参赛身份及所需专用账号；仍须经过赛程、名单和停交检查才能提交。退赛或撤销资格保留历史提交。候补仅在显式启用时依公布规则处理，不默认按申请顺序录取。
- ICPC 正式规则配置按对应年度核验三人队及资格、替补限制；个人赛和其他训练队规模可配置，不声称符合官方参赛资格。

## 2. ICPC／ACM 计分基线

用户要求计分及判题对标官方规则；本节记录项目确认口径。年度规则定版时锁定适用原文和测试样例。规则对标不代表完整 CCS、Contest API 或题包格式兼容。

| 项目 | 已确认行为 |
| --- | --- |
| 排名 | 解题数降序、总罚时升序、最后一道解出题的首次 AC 时间升序；仍相同则并列，名次为 1、2、2、4，不用内部 ID 拆开并列 |
| 单题罚时 | 首次 AC 距开赛时间向下取整到整分钟，加此前计罚错误次数乘 20 分钟；只对最终解出的题累计 |
| 不计罚 | CE、SE；未解出题的错误不计总罚时，首次 AC 后的提交不再增加该题罚时 |
| 时间与顺序 | 保留原始接收时间及稳定次序用于边界、首次 AC 与审计，不先截断提交时间；有效区间为 `[开始, 结束)`，结束前接收而之后判完仍有效 |
| 参赛范围 | 正式、打星/特邀、裁判测试、赛后补题明确区分；团队结果不作为每位成员独立解题证据 |

默认文本接受合理空白差异和 ASCII 字母大小写差异，题目显式要求大小写时按固定配置执行；浮点和 SPJ 按 [判题设计](judging-design.md)。此前“默认区分大小写”的提案已被后续 ICPC 对标决策替代，不扩展为未定义的 Unicode 大小写折叠。

## 3. 封榜、气球与最终确认

- 按提交接收时间决定隐藏；标准五小时比赛默认最后一小时封榜，其他时长明确配置。封榜前接收、封榜后判完的结果仍可公开。
- 公开观众只取得允许的待判信息及数量；本队可看自己的实际判定，裁判可看实时全榜和封榜视图。所有列表、统计、通知、缓存和导出遵循相同授权，不能只在前端遮挡。
- 比赛结束不自动解封。存在待判、未解决 SE、未结答疑、候选重测或影响成绩的纪律复核时阻止最终确认；解决后授权裁判确认固定结果版本。
- 每队每题一条气球业务记录；隐藏结果对应气球暂缓发放，裁判可管理受限队列。失去 AC 时撤销未发放项，已发放项标异常由人工处理，再获 AC 不重复发球。
- 成绩快照固定提交集合、有效判定、规则、人工裁决和奖项配置。滚榜期间结果变化必须停止并重新确认，不让已揭晓内容静默改变。

## 4. 重测与赛中异常

采用保留旧有效结果、生成候选结果、正式比赛审核后生效。训练普通有效新结果可自动生效；新尝试 SE 保留旧结果并标异常，不能覆盖为选手失败。

- 单份或批次重测记录范围、原因、基线结果、目标题目/环境版本和代次；发布前检查基线和并发冲突。批次全部候选有效且无冲突后，作为同一结果版本生效，不边跑边改正式榜。
- 根据全部有效提交重算首次 AC、罚时、气球和成长投影；记录投影延迟及结果版本。回退是新的受控操作，保留旧结果、候选、审核和生效历史。
- 延期开赛、延长结束时间由裁判人工决定，生成赛程新版本并协调账号窗口、题面开放和通知。局部机器故障记录影响范围，不自动全场延赛或免罚。
- 停交只拒绝新提交，明确展示原因；已接收任务保留处理。停交不等于停止计时，首期优先以显式延赛补偿，复杂暂停/扣除时间段留待扩展。
- 已封榜比赛延期后保持封榜；未封榜的调整先预览新封榜时间。结束后不通过普通编辑直接重开，赛后练习独立；恢复、重新开放须受控裁决，不接受浏览器回填接收时间。

## 5. 答疑、通知与查重

- 私有答疑默认仅本队和授权裁判可见，支持一般事项/具体题目、追加回复、待处理/已回复等状态、认领转交和并发版本检查。影响公平性的解释经去除个别信息后发布全体澄清；可使用“请阅读题面”等模板。
- 全体澄清及公告先持久化，再推送提示；断线后通过授权接口补取。送达、已读和理解不同，修改生成版本并重新提醒，不能强制抢焦点；赛前、赛中、赛后通知限定比赛范围，校内离线可用。
- 查重采用本地离线、赛后批处理、人工复核，Dolos 优先验证，JPlag 备选。按同场、同题及适用语言分析正式提交；内容去重仍保留作者、提交及时间关联，模板排除显式配置并版本化。
- 不保证跨语言检测；解析失败/不支持表示未检测，不表示低相似。固定引擎、解析器、配置和输入集，保留历史报告；实际 C/C++、Java 21、Python 3.14 语法支持须验证。
- 查重有独立预算，低于正式判题；源码不上传外部服务，报告仅授权人员可见。相似度是线索，人工结合片段、来源和陈述裁决，允许纠错；不自动判作弊或直接修改分数。

## 6. 奖项与滚榜

- 排名与评奖资格分开；赛前公布分组、固定名额/比例、计算基数、取整、最低解题要求、兼得及完全并列时的处理办法。缺规则或边界并列无法决策时阻止自动定稿，不增加隐藏比较条件。
- 系统基于正式结果版本、资格和规则生成可复核候选名单，人工确认发布。结果或资格改变使候选失效；发布后的修正形成新版本并保留原因。具体比例和分组等真实通知后配置。
- 滚榜优先验证标准导出对接外部官方 ICPC Tools Resolver，保留展示适配边界；先验证本地离线包/事件输入，主持控制、暂停继续、速度、奖项停顿和检查点恢复以实测为准。多屏或 CDS 按需要验证，不预设必需常驻组件。
- 导出绑定最终快照及内容哈希，只交授权工作人员；包含隐藏结果的包/数据源不能暴露给观众。预演不修改成绩或自动解封，输入/配置版本一致才能恢复检查点。
- 官方工具使用自定义 ICPC Software License，不能当作 MIT/Apache 项目；非商业、源码公开及其他条件需在正式准入时核验本项目适用性，外部运行也不自动免除许可审查。接口采用适配子集，不宣称完整标准兼容。

## 7. 赛后开放

补题、题解、最终榜、本人源码、他人源码、正式数据与程序材料独立授权，并按比赛类型设置默认值。

- 训练赛结束后默认允许原获准参赛者补题；正式赛在结果确认及滚榜结束后向配置范围开放。补题不影响官方成绩、罚时、奖项或气球。
- 题解同时满足预设发布时间及审核批准才能开放，可为复用继续保密。比赛开放不使私有题永久进入公共题库。
- 个人/队伍历史源码按当时名单授权，专用账号停用后通过个人账号受控查看；他人源码默认私有，公开需事先明确规则与授权。
- 正式数据、答案、SPJ 和标程默认私有，与能否练习、题解发布分别控制。发布前预览内容及人群并审计，账号到期不删除历史。

## 8. 依据与验证边界

本轮记录用户确认，不新增联网调研或声称官方规则已完整实现。既有讨论依据包括 [ICPC 区域赛规则](https://icpc.global/regionals/rules)、[2026 总决赛规则入口](https://wf.icpc.global/2026/about/)、[2025 Judging Notes](https://docs.icpc.global/wp-content/uploads/2025/07/2025JudgingNotes.pdf)、[CCS 草案](https://ccs-specs.icpc.io/draft/ccs)、[Resolver](https://tools.icpc.global/resolver)、[工具许可证](https://github.com/icpctools/icpctools/blob/main/LICENSE)。动态链接和草案在实施时重新核验并锁定适用版本；规则、格式、工具许可与本地运行验收分别记录。
