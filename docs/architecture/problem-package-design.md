# 统一题目模型与题目包导入设计

日期：2026-10-25。版本：0.6。状态：用户确认统一内部题目模型及下述导入/发布约定；试用录入入口按开发与交付计划选择。首批Library Checker固定候选已实现离线适配、授权私有草稿持久化/HTTP与[绑定导入和只读回执](../problem-drafts.md#管理页导入协议)，不等于标准题包或完整发布支持。ICPC／Kattis Problem Package Format 2025-09子集兼容矩阵、一般导入流程和完整发布仍待验证。关联 [总体架构](system-design.md)、[判题设计](judging-design.md)、[存储](storage-design.md)、[题面渲染](frontend-sandbox-options.md#33-已确认的题面-markdown-与公式渲染)及 [需求](../requirements.md)。

## 1. 已确认路线与取舍

2026-11-03 用户确认[首批来源](../problem-sources.md)：Library Checker 十题起步，官方 ICPC 赛事包扩充，爬虫作为补充。固定上游原生材料已有离线私有候选及[统一私有草稿适配](../problem-drafts.md)，包含内容版本、模板/样例转换、全部材料哈希、自含复验、授权数据库入库、HTTP导入/本人读取、固定版本题面/样例预览、共享Markdown/公式渲染及绑定导入/只读回执协议；导入管理页面、图片授权、本站受限验证及审核发布仍待完成。Library Checker 的 `info.toml`/模板不等于 ICPC ZIP，以下统一模型与 2025-09 子集验证约定继续适用于正式导入，不据此声明标准题包兼容。

后台手动录入与 ZIP 题包导入统一转换为本站内部题目模型，之后使用同一验证、审核和不可变版本发布流程。训练试用按实际授权题库来源先实现其中一个入口，不要求双入口同时完成；不能延期版本、审核、私有材料保护和受限验证。外部格式由导入适配器解释，业务模块、Worker 和存储不直接依赖外部目录或供应商字段。

优先验证 `2025-09` 的受限子集，而非承诺完整兼容任意 ICPC/Kattis 题包；目标包括 Markdown 题面、本地图片、样例与正式测试数据、资源限制、所支持的检查规则及相关程序材料。交互题、直接提交答案题仍不属于首期；其他不支持或无法忠实映射的内容明确报告并阻止发布，不静默丢弃或伪造支持。

取舍：统一内部模型使两种录入入口共用业务与权限规则，标准格式适配便于复用题目资产；代价是维护版本化映射、兼容矩阵、校验报告及样例包回归。当前只是路线和流程确认，没有导入组件选型、真实题包实验或正式兼容声明。

## 2. 内部模型的逻辑边界

以下是职责与逻辑材料，不是已经建表的数据库模式或完整字段契约：

| 内部归属 | 内容与要求 |
| --- | --- |
| 题目身份与版本 | 本站稳定题目标识、不可变版本、关联来源；外部 UUID/题号仅作带命名空间的来源标识，不授予覆盖已有题目的权限 |
| 内容与展示 | Markdown 原文、题目名称/语言、必要结构与资源引用；样例输入输出单独保留原始文本，沿用既定渲染限制 |
| 执行材料 | 样例和私有测试、参考答案、检查器/参考程序及必要验证材料的逻辑文件标识、大小、哈希、可见性 |
| 判题配置 | 已选文本/显式浮点/SPJ、资源限制及运行环境引用，固定到题目版本；SPJ 已选 ICPC 协议、GNU++17 及必须支持 Testlib，浮点比较语义及固定测试顺序/提前停止已定、数值与编排实现及适配待验证 |
| 证据与流程 | 原包、来源与使用依据、导入版本/报告、验证记录、审核与发布记录，失败/未知状态不能当作通过 |

同一材料的公开/私有属性明确管理，不能因为存在于题包就整体公开。附件、题面图片及样例与正式数据/答案/参考程序分开授权；猜中哈希或逻辑标识不构成访问权限。内部模型细化时继续遵循题库模块数据所有权和最小公开接口。

## 3. 导入映射与支持矩阵

导入器先识别并校验来源格式版本，再按该版本解释元数据、默认值和目录；缺少版本或其他格式不得无提示猜测为 2025-09。来源版本、每个被映射字段和未支持特性进入报告；首期支持矩阵及代表性题包集须在实施准入时明确。

- **题面与资源**：只把已验证能在本站显示的 Markdown 与本地资源转换为受控引用；LaTeX/PDF、SVG、多语言映射、常量/样例占位指令等均须在兼容矩阵标明支持、待验证或不支持，不能由规范包含这些能力推导本站已经实现。
- **公式兼容**：2025-09 的 Markdown 规范要求 MathJax 支持的 TeX 范围，本站采用 KaTeX。导入需检查实际公式能否表达并预览验证；无法忠实呈现时报告并阻止发布，不能静默删公式、把错误显示当作兼容或自动更换已选渲染路线。
- **样例与测试**：样例、正式数据及参考答案按清单建立引用并保留原始内容；不能只抓取公开样例冒充完整测试数据。编码、测试分组和资源上限映射随实际子集协议定版；导入须形成明确的必需测试点有序清单，审核发布后随题目版本固定，重判沿用对应清单，见 [判题第 5.1 节](judging-design.md#51-已确认的测试顺序与提前停止)。来源顺序/分组无法忠实映射时报告并阻止发布，不依赖临时目录枚举或丢弃关键配置；具体映射及导入组件仍待验证。
- **判定语义**：按来源版本解释大小写、空白和浮点默认值，并明确展示与本站默认配置的差异。本站默认按后续 ICPC 对标决策接受 ASCII 大小写差异；显式敏感要求和其他来源差异必须在本站支持的检查模式中明确表达并重新验证。无法忠实表达则拒绝发布，不能自动用本站默认替代来源语义，也不静默放宽已确认的严格整数规则。浮点映射遵循 [判题第 3 节](judging-design.md#3-显式浮点容差)：每题显式绝对/相对容差，同时配置时取 OR，有限数值与混合文本、版本绑定和发布验证一致；无效容差/标准答案阻止发布，不能直接套用来源或库的默认阈值。
- **程序与脚本**：导入保存允许范围的程序材料，不在 API 主机编译或运行题包里的 build/run、生成器、检查器或参考程序；后续验证按固定构建/执行协议进入受限环境。首批 SPJ 已选 GNU++17，ICPC 协议与 Testlib 支持要求见 [判题第 4.1 节](judging-design.md#41-已确认的-spj-协议与-testlib-验证路线)；其他检查器语言、构建脚本支持及精确依赖仍待定，不把任意外部脚本作为可信安装入口。

所有不支持内容须明确报告并阻止发布；可保留为带阻断项的私有草稿供人工修正，解析不安全或结构无法识别时直接拒绝导入。修正须有新的材料/版本及报告，不用忽略未知字段、删除失败检查或修改来源原包来制造通过。

## 4. 导入到发布的流程

1. **接收与追溯**：校验录入/上传权限和容量预算；原包只读保留，记录内容哈希、来源、格式版本和使用依据，来源材料纠错新增记录而不改写旧包。原包本身仍属受限材料，不自动成为公开附件。
2. **安全解析与映射**：使用成熟 ZIP/YAML 等解析能力并核验所选版本，限制压缩/展开体积、文件数、路径和解析成本；拒绝越界路径、危险链接及歧义覆盖。具体解析组件、大小阈值及受支持链接/文件类型尚未选定，不手写脆弱通用解析器。
3. **私有草稿与报告**：生成内部草稿、来源映射、材料清单和差异/阻断项；导入成功仅表示已形成草稿，不等于内容正确、已审核或已发布。手动录入也生成同类材料与配置校验结果。
4. **受限验证**：在有界后台任务与受限执行环境验证题面/样例、数据/参考答案、所选文本/浮点/SPJ 规则及相关程序；资源和依赖满足前不能运行。API 不执行题包程序，失败保留可定位报告且不能进入已通过状态；任务遵守已确认持久化、幂等、预算及取消协议，具体执行组件待验证，不自动复用已选发信任务库或让判题 Worker 持有无关凭据。
5. **审核与发布**：沿用非作者终审、专门授权的紧急发布及事后补审边界（例外不跳过验证），所有必需验证及审核完成后，先完整持久化不可变材料，再事务发布固定版本及引用。发布失败沿用存储恢复/孤儿处理协议；不能先发布可见版本再补文件。

导入、映射、验证和审核分别记录状态及操作者。重复原包按哈希和来源去重，并核验目标权限；外部标识相同、文件名相同或重复导入不自动覆盖已发布内容。变更生成新版本，历史比赛/提交仍引用原版本。取消、中断、重试和清理不能误删被历史提交或进行中任务引用的材料；具体任务协议和并发控制待实现验证。

### 4.1 普通终审的交付边界

本节规定实现与验收边界。已实现[作者送审回执](../problem-drafts.md#作者送审回执)、分配范围内的[证据及材料读取](../problem-drafts.md#审核材料读取)、[退回与重送限制](../problem-drafts.md#审核退回与重送)及[只读批准阻断](../problem-drafts.md#批准准入状态)。草稿的 `private-draft` / `not-run` 与[参考报告的 `reported`](../reference-requests.md#参考报告接纳)是不同状态：后者只说明已保存一次确定结果，可能是失败或对拍不一致。即使正式点全 AC，也不能推断题面、材料、检查器、目标机资源或完整验证均已通过。作者现有的[本人报告入口](../reference-requests.md#作者申请入口)只返回经投影的结果，不用于向审核人开放其他作者的历史。

| 边界 | 实现须保留的约束 |
| --- | --- |
| 送审对象 | 作者显式送审。服务端固定草稿 ID、作者、来源 ID、来源锁摘要、内容版本和完整 `import_revision`；同一内容版本的不同导入修订不得共用审核决定。为该修订选定所需验证策略与明确证据，记录各证据身份、结论及摘要。参考执行证据必须绑定已接纳报告、正式 Plan、Profile 和独立对拍（如策略要求）。历史正式报告缺对拍在作者页仍可展示，但不足以满足要求对拍的终审策略。客户端自报摘要和“最新一条 AC”都不能确定送审证据；证据更换或策略失效须另开审核。 |
| 审核授权 | 普通终审使用当前登录的人类主体及显式、可撤销的审核权限；初版只允许访问明确分配给该主体的审核项。送审者不能自行授予审核权限；普通出题、管理角色、Worker mTLS 或维护归属字符串均不自动授权。判断非作者用稳定主体身份，初版以草稿归属为准；以后引入多人编辑或转移归属时，应保留可核对的作者归属，不能用转移或另一个角色规避终审要求。AI 只可辅助，不形成终审主体。 |
| 私有证据访问 | 对列表、计数、详情及直接材料请求应用同一审核范围；仅投影当前项所需的题面、固定标程和验证结果，所需附加材料按明确引用单独受控读取。猜中草稿 ID、报告 ID 或对象哈希不授权。禁止回传 Worker 令牌、原始传输证据、无关正式材料、存储路径和其他草稿；不能通过作者入口扩大读取范围。 |
| 决定与审计 | 批准或退回必须写入明确的审核项与固定修订，记录操作者、决定、理由、服务端时间及所见证据标识。批准前按现行策略确认必需验证全部通过，缺失、失败、未知或不一致不得批准。历史决定只追加、不覆盖；退回后修订或证据变化另行送审。一次决定只生效一次；确认未知时按原键和主体回读，同键同内容才可返回原结果，变更内容冲突，不得自动重发为新决定。 |
| 发布 | 独立发布事务重新核对当前发布权限、固定修订、完整验证、可用终审与材料完整性；审核决定不改变公开状态或改写历史版本。先完成不可变材料校验，再事务发布引用。已有决定的效力不因复用内容版本、替换证据或回滚代码自动延续。紧急发布另有显式授权、原因和补审，不能跳过必需验证；初版普通终审不提供例外入口。 |

实现顺序是：先接入版本绑定的送审与指定审核人证据读取，再接入批准／退回，最后接入独立发布。第一阶段允许审核人看到证据缺项，但不生成批准或公开引用；完整验证策略、人工确认标程及相应证据具备后才启用批准。审核资格与单项分配分开，由可信维护边界显式管理，默认均无授权。不同账号只能证明主体不同；负责人须明确授权实际非作者审核人，排除作者使用另一账号自行终审。已确认退回后仅修改完整导入修订或更新验证证据才可重送。P4 普通发布不提供紧急入口。

发布前撤销审核资格、撤回分配或改派时，原批准保留为审计记录，但不得用于发布。发布事务重新锁定并核对批准时的审核主体、审核资格修订与分配修订；向同一人重新授予资格或重新分配也不能恢复原批准。须在当前有效分配下重新终审。该发布门禁不追溯改变已发布版本的可见性。

内部发布门禁按送审项和分配修订读取批准账本，并在调用者的 `READ COMMITTED` 事务内锁定恢复代次、审核人账号、送审和材料，再复核批准时的身份代次、当前分配、固定证据、策略版本和完整准入。角色与分配变化通过追加历史记录保存；即使已取得父行锁，也不能用旧事务快照查询历史。账号认证代次或数据库恢复代次变化后，原批准不能用于新发布；需重新分配后再终审，可以重新指定同一审核人。已发布版本的历史不受影响。

接入发布写事务时，先使用[独立发布资格门禁](../problem-drafts.md#发布资格)检查当前发布者与授权修订，并在取得送审及材料锁前按稳定顺序预锁涉及账号。预期审核人须由已有批准复核确认；调用者还须独立复核材料和生产执行版本。成功检查的锁须持有到写事务提交，失败须回滚。门禁不写发布记录；schema 切换须停业务执行。

授权复核和决定写入须在同一有界数据库事务中。沿用身份行锁顺序 `恢复 → 账号 → 角色`；涉及多个主体时按稳定顺序先锁全部账号再锁角色。现有参考路径先普通读取申请以发现主体，再先锁草稿行、后锁申请行；迁移的表锁顺序还须考虑首次查询和外键，不能照抄行锁顺序。分配及审核的具体锁序须核对调用链并以并发测试验证。跨事务读取材料时，先受权冻结并校验固定引用，再短事务复核仍是同一主体、恢复及认证代次、审核资格和分配修订、固定证据，才返回结果；不在授权事务内做外部 I/O。撤权、换号、撤回和重分配不能借旧授权快照继续生效，撤销后重授也不自动恢复旧分配。初始账本为空，不补发历史批准；回滚保留已产生的审核历史，已有记录的迁移不允许以删除历史恢复旧 schema。

[作者确认标程](../problem-drafts.md#作者确认标程)与非作者终审是两项独立动作。草稿作者核对并确认冻结的完整导入修订和正式计划，计划绑定源文件及依赖。确认只解除该修订对应的一项阻断；作者仍不能终审。批准写入启用后，须在写事务内按退回流程的锁顺序取得同材料锁，再检查当前分配、是否已退回、现行策略及所有必需证据。只读准入响应不能作为批准凭证，读取之后可能有其他决定提交。

最低验收：用真实会话和临时 PostgreSQL 证明审核入口拒绝作者自审、未分配审核人、撤权主体和猜中对象标识的请求；相同内容版本但不同导入修订的审核不得串用。覆盖材料读取期间撤权、两主体锁序、撤权与决定、证据替换与批准、同键并发及 COMMIT 回包丢失；确认未知时只读回执的 404 不证明没有在途写入。验证失败、不完整和卷积对拍不一致都不能批准。发布阶段另测草稿和旧版本的可见性、材料缺损及事务中断；用实际授权的非作者完成端到端演练，测试账号只证明权限实现，不代替实际终审。

[题面语义确认](../problem-drafts.md#审核人确认题面语义)作为独立证据，只对当前分配及冻结修订有效。撤权或重新分配不销毁历史，但不延续当前效力；同材料退回使确认不再用于准入。批准必须另行核对可信渲染及其余证据，不以人工声明替代客观验证。

### 4.2 发布材料准备

受信调用方提供已预留的本站题目 ID、草稿归属、冻结的完整导入身份、正式 Plan 与独立取得的 Plan 摘要。准备器重建并核对题面、样例、静态图片和正式计划的引用，不读取当前导入目录。展示制品只包含题目 ID、版本、标题、语言、Markdown、原样例与重编码的 PNG。Markdown 仍须由受限渲染器处理。制品不含草稿或作者 ID、来源锁、隐藏点、正式答案、标程或存储对象选择器。

在数据库事务外、共享材料槽和明确截止时间下，先用现有有界参考快照核验有序正式材料，再读取展示对象并封存最多 7 MiB 的 JSON。版本摘要由协议、本站题目 ID、正式 Plan 摘要及展示投影确定；完整导入修订由 Plan 约束，换修订即使题面相同也生成新版本。相同输入可重试。错误或取消不返回可用于发布的材料引用；若存储写入已成功但确认中断，可能留下未被业务引用的不可变对象。

这一步提供发布事务的候选材料，正式 Plan 仍是私有验证计划，不能直接当成生产检查器与 Worker 执行准入。准备成功不产生批准、发布记录或公开路由。后续事务必须重新核对当前授权、终审、生产执行版本与所有证据，再提交可见引用。

有权限的发布准备或恢复维护调用方，可持独立取得的同一份可信候选引用读回展示 JSON。快照检查原始字节大小和哈希、固定字段、规范 JSON、题目 ID，并按已封存的算法重算版本。需要完整复核时还须独立提供同一完整导入修订与正式 Plan；确认两侧绑定后重新核对有序私有材料和依赖。失败时无可用结果；调用方在数据库事务外持共享材料槽并指定截止时间。读回只证明当次对象与已有可信引用一致，不能以调用请求自行提供的摘要授权访问，不改变批准和发布状态。

## 5. 验证出口与未知

关联 AC05/06/17/18/20/22，实施时至少验证：

- 手动录入与代表性 2025-09 子集题包生成语义一致的内部版本；文本/浮点/SPJ 配置及与本站默认差异可见且不被静默改写。
- Markdown、图片、公式与样例符合既定展示规则；不支持题型/字段/公式、缺失材料及不完整测试集不得绕过阻断项发布。
- 路径穿越、展开超限/文件冲突、解析异常、未授权上传/材料读取被拒绝；API 不执行包内程序，私有数据不泄漏。
- 重复/并发导入、解析/验证中断、取消、磁盘不足、发布失败和备份恢复可追溯；旧题目版本不被覆盖、文件引用与哈希完整。
- 校内断外网验证题面、数据、受控工具链/检查器及审核发布流程；限制导入/验证并发和磁盘占用，不能耗尽比赛预算。

Library Checker固定来源的离线字段、限制和草稿校验归[草稿合同](../problem-drafts.md)，不等于标准题包支持。2025-09的完整字段、支持矩阵、ZIP/YAML解析组件、具体大小/并发、SPJ适配/构建制品、导出及更多格式仍待验证；本标准子集尚无真实包导入或完整发布验收，不能声明正式支持2025-09。
