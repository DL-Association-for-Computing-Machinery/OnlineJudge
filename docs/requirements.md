# 东华理工大学计算机协会 OnlineJudge 需求草案

版本：0.23　整理日期：2026-10-25　状态：M0 已开展持久化/租约核心及 Linux 沙箱分项实验；训练与比赛产品尚未交付，完整组件准入、生产硬件参数与业务验收仍待验证。版本边界见 [开发与交付计划](phase-1-development-plan.md)。

当前实施证据与缺口统一见 [M0 记录](m0-experiment.md)，本页维护需求与验收标准，不重复维护分项进度，也不把分项测试提升为整项 AC 通过。

平台首先服务于东华理工大学计算机协会，同时允许校外同学注册训练。核心目标是统一本站刷题、长期战队训练、协会及校级比赛组织、外部赛事参与和参赛名额管理，让同学看见自己的成长，并降低协会反复搭建比赛环境的成本。

本文是产品与验收依据，不代表功能已实现。**已确认**来自本次需求对话；优先验证组件仅确定准入顺序；数值、兼容矩阵与运行效果以实际验证为准。此前推荐项已逐项讨论，本次更新为确认口径；真正未决事项集中在文末。涉及安全隔离、权限和数据一致性的工程约束沿用根目录 [AGENTS.md](../AGENTS.md)。

## 目标和范围

### 已确认的业务范围

| 领域 | 范围 |
| --- | --- |
| 本站训练 | 本站看题、提交、判题为主；题单组织日常训练，反馈按题目配置 |
| 题库建设 | 辅助出题人，重点是生成与验证数据；允许 AI 辅助生成标程，验证后由出题人审核确认；题目审核后发布 |
| 组队 | 用户创建队伍、设置个人组队状态，方便检索与邀请；每人最多一个长期战队，允许退出和更换 |
| 战队训练 | 队长安排题单，各队可举办训练赛，其他队伍可以自主参加；协会定期组织官方比赛 |
| 校赛 | 校内外用户注册，支持临时参赛队、报名审核、多机房安排 |
| 比赛 | 首版仅 ICPC／ACM 计分，支持个人赛和团队赛；线下团队赛使用队伍账号，线上团队训练使用成员个人账号 |
| 比赛运营 | 赛时榜单、封榜、对标 ICPC 正赛效果的滚榜、简单气球登记、答疑公告及代码查重 |
| 外部赛事 | 提供 Codeforces、力扣、牛客小白月赛等赛事跳转入口，并同步可获取的相关信息 |
| 成长与评估 | 成长积分、算法能力画像、比赛成绩分开展示，帮助发现短板、选择队友并提供正反馈 |
| 参赛名额 | AI 辅助解析通知和计算，管理员确认后生效，保留人工录入和修正 |
| 规模与部署 | 约 300 人规模的校赛；学校有服务器，需支持分布式部署并利用机房主机承担判题；高并发能力需实际压测 |
| 工程要求 | 模块化、高内聚、低耦合，便于功能变更、外部服务替换和扩展 |

### 首版边界

- **明确不做**：OI／IOI 等其他计分模式、代码打印。
- **推荐暂缓**：自动推荐队友、复杂气球派单与配送跟踪、通用赛事规则编程引擎。用户当前要求是检索邀请和简单发放登记。
- **未授权为既定范围**：AI 为参赛选手提供赛时解题、娱乐中心、商业收费、多学校独立运营后台。旧项目中的功能不自动成为新项目需求。
- **审计后交付顺序**：工程骨架 → 关键技术验证 → 训练试用 1A → 完整训练 1B → 战队训练 → 正式比赛 → 辅助能力。辅助能力不与训练闭环和首次完整比赛演练交错。首个验证从 GNU++17 文本题开始，1B 仍须覆盖全部首批语言和文本/浮点/SPJ；1A 语言/题型按真实用户与题库冻结。多文件/ZIP 提交、自测及双录入入口不作为 1A 前置，详见 [发布边界与验收归属](phase-1-development-plan.md)。日期、首批题库数量与授权来源仍待明确，不因分期取消目标需求。
- **首期不做成员系统**：不判断计算机协会成员身份，不引入成员审核、现役/退役状态或飞书成员导入。未来成员身份结束时保留账号、以退役等标识表示；该约束不作为当前注册、组队或报名的前置条件，不实施成员退出注销流程。

## 用户角色与权限

采用平台角色＋资源范围＋具体操作权限。队长身份来源于具体队伍，裁判和工作人员限于指定比赛；默认拒绝，服务端每次操作及下载、导出、后台任务检查当前授权，不依赖协会成员身份。

| 角色 | 已确认权限方向 | 边界 |
| --- | --- | --- |
| 游客 | 查看公开题目简介、赛事信息和已公开榜单 | 不提交代码，不访问未公开资料 |
| 注册用户 | 本站刷题、创建个人题单、设置组队状态、创建或加入队伍、报名个人赛、接受团队报名 | 仅查看有权访问的题目与成绩；外部账号需绑定确认 |
| 队长 | 管理本队成员与招募、安排题单、创建本队训练赛、提交团队报名 | 不访问其他队伍私有训练或未授权题目；不能单方把他人加入队伍 |
| 出题人 | 创建题目草稿、使用 AI 辅助、维护标程与数据、发起验证和送审 | 仅处理获授权题目；题目访问权限与公开状态分离 |
| 题目审核人 | 审查题意、标程、数据验证报告，批准或退回指定题目版本 | 推荐由另一位被授权出题人或管理员担任，作者不得自行终审 |
| 比赛组织者 | 配置比赛、题目、报名资格、名单、赛场、座位与开放策略 | 队长组织训练赛与管理员组织官方赛的权限范围分别控制 |
| 裁判 | 查看指定比赛完整榜单和提交、答疑公告、处理查重报告、按授权重判 | 敏感操作记录原因；涉及成绩的处理可复核 |
| 气球工作人员 | 查看指定比赛的队伍位置和气球任务，标记发放及纠错 | 不获得源代码、隐藏成绩明细或其他管理权限 |
| 业务管理员 | 官方赛事、报名审核、题目发布授权、名额确认与分配 | 日常业务管理与平台系统配置分离，不管理首期之外的协会成员身份 |
| 平台管理员 | 账号角色、系统配置、判题节点、备份与运行状态 | 高权限操作留审计记录；不因账号角色隐式计入比赛成绩 |

同一人可承担多个不冲突角色。正式题目由非作者终审，AI 不算独立审核人；单人私有实验标记缺少独立审核。紧急正式发布须专门授权、记录原因并事后补审，不能跳过必需验证。接触本场保密材料的出题人/裁判不参加本场正式计分，试题提交独立记录。平台运维不隐式获得全部业务读取权限，发起重测、审核生效、最终确认与解封分别授权。字段与实现见 [比赛设计](architecture/contest-design.md#1-身份授权与报名)。

### 登录会话

用户确认服务端 Session＋Redis 共享会话＋HttpOnly Cookie；账号及权限按 PostgreSQL 路线持久化，任一 API 副本都须识别有效会话并检查当前资源权限。退出、封禁、过期和撤权须跨副本生效；Redis 故障不得绕过鉴权，恢复不得使已撤销会话复活。Cookie、CSRF 与校内 HTTPS 要求见 [会话设计](architecture/session-design.md)。

- 已确认首期初值：普通登录空闲 2 小时/最长 12 小时；自用设备主动勾选“保持登录”为 24 小时/7 天，默认不勾选；管理后台 30 分钟/8 小时，敏感操作再次验证。后台轮询不得无限保活，到期提醒并保留同一用户的本地草稿，重新登录后由用户确认提交。
- 普通个人账号最多 3 个有效会话，提供列表及主动撤销；超额登录经身份核验后选择退出已有会话。正式线下比赛每个参赛主体仅 1 个有效参赛会话，第二次登录拒绝、原会话继续使用；换机由工作人员核验、撤销旧会话后开放新登录并留痕。普通会话不能绕过参赛限制，多个标签页不额外占用名额，不以 IP 唯一识别设备。
- 受监考线下比赛独立配置有限会话窗口和适合赛程的空闲期限；比赛结束立即停止竞赛提交，赛后结果查看窗口默认 30 分钟且可配置，仍遵守封榜与可见性规则。窗口结束撤销参赛会话并停用专用账号；延期/延赛需协调期限并审计，不恢复已撤销会话。
- 会话库与客户端优先验证 SCS＋go-redis，Gin sessions 保留备选；正式采用、精确版本、每场赛程参数、活动识别及故障恢复时限待定，上述规则尚未实现或验收。
- 密码保存采用 Argon2id＋每个密码独立随机盐＋可升级的参数记录；数据库保存验证记录而非原始密码，参数升级不能覆盖并发改密/重置。具体参数在硬件确定后结合集中登录负载验证，Go 封装及格式待设计。
- 日常采用邮箱验证注册＋密码登录＋邮箱自助找回；验证前不开放训练提交，找回至已验证邮箱且成功重置后撤销旧会话。正式比赛采用校内发号＋人工核验重置；断外网或邮件故障可暂停注册激活/邮件找回，既有密码登录、提交、判题和赛务必须继续运行。邮件采用可替换 SMTP 接口、优先验证 go-mail；优先验证 PostgreSQL 持久化发信任务＋独立受限发送执行器；River 开源核心优先验证、专用表备选，邮件载荷采用业务侧短期 AES-GCM 加密、River 仅存业务 ID、独立密钥文件；不考虑付费方案，令牌/重发/重试规则已确认（见下条），邮件服务与核验材料待设计，域名和可用 SMTP 暂不确定；详见 [账号流程](architecture/session-design.md#8-注册找回与账号发放)。

- 邮件规则首期默认：注册链接 24 小时、找回链接 30 分钟，均从生成起计时；同账号同用途主动重发至少间隔 60 秒，每次生成新链接，旧链接在原期限内有效，最多 3 个有效链接，满额暂缓新申请且不挤掉旧链接。任一成功完成操作后，同用途所有链接原子失效。临时失败最多重试 5 次（含首次 6 次），每任务发送窗口从生成起最多 10 分钟且不超令牌到期，永久失败不重试；自动重试复用原令牌且不延长期限。额外账号/来源/全局额度仍待定，详见 [已确认规则](architecture/session-design.md#12-已确认的令牌有效期重发与发信重试)。

技术选型不考虑付费方案、商业付费功能或付费服务；核验免费组件的具体许可证及免费服务长期条款，不依赖付费升级才能实现的必要能力。硬件、域名和现有 SMTP 条件仍待核验，不由本约束推断零运维成本或采购授权。

## 战队与训练

### 代码编辑与提交

- 用户确认首版提供基础在线编辑＋文件上传，支持语法高亮、缩进、快捷键和草稿保存；代码编辑器已选 CodeMirror 6，尚未集成或验收。
- 首批工具链已确认 GCC 15（C17、GNU++17 默认、GNU++20 可选）、Temurin JDK 21、CPython 3.14，PyPy 后续评估；补丁与构建版本、时间/内存规则待验证和定版。界面可选语言须与服务端实际启用配置一致，不能把前端高亮当作判题支持。
- 用户确认暂时只支持浏览器本地保存代码草稿；首期不提供服务器草稿同步或跨设备恢复，后续如需扩展另行设计。已确认 IndexedDB＋idb，停输 1 秒后保存、持续输入目标每 5 秒保存；事务成功才显示已保存，多标签冲突保留双方供选择，不按时间自动删除，支持导出/手动清理；主动退出默认勾选清除此账号草稿且可取消，会话自然过期保留以供同账号重登恢复。容量/大小预算、精确版本及运行实现仍待定，详见 [草稿规则](architecture/frontend-sandbox-options.md#32-已确认的-indexeddb-本地草稿规则)；不把草稿保存等同于提交成功，正式提交仍由服务器持久化。
- 实现建议：文件导入前检查大小和编码，覆盖未保存内容前提示；只有用户明确提交后才进入判题。限制值在语言和提交协议确定后记录。
- 草稿与文件内容按用户、题目和适用比赛隔离，学校公用电脑换账号时不能展示前一个账号的代码；验收覆盖刷新恢复、中文输入、键盘操作与异常提示。

### 长期战队与临时参赛队

- 每位用户同时最多属于一个长期战队；发送多份邀请不等于加入，接受邀请时再次校验唯一归属。
- 用户可以自由退队并加入其他队伍；队长有其他成员时先转让，空队允许归档，恢复重新检查当前成员关系，不自动拉回原成员。
- 个人可主动设置组队状态。推荐初始选项为“寻找队伍”“已有战队但接受交流”“暂不考虑组队”，状态文案可以调整。
- 检索可使用组队状态、擅长方向、可训练时间和用户愿意公开的能力信息；不公开联系方式等非必要信息。
- 单场比赛允许临时参赛队，不改变长期归属；同场每人最多一个计分身份，个人和团队报名也互斥。
- 团队报名要求成员逐一确认同一名单版本；名单变化使确认和审核失效。按公布时间冻结阵容，特殊变更依赛事规则授权审计。退队或转队不能改写历史参赛阵容，新成员不自动取得历史源码。
- 长期战队成绩仅归集明确代表该战队的参赛记录；临时队成绩保留为临时队成绩及成员参赛经历，不自动计入成员当前战队。
- 队伍人数、替补和报名资格由比赛配置；不将所有比赛硬编码为三人制。

### 题单与训练赛

- 个人可以创建个人题单；队长安排本队题单，可设置目标、说明、推荐顺序和截止日期。
- 发布任务固定题单版本、参与人员、起止时间和完成要求，题单后改不静默改变任务。个人任务按本人有效提交认定，团队 AC 不代表每人完成。
- 默认允许历史有效 AC 抵扣并标记此前完成，需要重做时在发布前关闭抵扣。截止保存按时进度，之后允许补做；判题延迟按服务器接收提交的时间认定是否按时。
- 任务增删题、延期和人员变更有版本、影响提示及通知，不抹除已完成记录。队长看必要任务进度，不因此获取成员源码和私人调试。同题可满足不同任务，但同次解题不重复奖励；首期无复杂自动排课。
- 战队训练赛可设置仅本队、邀请参赛或开放给其他队伍。协会官方赛与校赛由有权限的组织者发布。
- 默认只允许选用已发布或比赛出题组明确授权的题目；创建比赛不能获得任意私有题库的访问权。
- 训练赛创建数量、频率和判题资源配额可配置，正式赛事可优先使用判题资源。

## 题库与辅助出题

### 题目内容与来源

采用统一题库、受控标签、平台难度分级和版本化题单。题目身份稳定，发布版本不可变；题单、比赛、提交明确引用版本，升级显式确认。算法/数据结构标签由获授权人员维护别名与合并，AI 仅推荐，私人标记不进入公共标签。难度采用少量明确分级并允许未评定，由出题初评、审核确认；通过率和样本量作辅助，不直接等同难度，外站难度保留原义。

检索支持题号/标题关键词、标签、难度、来源、完成状态与所属题单；服务端权限过滤覆盖结果、计数和筛选项。题单支持顺序、分节和说明，发布为版本；公开题单不自动公开私有题。正式比赛默认隐藏可能提示解法的算法标签，是否展示赛前统一配置；赛前检查题目是否已泄露。首期先实现明确检索，不预设独立搜索服务或语义检索。

- 题面参考洛谷的结构组织，包含描述、输入输出格式、样例、约束、时间内存限制，支持 Markdown、数学公式和图片。渲染组件已确认 react-markdown＋remark-gfm＋remark-math＋rehype-katex／KaTeX：预览与选手页面共用组件/配置，首期禁用原始 HTML、限制链接/图片地址，KaTeX trust 为 false 且展开/尺寸受限；题面图片、公式样式与字体校内提供；样例原始文本保留空格/换行并可复制，公式错误局部提示，详见 [渲染约定](architecture/frontend-sandbox-options.md#33-已确认的题面-markdown-与公式渲染)。具体版本及运行效果待验证。
- 题目来源包括原创、获准使用的第三方题目材料，以及允许导入的题目包。已确认后台手动录入与 ZIP 导入统一转换为内部题目模型，优先验证 ICPC／Kattis 2025-09 子集；MCP 或爬虫作为其他候选入口，不预先绑定实现。
- 导入先形成私有草稿，完成受限验证与审核后才发布不可变版本；保留原包、哈希、来源与使用依据，明确展示判定配置差异，不支持或无法忠实映射的内容报告并阻止发布，API 不执行题包程序。子集含 Markdown/本地图片、样例/正式数据、限制及所支持的检查规则和程序材料，具体兼容矩阵与组件尚未验证，详见 [题包设计](architecture/problem-package-design.md)。
- 导入题保留来源平台、原题编号、原始链接、获取日期和使用依据；不能将“网页可访问”直接视为可转载许可。
- 自建测评数据标明“本站自建数据”，保留数据版本；本站 AC 与原站 AC 分开记录。
- 原创题与外部导入题使用统一的质量检查和发布流程；正式比赛题在公开前保持私有。

### AI 辅助与数据验证

已确认流程：题面和约束草稿 → AI／人工候选标程及生成器 → 分阶段验证 → 人工确认标程 → 非作者终审 → 发布或授权给指定比赛。

- AI 可辅助生成标程、暴力解、数据生成器、输入校验器和测试覆盖建议。模型输出作为候选内容，不直接成为正式答案或发布结果。
- 标程须经过算法与复杂度审查、样例及边界验证；适用时用独立解法或小规模暴力对拍。不同模型生成的相似代码不能单独构成独立正确性证据。
- 生成正式输入后，使用已确认标程执行得到期望输出；答案不唯一时使用经过验证的答案检查器。首期题型已确认标准输入输出＋文本比较、显式浮点容差和受限 SPJ，见 [判题设计](architecture/judging-design.md)；交互题和直接提交答案题后续扩展。
- 数据覆盖典型输入、最小／最大规模、边界、特殊结构和常见错误算法；使用错误解、低效解检查数据区分度。
- 输入校验器与输出检查器分别验证，并以非法数据/畸形输出测试校验器自身；未完成或失败的必需检查阻止发布。AI 提供者可替换，人工流程完整，不默认外传私有材料；任务并发、上下文、输出、重试和取消有预算，取消后的迟到产物仅作候选。
- 保存生成器、校验器、标程版本、随机种子、执行环境、验证报告和审核人，支持复现。
- 验证报告展示失败原因与覆盖范围；没有完成的检查不得显示通过。遇到题意歧义、解法冲突或约束缺失时退回人工处理。
- 题目建议状态为草稿、验证中、待审核、已批准、已发布、已归档。内部训练赛可使用已批准且授权的未公开题目。
- 题面、标程、检查器或数据发生实质变更后生成新版本并重新验证；比赛固定引用版本，赛时更新与重判须通过裁判操作。
- 数据生成、标程和检查器执行同样需要受限运行环境、超时和资源限制；AI 任务有预算、失败重试边界和可取消状态。

### 判题与反馈

- 首期已确认标准输入输出式算法题，支持文本比较、按题显式配置的浮点容差与受限 SPJ；交互题、直接提交答案题后续扩展。文本默认按空白分隔 token、默认接受 ASCII 大小写差异、忽略空白数量/换行差异；浮点不开全站通用误差，严格整数/浮点字段混合用自定义检查器。全部要求的测试通过才 AC，不引入部分分；已确认固定测试顺序随题目版本发布，单份提交串行测试、首次选手失败停止，不跨测试点按错误种类改判。需编译语言每尝试编译一次，逐点新隔离环境；不同提交按资源预算并行。系统故障中止本次尝试并有限恢复，不计选手错误或罚时；后续测试标未执行，耗时/内存仅描述实际执行部分，见判题设计第 5.1 节；检查器及参数绑定题目版本，检查器构建失败/崩溃/超时/非法协议归系统错误，不判选手 WA 或计罚时。详见 [判题设计](architecture/judging-design.md)，SPJ 已确认 ICPC 协议（原生 42/43 正确/错误，其他退出/异常为系统错误）、testlib 优先验证及 GNU++17；固定适配/工具链/制品哈希，核验比较语义，原始诊断默认供裁判，准入前核验依赖并做隔离验证。浮点规则已确认：每题显式配置绝对/相对容差，同时配置时满足任一项即可；只接受有限十进制/科学计数法数值，数值位置非法输出为 WA，非数值 token 沿用题目大小写配置（默认接受 ASCII 大小写差异）。非法容差/无效标准答案阻止发布，参数和比较实现版本绑定题目版本；数值解析精度/溢出与适配实现、组件准入仍待验证。首批工具链与语言标准按本文件已确认范围实施，具体配置见 [工具链设计](architecture/frontend-sandbox-options.md#61-首批工具链与语言标准)；补丁与构建版本、命令和资源规则待验证。
- 每场比赛选择允许语言，并公开对应版本与限制；按语言配置合理资源限制，避免不同语言被不透明规则影响。
- 过程状态与结果分离；统一结果为 AC/WA/CE/RE/TLE/MLE/OLE/SE，不设 PE，明确的格式错误为 WA，未知或证据冲突为 SE。单点异常依据执行阶段及可信终止原因归因，不用错误文字或回报先后猜测，详见判题设计第 5.3 节。
- 资源按测试点 CPU 主限制＋墙钟兜底、进程组总内存及输出/线程/临时盘等有界预算执行；编译、运行、检查器独立限制。语言规则校准并公开，数值等硬件明确后验证。
- 正式比赛最小反馈、训练按题配置、裁判完整受控诊断；正式赛默认可看本队判定和过滤限长编译错误，隐藏测试编号/数量、正式 I/O、差异、标程与题解。默认不展示精确运行时间/内存，需展示汇总时赛前统一声明。训练也默认保护私有数据。
- 已运行点汇总为最大 CPU 时间与最大进程组峰值内存，编译分开，未执行/未知不能填零或假造通过率；诊断转义、截断标识和权限覆盖所有出口。
- 自定义输入调试采用受限自测任务、独立配额与临时结果：执行时固定源码/语言/入口和自有输入，返回受限输出与状态，不能调用隐藏数据/SPJ/标程充当答案服务，不计正式成绩或成长。训练默认开、正式赛默认关，可赛前统一启用；仅一次运行收集结果，无交互终端或常驻调试器，详见判题设计第 7 节。
- 封榜默认只隐藏对外榜单中指定时间后的结果，不停止真实判题，也不自动禁止选手查看自己的判定。

## 比赛与报名

### 比赛形式与账号

| 场景 | 已确认账号行为 | 排名主体 |
| --- | --- | --- |
| 个人赛 | 使用个人账号；正式线下赛建立受限参赛会话 | 个人 |
| 线下团队赛 | 每场比赛生成独立专用队伍账号，限该比赛使用并在赛后查看窗口结束后失效 | 本场参赛队 |
| 线上团队训练赛 | 成员个人账号提交，保存提交者，合并本场队伍提交 | 本场参赛队 |

账号与选手的映射由报名名单确定。线上团队赛任意成员通过同一题只计一次通过，罚时按本场全队提交计算。线下共用队伍账号的成绩不用于推断具体成员独立完成了某题。

专用队伍账号绑定本场报名确认的名单快照，后续退队/换队不改变历史；使用独立随机密码，校内工作人员可离线发放、重置与协助换机。热身与正式赛分别授权，提前登录不开放正式题目。账号停用后保留提交与成绩，成员通过个人账号按授权查看历史；工作人员使用各自账号及指定比赛角色。

### 校赛组织流程

已确认流程：发布赛事与报名规则 → 用户组队 → 成员确认 → 提交报名 → 自动校验明确条件＋人工资格审核 → 分配机房座位与账号 → 热身检查 → 正式比赛 → 成绩复核 → 滚榜颁奖 → 按策略开放补题与题解。

- 校外用户可以注册训练；是否可参加某场校赛、是否计入奖项，由该场比赛的资格规则决定。
- 每场可开放申请、定向邀请或管理员导入；支持待审核、需补充、已通过、未通过、已撤回及审计。自动检查报名时间、人数、同场重复身份；学籍等不能可靠核验的条件人工审核，不依赖协会身份。
- 审核绑定确认名单版本，变化后重新确认审核；通过后生成参赛身份及所需账号，不绕过开赛、名单冻结和停交限制。退赛或撤销资格不删历史提交。候补需显式配置，不默认按申请先后录取，报名容量与奖项名额分开。
- 支持多个距离较近的机房，训练赛可只使用一个教室；队伍位置记录为赛场／机房与座位号。
- 人数上限、报名截止时间、审核截止时间、组别和奖项范围可配置。
- 推荐提供报名与座位表导入导出、账号发放及赛前检查，具体文件格式在接口设计阶段确定。
- 支持比赛延期开赛、延长结束时间和异常恢复的受控操作并留痕；暂停计时及暂停期间提交规则暂不定义为首版必需。

### ICPC／ACM 计分

- 已确认对标官方 ICPC／ACM：解题数降序、总罚时升序、最后一道解出题首次 AC 时间升序；仍相同则并列，名次 1、2、2、4，不用内部 ID 拆并列。
- 每道已通过题按首次 AC 距开赛时间向下取整到整分钟，加此前计罚错误每次 20 分钟；保留原始时间用于顺序、边界和审计。未解出题不计总罚时，首次 AC 后不增加罚时。
- CE、SE 不计罚；WA、RE、TLE、MLE、OLE 等选手错误按该口径计算。提交有效区间为 `[开赛, 结束)`。
- 比赛开始／结束边界以服务器接收时间为准；结束前接收的提交即使结束后判完也参与正式结果。
- 赛后补题、非正式参赛、裁判试题提交与正式参赛成绩分离。

## 榜单与 ICPC 式滚榜

- 比赛提供选手、公开观众和裁判视图，裁判可以查看完整真实结果。
- 封榜时间可配置；推荐按提交接收时间决定是否隐藏。封榜前提交、封榜后判完的结果仍更新公开榜。
- 封榜后公开端只获取允许公开的信息；隐藏成绩不能仅在前端遮挡，也不能通过提交列表、统计接口、通知或气球记录泄漏。
- 比赛结束不自动解封。待判题完成、重判与查重相关裁决确认后，组织者确认最终结果版本，再开展滚榜。
- 滚榜以 ICPC Tools Resolver 为主要行为参考：从低排名向高排名逐步揭晓隐藏结果，展示判定与名次移动，支持主持人逐步推进、暂停、继续、速度控制和奖项停顿。
- 提供大屏展示和独立主持控制；推荐支持预演与从检查点恢复。对标效果需要在设计阶段选定参考录像和样例比赛，不将视觉一致性视为已经验收。
- 结果版本在滚榜期间固定；若需修正成绩，应中止并明确重新确认版本，不能无提示改变已揭晓内容。
- 已确认标准导出＋外部官方 Resolver 优先验证＋展示适配器；导出和事件子集、离线效果与控制恢复须实测，不声明完整 CCS 兼容。官方工具自定义许可证的本项目适用性仍须准入核验，详见 [比赛设计](architecture/contest-design.md#6-奖项与滚榜)。

## 气球与赛时事务

### 简单气球登记

- 每队每题首次通过产生一条气球任务，重复 AC 或重复事件不重复产生。
- 任务显示队伍、题号、气球颜色、机房、座位、通过时间和发放状态；支持机房筛选。
- 状态以待发放、已发放为主，保留操作人和时间；误标可纠正并留痕。
- 暂不做领单、配送路线、配送中状态或复杂调度。
- 已确认隐藏成绩对应气球暂缓发放，裁判保留受限队列，按解封/揭晓授权处理，不能通过气球泄漏封榜结果。
- 重判取消 AC 时，未发放任务撤销；已发放任务标记异常交人工处理，不自动要求回收气球。

### 答疑与公告

- 选手按题目或一般事项提交答疑，裁判可单独回复或发布对所有参赛者可见的澄清。
- 答疑有待处理、已回复等状态，保留完整处理记录。全体公告不得携带不应公开的个别队伍信息。
- 比赛页面展示公告与未读提示；广播范围限定在相应比赛。
- 私有答疑支持追加、认领转交及版本冲突处理；影响公平性的解释去除个别信息后全场澄清。通知先持久化再提示，断线补取；送达/已读分开，编辑形成新版本及未读提醒，不抢焦点，全部待处理事项解决后才最终确认。

### 代码查重

- 首版采用本地离线检测＋赛后批处理＋人工复核，Dolos 优先验证、JPlag 备选；同场同题及适用语言分析，源码不上传外部服务，语言语法支持须验证。解析失败标未检测，不能标低相似；内容去重仍保留作者及时间关系。
- 报告包括相似片段、相关提交、使用的检测配置和版本，排除或说明题目模板代码的影响。
- 相似度是复核线索，不能自动等同作弊。人工结论、依据和处理结果留痕，并允许纠正。
- 裁判可将相关记录置为待复核；成绩和奖项是否受影响由有权人员决定。待复核与已确认违规分开表示。
- 查重报告和他人源代码默认仅向授权裁判／管理员开放；引擎/解析器/模板排除配置及输入集固定版本，低优先级独立预算，保留历史报告与人工纠错依据。

## 赛后开放策略

下列为已确认默认，组织者在赛前配置。补题权限、题解、最终成绩、源代码和正式材料分别授权，不能用一个“比赛结束”开关同时放开。

| 内容 | 战队训练赛 | 协会官方赛与校赛 |
| --- | --- | --- |
| 补题 | 比赛结束后向原有获准参赛者开放，补题记录单独统计 | 推荐在成绩确认和滚榜结束后向配置的人群开放 |
| 题解 | 结束后按组织者预设时间开放；仍未批准的题解不自动发布 | 推荐随赛后公开安排发布，可继续保密复用 |
| 最终榜单 | 未封榜比赛结束后继续更新有效提交；封榜比赛由组织者解封 | 人工确认后按滚榜／颁奖安排公开 |
| 自己的代码 | 个人账号或本场队伍范围内可访问 | 同左，比赛专用账号失效后通过受控历史访问入口查看 |
| 他人的代码 | 默认不公开，用户或组织者按规则另行授权 | 默认不公开，保留查重和裁判复核权限 |

训练赛对外开放不等于把私有题目永久转为公共题库。题目所有者授权与比赛开放范围共同决定访问权。

正式测试数据、答案、SPJ 和标程默认私有；题解同时满足发布时间及审核批准才能发布。新队员不自动取得旧比赛源码，专用账号失效不删除历史。发布前预览人群及内容并审计。

### 奖项与结果变更

排名与评奖资格分开，打星/特邀身份显式展示。每场赛前公布固定名额或比例、基数、取整、最低解题、兼得及完全并列办法；规则缺失不能自动定稿。系统生成绑定正式结果版本的候选名单，人工确认发布；重测/纪律裁决或资格变化使候选失效，发布后更正保留新旧版本。实际比例、分组和名额按真实通知配置，不预设通用公式。

重测保留旧有效结果并生成候选，训练有效新结果可自动生效，SE 不覆盖旧结果；正式赛单份/整批审核后按同一结果版本生效，检查基线与并发冲突，重算首次 AC、罚时和派生记录。赛程调整、停交和延赛人工裁决且版本化，停交不停止计时；不丢已接收任务，不回填浏览器时间，封榜不因延期自动解除。详见 [比赛流程](architecture/contest-design.md)。

## 外部赛事与成长评估

### 赛事导航与数据同步

- 聚合 Codeforces、力扣、牛客小白月赛等的可用赛事信息，展示名称、时间、平台、状态及原站参赛链接；在原站报名和参赛。
- 用户绑定外部账号后，按各平台实际允许的接口同步提交、比赛成绩、Rating 等可用字段。每个平台分别核验能力，不承诺全部字段实时同步。
- 保存来源、原始赛事／题目 ID、数据更新时间和同步状态，区分未绑定、未参赛、信息未公开、同步失败与已同步。
- 支持限频、缓存、可恢复重试、手动刷新和人工补充证据。失败不删除已有有效历史，也不将未知记成零分。
- 外部官方数据修订后可更新，并保留对本地积分或画像产生变化的依据。
- 不要求用户交出第三方平台密码；账号归属确认和数据访问授权方案待平台接入时核验。
- 已确认官方接口优先、平台适配器隔离、人工补充证据，首个验证 Codeforces；账号区分未绑定、待核验、已核验和失效，同名/输入 handle 不证明归属。未核验记录不进入资格或成长计算；保留稳定来源 ID、时间及证据，跨站 Rating 不合成统一分。
- 全平台限频、增量缓存和有界退避，手动刷新共享预算；数据缺失/失败不等于零，官方修订保留历史，人工证据不被静默覆盖。外部同步可停用，不阻断校内比赛，不承诺实时全量支持。

### 三类成长展示

| 展示 | 目标 | 推荐默认 |
| --- | --- | --- |
| 成长积分与等级 | 让同学看到持续投入的成果 | 首次有效解题、题单完成、赛后补题等累计；正常活动不倒扣，误计与违规积分可审计纠正 |
| 算法能力画像 | 发现短板，为检索队友提供依据 | 按专题、难度和限时表现分析；展示证据量与时间范围，资料不足显示未知 |
| 比赛成绩 | 如实记录竞赛表现 | 本站成绩与各原站 Rating 分别保留，允许波动，呈现成长趋势 |

- 积分规则与版本公开，重复提交不重复加分；同源题去重，无法确认题目同源时不伪造等价关系。
- 常规训练表现和限时比赛表现分开；团队成绩不能直接当作每位成员的个人能力。
- 队伍账号下无法区分作者的提交不自动向每位成员计入独立解题积分；团队参与奖励如需设置另行定义。
- 薄弱专题进步与补题可获得额外正反馈；具体权重、等级曲线、去重和防刷细则待验证。
- 默认个人完整画像对本人可见，公开档案由本人选择展示；队长能查看本队任务进度，不能因此获得所有私有外部记录。
- 每项结论关联有效记录、规则版本、样本量和时间范围；资料不足为未知，待核验/不完整/纪律复核有标识。历史改判可重算和冲正，同源关系须有证据；成长积分权重与等级曲线用代表性样本后验证，不自动用于选拔或名额分配。
- 用户已明确用途为成长、短板识别、组队和正反馈；自动用综合评分决定校队选拔或参赛名额不属于已确认要求。

## 通知解析与参赛名额

- 管理员提供官方通知链接、文件或手工内容，AI 提取赛事、年份、站点、资格、名额计算条件和截止时间。
- 每条提取规则关联通知原文位置；区分原文明确规定、AI 推断、缺失信息与冲突，不把推断直接作为可执行规则。
- AI 提取候选，人工确认规则后以确定性逻辑计算，再人工分配；只使用受控规则类型，不执行 AI 任意代码，保留输入快照与规则版本。
- 展示“系统预计名额”“主办方确认名额”“已分配”“已报名”等不同状态；具体剩余名额根据已确认的口径计算。
- 管理员可手工录入、修正规则和结果，必须保留原因、前后值与来源；AI 重新解析不能静默覆盖人工确认。
- 通知更新后提示受影响站点与队伍，生成待复核版本，不自动改变已确认分配或报名。
- 名额分配给队伍仍由管理员决定；正式外部报名仅记录进度与链接，首版不承诺自动代报名。
- 尚缺真实通知样本和计算案例，暂不固化某届 ICPC 的公式，也不声称“达到某排名必得固定站点名额”。
- 预计与主办方确认分开，已分配与已报名分开；报名不重复扣减已分配名额。缺公式/证据标未知，不填零。规则按年度/赛事/站点作用，更新先展示差异及影响，不能自动取消分配或代报名。

## 模块边界与部署

### 推荐模块划分

| 模块 | 拥有的数据与职责 | 对外提供的能力 |
| --- | --- | --- |
| 身份与权限 | 个人账号、角色、外部账号绑定 | 身份校验与授权判断 |
| 战队与训练 | 长期战队、邀请、题单与任务进度 | 队伍关系与训练安排 |
| 题库与出题 | 题面、来源、标程、数据、题目版本和审核 | 可授权的固定题目版本 |
| 判题 | 提交执行任务、运行环境、判定和节点状态 | 受限执行、结果与重判任务 |
| 比赛 | 报名、参赛阵容、规则、有效提交和赛程 | 参赛资格、成绩事实与比赛事件 |
| 榜单与滚榜 | 基于比赛事实派生的视图与揭晓状态 | 不同权限的榜单与展示控制 |
| 比赛事务 | 答疑公告、座位、气球、查重复核 | 指定比赛的工作人员操作 |
| 外部同步 | 平台适配器、同步状态和原始数据快照 | 带来源与时间的标准化外部记录 |
| 成长评估 | 积分明细、画像规则和聚合结果 | 可解释的个人／队伍成长信息 |
| 名额管理 | 通知、规则、计算和确认版本、分配 | 可追溯的名额计算与管理 |

- 模块通过公开接口和有版本的事件协作，不直接修改其他模块私有数据。
- 题目导入、第三方赛事同步、AI 服务、查重引擎和判题后端使用适配边界，允许替换供应商与实现。
- 榜单、气球和成长统计依据可追溯的比赛／判题事实更新，处理重复、乱序和重判纠正，避免各自维护互相矛盾的 AC 记录。
- 比赛名单保留历史快照，与用户当前战队归属分离。修改模块规则必须检查调用方与历史兼容性。
- 用户已确认 Go + Gin 自研，先采用模块化单体＋独立判题 Worker，判题节点独立扩展；优先验证 PostgreSQL＋持久化任务表及 go-judge，组件正式采用待验证。前端已确认 React＋TypeScript＋Vite＋Tailwind CSS＋shadcn/ui 与 CodeMirror 6，首期代码草稿仅浏览器本地保存，路由/请求/缓存/包管理器已确认 React Router（声明式）＋TanStack Query＋原生 fetch＋pnpm，契约与配套见 [接口与任务](architecture/api-worker-design.md)，具体版本待验证；技术决策见 [ADR-001](architecture/001-go-gin.md) 和 [选型比较](architecture/frontend-sandbox-options.md)。
- 存储已确认数据库保存小数据（含受限提交源代码）、校内本地磁盘保存大文件、Worker 本地缓存，预留对象存储接口。API 多副本必须读取同一份权威材料；Worker 缓存可重建，不替代备份。首期同机 API 共享持久化目录，跨主机扩展前接入统一可访问后端；见 [存储设计](architecture/storage-design.md)。

### 容量和可靠性

- 用户明确要求负载均衡、高并发并节约学校资源；“资源可能有限”为规划前提，实际硬件尚未核实。业务请求分流与判题任务分配分别设计，不将该要求自动解释为采用微服务。
- 在资源预算内验证多 API 副本负载分担与多 Worker 调度；限制数据库连接、在途请求、执行并发及队列/磁盘占用。允许受控排队、降级和明确拒绝，但已接收提交不得丢失；容量报告须包含拒绝和超时，不能用过度限流冒充达标。
- 已确认规模为约 300 名参赛者，不等于 300 个同时运行的判题任务；团队赛队伍数量和峰值提交量仍待确认。
- 支持学校服务器与多台机房主机组成判题节点池；每台主机的系统、CPU、内存、可用时段和安装权限需现场核验。
- 判题并发受每个节点资源限制，超出容量的提交可追踪排队；正式比赛与训练／AI 造数据任务可隔离或设置优先级。
- 节点掉线后任务可恢复处理且不会重复计分；提供队列积压、节点健康和系统错误的观测。
- 判题节点与业务数据、宿主机敏感资源隔离；执行用户代码时限制网络、文件、进程和资源使用。
- 部署交付应包含经过验证的初始化、增加／移除判题节点、备份恢复和故障处理流程，减少每次办赛重新探索部署方法。
- 内网穿透是既有部署经历，不直接作为新平台必选方案。推荐判题节点通过受控网络连接服务；正式比赛不依赖 AI 或外部同步实时在线。
- 已确认正式校赛须在校内断外网后继续完成登录、提交、判题、榜单和赛务；核心服务与页面资源应在校内可用。具体网络拓扑、机器与权限、恢复时限和备份频率待询问确认，设计展开见 [总体架构讨论稿](architecture/system-design.md)。

| AC10 | 同一队同一题只产生一条气球任务，按机房和座位准确展示；误标和重判异常有可追踪处理 |

| AC13 | 比赛结束后按策略开放补题与题解，补题不改变正式成绩；滚榜前不提前公开隐藏结果 |

| AC15 | 通知解析结果保留原文依据，未经管理员确认不生效；通知更新、人工修正可追踪且不会被自动覆盖 |
| AC16 | 在约 300 人使用与集中提交场景压测，测量提交接收、队列等待、榜单延迟、错误率；注入节点掉线并确认不丢已接收提交、不重复计分 |
| AC17 | 代码、测试数据、未发布题解、报名资料和完整查重报告按权限访问；直接请求接口仍受同样限制 |
| AC18 | 正式校赛环境断开外网，使用未缓存页面的新浏览器完成本地登录、看题、提交、判题、榜单与赛务操作；校内服务可重启恢复，外部 AI/同步停用不阻断比赛；具体断网拓扑及恢复时限在硬件核验后定版 |
| AC19 | 至少两个 API 副本经入口分流，跨副本登录会话、提交幂等、任务认领和配额一致；副本退出/恢复后重新分流，无重复计分；记录故障窗口内失败及恢复时间，不将同机多进程当作主机高可用 |
| AC20 | 在明确的 CPU/内存/连接/磁盘预算下进行混合负载、突发提交及过载恢复测试；验证有界执行、持久化排队、低优先任务降级和超水位明确拒绝，已接收提交不丢失；记录资源峰值、时延分位数、接受/拒绝/超时和队列恢复情况 |
| AC21 | 在线编辑具备高亮、缩进和快捷键；可选择代码文件并经确认提交；在当前浏览器存储可用且数据未清除时，代码草稿刷新后可恢复，不向服务器同步草稿或承诺跨设备恢复；保存失败可见且不冒充提交成功；切换用户、题目或比赛不串用草稿；超限/不支持的文件和覆盖未保存内容有明确提示 |
| AC22 | 多 API 副本访问同一材料版本；文件写入/发布中断、并发写入及磁盘不足不暴露半文件或无效发布引用；Worker 缓存丢失/损坏可重建且不绕过授权，选手无法读取整个缓存或标准答案；从独立备份恢复数据库及其引用文件后，哈希一致且既有题目版本可重新判题 |
| AC23 | 至少两个 API 副本下验证登录、退出、凭证轮换、封禁/撤权、空闲与绝对过期及续期/撤销竞态；Redis 超时或写入失败不得冒充成功或绕过鉴权，旧数据恢复不得使已撤销会话复活；验证 Cookie/CSRF 保护与校内断外网登录，故障和恢复时间如实记录 |
| AC24 | Argon2id 新记录使用独立随机盐并可正确校验；错误密码、畸形记录、越界参数或不支持版本明确失败；旧参数成功验证后可安全升级，升级与并发改密/重置不覆盖新凭据、不产生有效旧会话；密码及完整验证记录不入日志，断外网可校验；实际硬件下测试多 API 集中登录/批量发号的计算并发、CPU/RSS、排队与过载恢复，参数及预算可追溯 |
| AC25 | 日常注册须验证邮箱后激活，未验证不能提交；找回请求不改变密码或既有会话，有效令牌重置成功才撤销旧会话；令牌绑定主体/用途/期限，过期、错用途、重放及多 API 并发重复消费失败，不复活禁用账号；发送与校验限流、响应防枚举、秘密不入日志；邮件失败不绕过验证，真实断外网仍可既有账号登录、校内发号/人工核验重置、提交、判题、榜单和赛务；开发收件器测试与真实投递验收分开记录 |
| AC26 | 相同判定事实得到整分钟/20 分钟/CE-SE 不计罚和正确并列名次；边界与原始提交顺序准确，正式重测整批审核生效，冲突阻止发布 |
