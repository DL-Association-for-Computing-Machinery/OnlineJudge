## 试用节点只读盘点（2026-11-14）

通过 SSH 公钥和严格主机密钥校验，以普通 `guest` 用户在目标节点运行 `uname`、Docker 客户端版本检查及 [target-inventory.py](../../scripts/target-inventory.py)。脚本由 SSH 标准输入送入 Python，无远端文件落盘。目标为 Ubuntu 24.04 x86_64，内核 `6.8.0-124-generic`，可见 CPU 亲和性为 4，系统总内存约 3.64 GiB，交换空间约 1.94 GiB；`/tmp` 所在文件系统当时约有 31.2 GiB 可用。登录会话可见 cgroup v2，祖先之一报告进程上限 9613；这些数据只描述盘点进程及文件系统，不是 Worker 容器配额。材料、数据库卷尚未指定，未取样。

Docker 29.6.1 是已观察到的客户端版本。标准 Engine socket 对此用户不可用（缺失或不可写），未确认 Engine 版本或容器隔离。现有 [Ubuntu 本地档位](../checker-admission.md#ubuntu-独立判题实验) 固定 arm64、`6.8.0-106-generic`、原生专用 Engine 和固定镜像；它与本机报告不能作为试用节点的档位或证据。盘点没有安装依赖、改权限、创建或启动容器，也未写入题目材料。

现场准备顺序：管理员先确认可执行受控实验的专用节点或隔离客体、容器运行权限与材料/临时路径；在本地锁定 amd64 工具链、执行镜像、内核和运行参数，为固定 17 点材料生成新档位的交接制品，并验证旧档位、错对象或错制品均不能启动。现场仅用已核对的制品执行固定 AC、WA、OLE 对照，保存原容器停止证据及独立检查器观察，再按同一修订复核。不能用共享主机上的普通 Docker 权限代替专用隔离；检查器准入、普通终审与发布仍独立处理。

## A+B amd64 候选镜像

[候选 Dockerfile](../../deploy/experiments/go-judge-aplusb-amd64.Dockerfile) 从原实验 Dockerfile 锁定的两个多架构索引中各选取唯一 `linux/amd64` 子清单，并保留执行器入口参数。原 arm64 镜像和运行档位保持不变。

```sh
docker --context desktop-linux buildx build --platform linux/amd64 --load \
  --provenance=false --network none \
  -f deploy/experiments/go-judge-aplusb-amd64.Dockerfile \
  -t oj-p4-aplusb-amd64-candidate:local .
docker --context desktop-linux image inspect --format '{{.Id}} {{.Os}}/{{.Architecture}}' \
  oj-p4-aplusb-amd64-candidate:local
docker --context desktop-linux run --rm --pull never --platform linux/amd64 \
  --network none --read-only --cap-drop ALL --security-opt no-new-privileges \
  --entrypoint /usr/local/bin/g++ oj-p4-aplusb-amd64-candidate:local -dumpfullversion
```

本地构建报告的镜像清单摘要为 `sha256:bfb42a2daf3f86c8636e3db883179852f385df1a31fd2b9f4a42d01e7e9f502c`，配置摘要为 `sha256:fe1a97991b090d9232fb8b086139925debe96dce834fe16def8c7f3373a2f4f9`；Docker 回读 `linux/amd64`，GCC 回读 `15.3.0`。这是本机候选镜像构建和版本读回，未验证独立重建、原生节点上的 go-judge 执行或隔离。尚未将候选镜像登记为 Worker 档位，也未传到试用服务器。

## A+B amd64 候选材料

对固定 A+B 17 点私有题包运行 [离线清单命令](../../README.md#ab-固定材料隔离判题)，增加 `--trial-amd64-candidate`。该分支只接受已审核的完整导入修订、正式 Plan、检查器候选与 `262144` 字节／每 token `12` 字节上限。生成的判题清单摘要为 `8fc0161f7229ea8c8882098d61973fa6f1b81c3bda4fcccc0c6d285fb1c94817`，其中检查器试验档位摘要为 `0127bfe7d7703cd5eb382f33d71dc81bdb8860d1c69abe20a5c2f51dc45c3365`。导出需单独传入已核对的该清单摘要以及新的私有目录。

现场候选档位的内核来自只读盘点，镜像来自上方构建。材料仍是同一 17 点，运输清单会绑定候选档位；现有执行配置和交接回执验证器均不接纳它。后续须验证专用节点、原生 Engine、镜像身份、有效容器限额及生命周期，再登记可执行档位。

本机无网络 Docker 中，以固定私有题包两次导出，32 个对象与运输清单逐字节一致。运输清单摘要为 `d136160e862b2553e6bb0c87637052635ec2871d72f7efcb51840454479e89b4`。传入旧 Ubuntu arm64 判题清单摘要或同时选择两个档位均被拒绝，未留下输出目录。该测试未运行判题程序或访问试用机。

## A+B amd64 候选交接

沿用 [A+B 交接命令](../checker-admission.md#ab-目标节点交接)，以 `--runtime 0127bfe7d7703cd5eb382f33d71dc81bdb8860d1c69abe20a5c2f51dc45c3365` 和 `--slot oj-aplusb-trial-amd64-sandbox` 封装或核对这个候选包。封装输出仅含 32 个固定对象、运输清单和交接清单。接收方必须从独立渠道获取预期交接摘要、节点、候选 Git 修订及档位，不从收到的包推导这些预期值。

候选包使用 `oj.aplusb-trial-candidate-handoff.v1`，只支持 `pack` 和 `verify`；报告核验及回执生成均拒绝该协议。成功核验只证明候选字节与约定绑定一致；不表示指定节点真实运行过，也不解除生产检查器、目标运行时或终审的阻断。

本机无网络复验：用测试节点标签和测试 Git 修订两次打包，34 个文件逐字节一致；接收方按独立摘要回读成功，修改节点标签或一个对象字节均失败。该包只用于演练；现场包应按获准节点及正式构建修订重新封装。

## A+B amd64 停止槽预检

专用节点的管理员在独立核对节点及制品、预置停止槽并保存其完整容器 ID 后，可用 `checker-candidate aplusb-trial-preflight --container-id "$ORIGINAL_CONTAINER_ID"` 读回配置。只接受 Linux amd64 上的本机 Docker Unix socket，核对固定内核、cgroup v2、镜像、槽身份及所有者 `onlinejudge.trial-aplusb-amd64-test`。停止槽须为 `created` 或 `exited`，PID 为 0，断网、无挂载、只读根文件系统，且设置匹配的 CPU、内存、swap、进程数和临时文件系统限额。

命令只读，不创建、拉取或启动容器；输出不含节点文件路径或凭据。成功只表示该次停止槽配置读回匹配，不能证明实际运行限额、节点专用性、判题、停止或生产准入。`guest` 的 SSH 盘点没有执行这个需要管理员读取 Engine 的检查。不得把预检通过当成批准启动的依据。

本机无网络工具容器通过 Linux amd64 交叉构建、`workerhost` 和 `checker-candidate` 竞态测试及 `go vet`。本机 Docker 另用一个临时、非特权且从未启动的容器核对真实 `inspect` JSON 模板与镜像 ID、平台字段，核对后移除该容器；本机 Engine 是 arm64，此实验未通过或替代专用 amd64 节点的完整预检。

## 批准账本迁移

本机无网络临时 PostgreSQL 14 验证 schema 25 与 26 之间的空账本回退和重升；错误资格修订违反外键，重复分配批准违反唯一约束。非空时 Down26 被拒绝，原记录和 schema 26 保留。原送审迁移和同材料退回回归同时通过。此验证直接写入隔离夹具以检查数据库约束；普通批准接口、实际终审和发布事务尚未执行。没有迁移任何持久数据库。

## 内部批准事务

临时 PostgreSQL 14 复验了正确摘要但准入仍阻断时不写审批、错误摘要拒绝、原键回执与同键异意图冲突，以及当前批准阻止同材料退回、重新分配后可由当前审核人退回。回执部分使用显式写入的历史夹具验证，没有代替业务路径生成真实批准。批准、退回和授权集成回归及审核相关 Go 竞态检查通过；HTTP 批准入口和现场准入证据仍待完成。

后续接入了默认关闭的[批准 HTTP 入口](../problem-drafts.md#批准准入状态)。本地 HTTP 测试验证未启用时返回 404、跨站请求不能到达批准服务、阻断响应和按原键读取分别路由；未运行实际非作者终审，现场证据仍待取得。

## 浏览器批准与回执恢复

`scripts/test-browser-account.py --review-materials` 在隔离 HTTPS、PostgreSQL 14 和 Redis 下通过 9 项，覆盖桌面与 390px 宽度。真实准入阻断时不显示表单；测试放行浏览器展示后，真实 API 仍返回 `409 REVIEW_APPROVAL_BLOCKED`，页面要求重新读取。另模拟批准响应丢失及匹配回执：刷新只按原键 GET，真实 404 保留原键，回执匹配后显示已核实，没有第二次 POST。浏览器报告 SHA-256 为 `dae78f5057ccbd4374054a4136ca2eca136c6e303fd33b50041d852e6b53b133`。前端 164 项及 lint、类型和构建，后端格式、静态检查、全量竞态测试和构建，以及两个临时 PostgreSQL 批准测试均通过。模拟回执不证明真实提交成功；现场准入、实际非作者批准和独立发布仍待验收。

## 发布事务内的批准复核

隔离 PostgreSQL 14 的 `TestPublicationGate*` 八组竞态测试通过。用历史批准夹具验证准入仍阻断、错误审核人、材料、策略或快照无法通过，以及撤权重授、改密、恢复代次变化和同人改派使旧批准失效。通过 PostgreSQL 实际锁等待证明门禁取得送审锁后读到新分配，且调用者回滚前保留锁。按送审项和分配修订查询可命中已有批准主键（小夹具关闭顺序扫描核对，未新增索引）。未连接发布写入，夹具没有绕过实际终审策略。

## 独立发布资格

四组 `TestPublisher*` 在隔离 PostgreSQL 14 通过竞态检查：未授权或旧修订拒绝；等待账号锁后看见已提交撤权；在同一事务链接发布资格和批准门禁，实测撤权及停用审核账号等待至回滚；schema 26/27 空账本往返通过，已有授权历史时拒绝向下迁移。最新资格读回可利用新账本主键倒序扫描（小夹具关闭顺序扫描核对），未新增辅助索引。sqlc 重生成无差异，身份与参考模块竞态验证及维护命令构建通过。尚未连接可见版本写入或迁移持久数据库。

## Ubuntu VM 内部发布和目录联验

在 Mac 的现有 Ubuntu arm64 VM（内核 `6.8.0-149-generic`）以内网禁用的临时 Docker 工具容器及 PostgreSQL 14，运行 `go test -race -tags integration ./tests/integration -run '^Test(Publication|Publisher|ReviewApproval)'` 和材料封存／读回竞态专项。真实普通批准因准入缺项被拒，发布写事务在缺角色、缺批准或批准不再满足准入时均不写入；仅登记执行材料也无法通过执行准入外键。另在同一临时库用显式历史发布夹具验证原键回读、不同意图冲突、最新版本投影、字面检索和分页、草稿不可读、缺对象不返回题面，以及空迁移往返和非空回退拒绝。最新发布查找使用复合主键。

正向目录结果来自历史夹具，没有放宽普通批准或伪造现场 evidence。未完成真实终审成功写入、生产执行准入、选手 HTTP/页面或实际发布；未在这个内核重跑 Worker。

## 与主线迁移合并

主线已将 schema 26 用于平台管理员历史。P4 的三份 SQL 内容不变，普通批准、发布资格、发布与执行准入分别改为 schema 27、28、29；上文保留隔离验证时的原编号。以主线 26 为基线停机升级，空 P4 账本可以退回 26 并保留管理员历史。用旧 P4 分支编号创建的临时库不能直接沿用；应为本版本新建临时库。此次代码合并不迁移持久数据库，也不替代正式准入、非作者终审、题目发布或选手端联验。

## 本地选手只读题库与 A+B 对照复验

在现有 Mac Ubuntu arm64 VM，用临时 PostgreSQL 14 运行发布、发布资格与普通批准集成竞态测试。批准仍阻断，失败写入后 HTTP 列表为空、草稿 ID 返回 404；在历史发布夹具写入后，匿名详情的响应与封存投影一致。Chromium 的 10 项检查使用本机隔离 HTTPS、PostgreSQL 和 Redis；匿名选手可检索并刷新历史发布夹具，读取原样例、题面与静态 PNG，私有草稿仍不可访问。浏览器报告摘要 `f376e390dc316300abec77d041e4c35ac6b5a0fe39fed47d0298df47c4987ce9`。

VM 临时启动已安装的固定 `6.8.0-106-generic` 档位。A+B 17 点固定合成对照实际返回 AC、WA、OLE；反向档位绑定未启动槽，每轮确认原容器退出、PID 为零、控制锁释放，随后清理槽。新报告交接通过并封存 `report-readback-only` 回执，摘要 `73ad18073977aa75eeb367996a1e2b10b4e793d38565aec0b0de2b71e90cfed3`。这项实测还未接入受信准入写入，普通终审和实际发布成功仍待验证。操作未连接试用服务器；同一操作者使用不同测试账号可核验账号权限和功能，不能证明独立人员终审。

## Mac Ubuntu VM 本地完整流程

在一次性 PostgreSQL 与 Redis 上，以真实冻结 A+B 17 点作为草稿；独立固定 AC、WA、OLE 报告及运输清单，错误报告摘要被拒绝。浏览器夹具为正式参考结果登记测试行，并通过真实作者 HTTP 确认标程。独立的本地执行准入使用实际三份原报告，审核策略和题库读取限回环环境。

按用户授权以第二个账号在实际浏览器完成四项题意确认，审核准入之后为通过；点击批准得到 200，使用原请求键返回同一回执。批准前本地选手目录为空。用不同的发布角色运行维护命令得到 A+B，重复原发布键读回同一版本，数据库各有一条题意确认、批准和发布。Mac Chromium 未登录可打开新发布的题目，看到两个样例，刷新后样例保持一致；草稿 ID 返回 404。此项验证为自动操作的双账号功能验收；未连接试用服务器，生产准入和独立人员终审仍待完成。
