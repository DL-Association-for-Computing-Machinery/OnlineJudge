# 精简交付基线与项目骨架

日期：2026-10-25。版本：1.0。用户接受架构审计后的收敛方向，并明确要求先初始化仓库、搭建项目骨架。本页管理交付范围与组件引入时机；业务规则仍以[需求](requirements.md)和对应专题为准。延期不等于取消需求，骨架通过不等于训练或比赛验收通过。

首期实施拆分见[首期开发计划](phase-1-development-plan.md)，包含 0B/1A/1B 的依赖、开发包、里程碑和验收子项；本页继续作为发布范围与组件引入时机的基线。

## 1. 本次交付

- 复用现有 Git 仓库及 `codex/engineering-baseline` 分支，不重置或重新绑定远端。骨架完成后，用户另行授权将现有成果分组提交并推送此任务分支；不包含主线写入、合并或部署。
- 建立 Go + Gin API、独立 Worker 命令入口、React + TypeScript + Vite 前端、健康检查契约和真实应用 CI 配置。
- API 默认提供 `/api/v1/healthz`；M0 显式启用的本机接口已接入提交持久化/回执，租约与沙箱分项已验证，完整 Worker 与会话仍未接入。见[M0 记录](m0-experiment.md)。
- Worker 当前是明确提示未接入并退出的骨架检查命令，不领取任务、不执行代码、不伪造心跳或判题成功。
- 前端为项目初始化预览页，可发起真实 API 连接检查，不提供虚构题库、注册、提交或比赛按钮。
- 已有实验数据库模式/迁移、双 API 进程和独立本机 Linux 沙箱证据；无生产部署、完整判题或远端 CI 运行证据。实际验证见[交付日志](delivery-log.md)。

## 2. 技术栈与引入时机

| 范围 | 本轮处理 | 下一步条件 |
| --- | --- | --- |
| Go / Gin、React / TypeScript / Vite、pnpm | 引入并锁定版本，执行实际检查 | 后续升级单独验证 |
| PostgreSQL、sqlc、pgx、Goose | M0 已接入真实数据库、迁移、提交与租约核心及集成测试 | 补齐完整节点协议、负载与恢复验收，未正式生产准入 |
| Session / SCS / Redis | Redis 仍为既有基线；新增 PostgreSQL 会话对比验证，不直接替换 | 比较跨副本撤销、名额原子性、读写开销和故障恢复；只保留一份权威会话存储 |
| go-judge、语言工具链 | 专用本机 Linux VM 完成 GNU++17 分项实验，未连接完整 Worker | 贯通固定环境、材料授权、续租/中止与有效结果回报；不在业务进程执行选手程序 |
| Tailwind / shadcn/ui、Router、Query | 保留方向，本轮无多页面、复杂组件或查询缓存需求，按需引入 | 第一条相应产品功能，不同时引入第二套同职责方案 |
| CodeMirror、idb、Markdown / KaTeX | 随题目、编辑和草稿功能引入 | 用户界面及异常路径验收，不自研通用编辑器或解析器 |
| River / SMTP | 可靠邮件功能时引入，不自研通用队列代替成熟库 | 实际邮件流程、事务与投递验证；不赋予判题 Worker 邮件凭据 |
| Outbox | 保留可靠事件原则，随首个异步消费者落地 | 普通同步调用不强制事件化；训练结果查询先直接读取权威结果 |
| Prometheus / Grafana / Alertmanager | 分阶段引入，不要求完整套件先于首条判题路径 | 先有结构化日志、健康、积压/错误可见性，再按值守和告警目标接入 |
| pgBackRest / restic | 保留后续优先验证方向，不无条件作为骨架前置 | 先确定 RPO/RTO、独立介质和实际恢复验证；小规模试用可比较逻辑备份＋材料清单，不承诺 PITR |
| Resolver / 离线查重 | 比赛阶段先做受控导出、外部运行与结果留痕 | 工具许可、格式、语法及真实赛务演练；不先重做完整工具界面 |

不引入微服务、Kubernetes、消息代理、独立搜索服务、第二套 ORM、第二套会话实现或对象存储实现。未来新增须有当期功能或实测瓶颈依据。测试工具属于开发工具，不按常驻服务计数。

## 3. 发布阶段与边界

| 阶段 | 交付目标 | 不代表什么 |
| --- | --- | --- |
| 0A：工程骨架（本轮） | 启动 API、前端连通、Worker 入口、契约、构建和自动检查 | 无真实判题、登录、数据库或生产部署 |
| 0B：关键技术验证 | GNU++17 文本题，提交/任务同事务、认证节点认领、受限执行、有效租约回报；验证重复、失联、迟到和材料异常 | 不是可公开使用的训练产品 |
| 1A：训练试用 | 获准用户登录、已审核授权题目、单文件编辑/上传与本地草稿、真实判题、结果和本人历史；关键权限、恢复及基本运维 | 不宣称完整语言/题型、战队或校赛支持 |
| 1B：完整训练 | 补齐 GCC C17/GNU++17/GNU++20、Java、Python 及文本/浮点/SPJ，完整日常账号流程；实际需要的录入入口 | 不把尚未实现的 ZIP、多文件或正式赛事能力报告为完成 |
| 2：战队训练 | 战队邀请、题单/任务、训练赛与历史访问；其计分/参赛权限等依赖随训练赛交付 | 不等待阶段 3 才实现训练赛实际需要的比赛核心 |
| 3：正式比赛 | 报名、专用账号、计分封榜、答疑气球、查重、重测审核、滚榜；断外网、容量、故障恢复与一次完整比赛演练 | 同机多副本不等于主机高可用 |
| 4：辅助能力 | AI 出题、外部数据同步、成长画像、名额管理 | 不与训练闭环和首次完整比赛演练争抢开发优先级 |

1A 的语言/题型清单在首批用户和题库确定后冻结；GNU++17 文本题仅为默认起点，不据此取消 1B 的完整语言承诺。首期多文件/ZIP 提交与至少 10 文件目标移出 1A/1B 必需范围，保留后续扩展需求，在首个实际需要它们的版本单独排期；内部文件集模型可保留，不提前做完整文件管理界面。

日常邮箱验证注册/找回的既有规则保持。邀请制试用、管理员发号替代公开注册目前仅为可选收敛方案，尚未单独确认；不得未验证邮箱却开放原本要求验证的训练提交。比赛会话及换机管理随比赛场景接入；已经交付的普通账号规则必须完整满足本版约定，不以“骨架”掩盖鉴权缺口。

题目录入先根据真实题库来源选择手动录入或受支持题包子集之一；两种入口不同时成为试用前置。版本不可变、来源、审核、受限验证和私有材料保护不延期。试用版不包含自定义输入调试服务；自测随后续训练增强单独验收。

## 4. 验收归属

保留 AC01—35 及细化条款，不删除原验收。每个版本将跨阶段 AC 拆为可执行子项：标记本版必需、后续、待验证；不得将部分通过记作整个 AC 通过。发布范围变更须同步此矩阵及对应专题。

| 发布范围 | 对应验收及拆分原则 |
| --- | --- |
| 0A | 构建、HTTP 契约/错误、前端真实连接和失败状态、Worker 诚实标识；均为骨架检查，不记 AC01—35 通过 |
| 0B / 1A | AC06/17/20/21/22/23/24/28/29/30 中已引入的题目版本、授权、持久化、单文件、会话、任务和恢复子项；邮箱账号上线时必验 AC01/25 对应部分；文本相关 AC05 与判题细化条款 |
| 1B / 训练增强 | 补齐全部首批语言、浮点/SPJ、日常账号与题库相关 AC；选择标准导入时执行题包兼容验收；多文件、ZIP、自测启用前分别完成 AC30 对应部分 |
| 2 | AC02/03/04/07/13/33/34 及训练赛所需计分、可见性和重测子项；成长奖励暂未引入，不能因此伪造奖励验收 |
| 3 | AC06—13/16/18/19/20/26/27/29/31/32 的正式比赛与运维部分，比赛账号/封榜/赛后权限等跨条款子项 |
| 4 | AC05 的 AI 辅助部分、AC14/15/35 与成长、外部来源、名额部分；之前已完成的核心验证继续回归 |

多 API / 多 Worker 协议从关键实验验证；日常试用可按实测部署单 API，不宣称已提供高可用。已引入功能的安全、数据一致性、故障恢复与必要测试不能以后续阶段为由跳过。

## 6. 实际目录与开发约定

```text
cmd/api/              API 进程入口、超时与退出
cmd/worker/           Worker 骨架检查入口（尚无任务执行）
internal/httpapi/     HTTP 路由、错误与契约测试
api/openapi.yaml     当前已实现接口契约
web/src/services/    HTTP 调用与边界校验
web/src/             React 页面
scripts/             仓库检查
tests/governance/    治理回归
docs/                需求、设计、运行与交付记录
```

本轮没有业务规则，因此不创建空 `domain/repository/service` 层。实际功能到来时按业务所有权组织 `internal` 子包，核心业务不依赖 Gin 或数据库具体类型。Worker 不复用业务 HTTP handler 执行代码。启动、检查命令及精确版本以 [README](../README.md)、`go.mod`、`web/package.json` 和锁文件为准。

参考：审计核验过的 [SCS 存储](https://github.com/alexedwards/scs#configuring-the-session-store)、[River 事务入队](https://riverqueue.com/docs/transactional-enqueueing)、[PostgreSQL 逻辑备份](https://www.postgresql.org/docs/current/backup-dump.html)。这些只支持候选机制，不是本项目兼容、容量或恢复证据。
