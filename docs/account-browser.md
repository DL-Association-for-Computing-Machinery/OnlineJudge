# 浏览器账号与会话

账号界面使用 React、原生 fetch 与 CSS，在 `/login` 提供已有个人账号登录与原尝试恢复，`/account` 提供当前会话检查、主动续期、退出和可选改密。页面由 React Router 导航，共享同一个账号 controller；旧 `/#account-title` 转到账号页。页面不提供注册、邮箱找回、角色或训练授权；未验证邮箱也不会因此获得提交权限。六个会话接口归[会话 OpenAPI](../api/session.openapi.yaml)，改密归[账号 OpenAPI](../api/account.openapi.yaml)。

新密码至少 15 个 Unicode code point、允许空格、不强制字符组合、拒绝常见弱密码及不 trim/归一化/截断的原始字节规则，已于 2026-11-01 由用户确认，见[需求](requirements.md#登录会话)。现有实现无需改变；这不代替生产弱密码字典的来源、许可和覆盖验收。

## 入口与操作

静态页面和 API 必须来自同一个 HTTPS Origin。前端仅请求固定相对路径，不接受 API 地址覆盖；API 仍独立检查实际 TLS、Host、同源证据、Cookie 及账号/恢复状态。受信单跳代理须按[会话设计](architecture/session-design.md#714-单跳受信反向代理)配置已验证且固定指纹的 mTLS。默认 Compose 和 Vite 开发代理仍为 HTTP/bootstrap，不能用于密码操作；页面会显示 HTTPS 要求并在序列化或 fetch 前阻止账号请求。现有连接检查只说明进程连通。

| 操作 | 确认条件与后续 |
| --- | --- |
| 登录 | Begin 202 后只确认同一候选，Complete 204 后再只读检查；Read 200 才显示已核验账号 |
| 检查当前会话 | 首次加载、刷新和手动检查均只 GET，不续期；没有后台轮询、聚焦或重连自动请求 |
| 继续本次会话 | 明确点击才 POST activity，保持原绝对截止；到期提醒只按本机时间提示，不代替服务器判断 |
| 退出 | 只有 logout 204 显示确认退出；401 仅说明无可用会话，503/网络失败仍待核验 |
| 继续确认原尝试 | 使用浏览器保留的 HttpOnly 候选 Cookie，不再发送密码或新建候选；刷新后仍可手动恢复 |
| 放弃原尝试 | 204 确认原候选已放弃，但不代表当前会话退出或仍有效；该候选若已被并发/丢回执确认发放，放弃可能使其会话失效，须另行检查 |
| 修改密码 | 当前密码、新密码与本地确认；只发送前两项。204 后要求重新登录；当前密码错误的 401 不直接把已有会话当成退出，404 只说明改密能力未启用 |

普通会话达到三个名额时，页面提示先在已登录设备退出，再确认原尝试。当前没有设备会话列表、远程选择撤销、保持登录选项或比赛会话界面，不能把提示当作这些能力已交付。

## 请求与未知结果

每次用户操作在首个 await 前占用同一个执行名额，覆盖整条 Begin→Complete→Read；组件 cleanup 取消请求并推进本地代次，旧成功、错误及 finally 不覆盖新状态。取消、网络失败、5xx、不符合预期的成功状态/结构均不证明回滚，不自动重发任何 POST。Complete 已确认而后续 Read 失败时保留“发放已确认、会话尚未核验”的区别，只提供手动检查。

请求设置同源模式、同源 Cookie、no-store、无 referrer、有限超时和 `redirect: error`。禁止重定向发生在浏览器发送跳转请求之前，防止 307/308 转发密码；不能用事后的 redirected 检查替代。JSON 响应最多读取 16 KiB，按操作接受固定状态码、公开字段和错误码，页面只显示本地固定文案，不回显服务端 title/HTML 或原始异常。客户端状态不是资源访问授权。

密码不 trim、归一化或截断，不进入 React 状态、URL、日志或 Web Storage；表单提交时立即 reset，确认项仅本地比较，正确设置 autocomplete。浏览器及密码管理器可能自行保留输入，页面不承诺控制其行为。改密未知标记只在当前 controller 实例内保留，手动 Read 不清除它，明确重新登录核验后才解除；完整刷新/新页面不会保留此标记。因此表单始终提示上次改密中断时先重新登录核验，不宣称跨刷新或跨标签阻止重提。

## 验证与边界

前端服务/状态机行为测试由现有 Vitest 与 frontend CI 执行。本次多页面替换引入已选 React Router；未引入 Query 或改变账号请求协议，具体依赖和示例边界见 [Web 界面](frontend-design.md)。站内首页/做题预览/账号往返保持 controller 生命周期，改密未知标记不会因站内导航被清除；完整刷新限制仍如上所述。

真实浏览器的[专用命令](../README.md#浏览器账号专项)只使用已有镜像、Node、Playwright 与浏览器，不自动安装/下载；构建仍在 Docker。它创建全新且位于仓库外的产物目录、自有测试 bridge/Redis/临时 PG，真实 race API 经 pinned mTLS 代理提供页面；仅将 9443/9444 映射到本机回环随机端口。外层临时证书仅在新测试浏览器 context 忽略校验，内部 mTLS 保持真实验证。合成低成本 KDF、200/hour 测试额度与词条不能充当生产配置。

夹具要求 `integration && browser` 双标签和精确测试名；普通集成 CI 不启动浏览器监听器。无认证的控制端点仅属于该隔离夹具，不得作为通用服务或对外运行。Node 断言和 Go 夹具排空分别报告：夹具正常退出不代表浏览器断言成功。驱动保留日志、JSON 结果和截图，检查节点退出/OOM/连接释放并仅清理 owner 标签匹配的资源，保留缓存与产物；失败不会悄悄换新进程重试。

本机 Chromium 桌面/390px 窄屏、Cookie、原候选恢复、密码拒绝/换代/重登、响应丢失和跳转保护已有分项证据，具体版本/次数见[交付记录](delivery-log.md)。测试中的 503、畸形响应和跳转为浏览器拦截注入；提交后未知改密先真实执行后替换回执，不以 mock 代替正常登录、数据库或 Cookie。其他浏览器、浏览器关闭重开/多标签完整竞态、生产 HTTPS/代理/存储 TLS、密钥/字典/容量及完整 AC01/23/24/25/M0 仍待验。未部署。
