## 输出与验证边界

候选目录为 0700、材料文件为 0600，包含 `source/` 原始材料与许可、`problems/<题号>/{in,out}/` 完整生成数据、`validation.json` 执行记录和 `catalog.json` 目录及来源信息。原始模板含 `@{...}` 指令，尚未转换、中文翻译或验证 Markdown/公式显示。

生成、标程、输入 validator 和原 checker 只在固定本地镜像的非特权容器执行：断网、UID 65532、只读根文件系统、无 capabilities、禁止新增权限、只读输入及驱动挂载；无 Docker socket 或宿主输出写挂载。CPU 2、内存 4 GiB（含 tmpfs）、进程 128，工作 tmpfs 3 GiB、临时 tmpfs 128 MiB；子进程 120 秒、单文件 128 MiB、整轮生成验证 3600 秒，导出 180 秒/2 GiB 数据预算。这些是题源准备工具预算，不是生产题目运行限制。

工具使用未修改的上游生成器，通过窄接口把 `toml.load(path)` 接到 Python 标准库 `tomllib`，不安装 Python 包。采用生成器 DEFAULT 模式并核对原始 `hash.json`，再显式对全部 254 点运行输入 validator 和 `checker(input, answer, answer)`；每题首个样例另用错误 token 验证返回 WA（退出 1）。不使用上游 TEST 模式的退出 0 冒充全部解答验证：该脚本对部分解答异常只记录日志。

每题另运行四个固定输入对照：合法边界、单字段超出约束（字符串题为大写字母）、截去末尾换行、合法输入后追加数据。首个必须退出 0；后三个必须由锁内 Testlib validator 以退出 3 拒绝。意外退出、信号或超时导致准备失败。自 v2 起，报告保存对照 ID、输入 SHA-256 和实际退出码，宿主按固定探针重新核对全部记录；`catalog.json` 保留探针脚本摘要。

v3 增加三个锁内上游明确标为 WA 的独立程序：A+B 和静态区间和的 `wa.cpp`，以及素性测试的 `insufficient_random_bases.cpp`。每个按原点序跳过样例，候选退出 0 后才调用原 checker；checker 退出 0 继续，退出 1 保存首个正式 WA。候选非零退出、checker 其他退出、超时或全部正式点无 WA 均使准备失败。编译沿用固定 GNU++17 参数及 120 秒限额，候选和 checker 各限 15 秒；输出只在工作 tmpfs 中临时使用，不进产物或日志。上游 TEST 模式仅记录预期判定缺失，不能用其退出码作本项证据。

上游错误解报告保存原点号、有序位置、程序、checker、输入和答案 SHA-256 及实际退出码。宿主从锁定清单核对这些字段及点的正式角色；首次命中以容器执行顺序为证据。另七题的上游错误解字段为 `null`。

v4 增加关联数组锁内低效解对照：按原顺序跳过样例，候选与正确解均使用 5 秒软 CPU 限额、6 秒硬限额和 15 秒墙钟限额。候选在超限前须正常结束且通过原 checker；首个 `SIGXCPU` 点须有接近软限额的子进程 CPU 用量，且正确解在同点、同预算内正常结束并通过 checker。墙钟超时、强制终止、用量不足、异常退出或无命中均不产生通过报告。报告绑定两份源码、输入、答案和 checker 摘要，保存 CPU 用量、信号及参考退出码；另九题的低效解字段为 `null`。这些证据只适用于固定镜像和候选，不是生产限额或所有低效解的覆盖。

v5 新增十题 [`lc-small-oracles.v1`](../scripts/library_checker_oracles.py) 的 198 个固定输入及答案，不读取上游答案。图搜索、更新历史查找、区间切片、直接后缀排序、逐字符前缀比较、试除及朴素卷积按各题定义计算；Z 算法和后缀数组各遍历长度 1–5 的全部二元字符串。每组输入通过原 validator，原标程输出只允许以空格、制表、CR、LF 分词，与独立答案严格逐 token 匹配，然后通过原 checker。三次子进程调用各有 5 秒墙钟限额，匹配前最多读取 64 KiB 输出。差异或异常会记录来源与固定用例号并阻止制备完成。报告绑定三份源码摘要、有序用例及输入/独立答案摘要；宿主重建固定证据清单。这些用例不增加到正式数据，不替代大规模区分度、人审或卷积的站内独立对拍。

新准备生成 `oj.source-validation.v6`。为没有锁内上游 WA 候选的七题增加 [`lc-formal-wrong.v1`](../scripts/library_checker_wrong_cases.py) 本地错误解，每题只引入一种确定的语义错误。固定探测序列独立于正式点原顺序，位置仍按原全集编号；不运行样例，候选与 checker 各限 15 秒。输入最多读 12 MiB，实际与参考输出各最多读 4 MiB；候选正常退出并输出同数量的非负整数 token 后才调用原 checker。checker 退出 0 记录该点未区分并继续，退出 1 保存首个拒绝及前序接受记录；无拒绝、格式错误、超时或其他退出均使制备失败。报告绑定候选 ID、正式点、输入/答案及 checker 摘要；来源目录另保留本地候选脚本摘要。至此十题各有一份错误解证据，仍不证明覆盖所有常见错误或低效解。

旧 v1–v5 仍可导入并保持原报告，不推断未执行的检查。新报告改变完整导入修订；仅来源证据改变时，内容版本不变，旧修订的站内结果不能自动迁移。

[审核准入](problem-drafts.md#批准准入状态)按完整导入修订及正式计划，采信[此次已审查的 v6 报告](delivery-log.md#2026-11-11十题正式错误解区分度)中的十题输入校验、九道非卷积题的固定独立小用例，并展示十题的单一错误解对照。卷积仍须通过本站对拍。题包自报结果不能加入受信集合；来源准备结果不证明完整数据覆盖、生产 checker 或目标节点准入。

[Z 算法](delivery-log.md#2026-11-11z-算法低效解-cpu-对照)及[其余七题](delivery-log.md#2026-11-11七题低效解-cpu-对照)使用 v6 现有正式材料完成独立低效解 CPU 对照。加上 v4 起纳入来源报告的关联数组，九道适用题各有一份证据；A+B 输入规模固定，不做复杂度区分。这八题的独立证据不增加 v6 报告字段或修改题包。每题仅覆盖一种候选和固定预算，不推断生产限额。

生成完成后将 USTAR 归档传到宿主私有临时文件，先终止并确认清理本任务容器，再由宿主按锁内材料和 `hash.json` 独立检查精确文件集合、字节哈希、类型与预算。解包拒绝越界、链接、稀疏/PAX、未知成员、重复及大小写冲突；不调用 `extractall`。Docker 的 `cp` 在本次环境看不到容器 tmpfs，故使用受限 `docker exec tar`；不通过增加宿主可写挂载解决。

源码与数据哈希属于宿主独立验证；validator/checker 执行记录依赖固定源码审阅，不是对同 UID 恶意程序的独立证明。只支持本锁内已审阅来源，不是任意上传程序执行服务。候选固定为 `private-unpublished`，不会写业务数据库或自动发布。失败、取消、导出或清理失败保留 `INCOMPLETE`；部分文件不能视为可导入完成包，重试须指定新输出目录。
