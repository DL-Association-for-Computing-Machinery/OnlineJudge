# P7 本机浮点判题

完整审核题包可通过源锁内的 `quality/decimal.json` 选择 `decimal-tokens-v1`。使用精确十进制数比较，按参考值的绝对值计算相对误差，配置两项时取 OR，边界含等号。配置和比较器版本进入版本摘要，历史重判从原清单读回。文字标签必须显式声明，坏标准答案、非法容差和与 SPJ 混用均拒绝；旧文本和 SPJ 清单保留原规则。

在本机 Ubuntu arm64 隔离 VM 上生成并发布合成题「十分之一极差（浮点）」，配置绝对容差 0.01、相对容差 0.001、忽略 ASCII 大小写。沿用预览、自动验题、真实参考 Worker、作者确认标程、非作者审核及独立发布账号：13 个正式点全部 AC，输入检查 4 个对照，独立算法 12 项，8 个覆盖条件及四类错误解均达到原审核门槛。题目发布版本 `5f3ceb0b8e3bc552aa38d6812d4752e381752d1a6baa7d59e215edd23e852043`。

Chrome 普通账号提交科学计数法和大小写变化、绝对边界、相对边界、相对越界、绝对越界、NaN、400,000 字节输出和空输出，真实训练 Worker 依次判定 **AC、AC、AC、WA、WA、WA、OLE、WA**。八笔浏览器结果和源码均由提交者读回，与数据库各一次完成的尝试逐笔相符；错误题目版本和其他账号详情读取被拒绝。浏览器报告 SHA-256 `206430ff4d14b4d97bae295977fd60314f52aa9850d67a6d5e825de0ad9d9a13`，数据库对账 `b8a00320778feb56dc97c3e7a78036f5e768307e51ad577a5c7b83a54728f259`。本轮临时 Worker、沙箱和浏览器夹具已停止。

以同一版材料再开两个终端，分别启动独立证书、独立槽的真实 Worker。两份相同源码同时持有有效租约，由不同节点各判 AC。主 Worker 收到 SIGTERM 后停止；该尝试过期且未报结果，副 Worker 在同代次接管并判 AC，本人读回。维护者用错误清单摘要重判被拒且未写审计；用原清单入队后，第二代 AC 本人可读，第一代历史与原源码逐字节不变。数据库对账 SHA-256 `4c3440167f8b472ce80fbcedadf51d3706ca73cacef887367274a04cce28e9c4`。两个槽及临时夹具均已停止。

比较器测试另覆盖仅绝对/仅相对、零容差、负值、极小与极大有限值、数值非法、敏感标签、缺失/多余 token 和坏标准答案。复测使用 [本机题包审核](../published-training-checks.md#全新同档位题的题包审核)，生成题包时加 `--decimal`，浏览器专项设 `OJ_BROWSER_DECIMAL_SPAN=1` 和题名 `十分之一极差（浮点）`。

标准答案和标程的预验证仍要求规范输出在原文本规则下一致；浮点容差用于选手判题和四类错误解拒绝。没有通用外部题包导入。本记录仅覆盖本机功能，未部署，未连接试用库。
