# 知识回写与项目文档同步

本页为[根规则](../AGENTS.md)要求按任务读取的执行细则；授权及边界继续适用，不因移出根文件而取消。项目文档维护当前行为，知识库保存可定位的验证证据，两者以链接关联。

## 自动知识回写（持续授权）

- 授权来源：用户于 2026-10-25 明确要求后续开发自动写回验证过的项目决策、踩坑和解决方案，不用每次询问。授权仅适用于本项目和上述 vault，跨会话有效，直到用户撤销或缩小范围；当前任务明确要求只读或不写回时，以该要求为准。
- 触发条件：完成一个功能、缺陷修复或阶段验证后，以及交付最终答复前，检查是否产生可复用的新知识。符合条件则把写回作为该开发任务的收尾步骤；没有实质新知识时不制造笔记、不重复记录、不更新无变化的热点。
- 准入标准：决策须已由用户确认，或属于授权实施范围且已落实并验证的工程选择，记录背景、备选方案与代价；踩坑须有实际复现或明确诊断证据；解决方案须记录验证命令、结果、适用环境及限制。用户意图的确认与技术效果的验证分开，不把建议、猜测或未运行的方案标为已验证。
- 写回内容：简明结论、原因、适用条件、证据位置、验证日期，以及适用时的仓库相对路径、提交号或未提交状态与文件哈希。必要的脱敏证据快照存入只增不改的 `.raw/`，AI 总结仍标为合成材料，不能循环佐证。
- 编译流程：先检索并按来源哈希去重 → 优先更新已有规范页 → 按需新建决策、故障经验或方案页 → 补充有依据的交叉引用 → 同步索引、热点、日志、项目进度和适用的来源/断言账本。发现证据冲突时保留双方、标注待裁决，不静默覆盖旧结论。
- 执行流程：使用适用 wiki skill 的可恢复事务，读取旧哈希、构造单个逻辑事务、inspect、简述改动路径后直接 apply，再运行 lint 和必要的证据复核。此次持续授权已满足范围内 Save/Ingest 的用户授权要求；不能因 skill 的默认逐次确认流程重复询问，但保留预检、并发冲突检查及工具权限要求。
- 授权边界：允许增量新增、更新知识与证据纠错；不包括删除原始资料、破坏性合并、批量迁移、保存秘密或整段聊天、联网研究或上传、安装插件、提交推送，以及擅自改变产品需求或根规则。超出范围时单独处理授权。
- 交付要求：最终答复简述已写回的页面与验证结果。写回失败不影响对代码验证结果的如实报告，但必须标明知识沉淀未完成及原因，不能假装成功或绕过沙箱；保留可恢复的事务草稿。此流程由实际开发任务触发，不是后台定时任务。

## 项目文档同步（持续授权）

- 授权与触发：用户于 2026-10-25 要求每次开发后同步更新项目文档。每个功能、修复、重构、配置变更或阶段交付结束后，以及最终答复前，自动检查文档影响并完成必要更新，无需逐次询问是否更新文档；此约定跨会话有效，直到用户撤销或缩小范围，当前明确只读要求优先。
- 同步范围：按实际改动更新已有 README、项目上下文、需求与验收说明、模块设计、API/数据模型、配置与运行说明、测试说明、部署与回滚手册、开发进度及变更记录。仅维护受影响部分；缺少必要文档时创建最小可用文档，不为每次改动生成整套模板。
- 记录内容：说明实际改变的行为、原因、影响范围、兼容性及适用的迁移/回滚步骤；在已有交付或进度记录中保留实际验证命令、环境、结果、已知限制和未完成项。没有提交时明确为未提交工作区状态，不虚构提交号。失败、未运行和待确认事项不得记为已完成。
- 同步顺序：检查本次差异与验收目标 → 定位受影响文档及已绑定的同步入口 → 更新规范章节和相关进度 → 清理本次变更造成的过期描述与矛盾引用 → 校验 → 汇报。优先原位更新，历史决策标明被替代的原因和新依据，避免只在末尾追加新说法而保留失效的“当前状态”。
- 证据与一致性：命令、路径、版本和接口以当前配置、锁文件、代码及实际运行结果为准；需求与验收口径以明确确认的决策为准，不能为迁就现有实现而静默降低要求。发现来源冲突时记录证据与待解决事项；代码合并、任务关闭或构建成功均不能单独证明全部验收完成。
- 外部项目文档：仅对已明确绑定到本项目且用户已授权同步的飞书/Wiki 等目标执行增量同步，无需重复询问；写前读取最新内容，保留可恢复的旧版本，写后回读核验并维护来源链接。仅浏览过的链接不自动成为同步目标，不混入其他项目文档。目标未绑定或缺少权限时先完成本地文档并保留同步草稿，明确报告未同步的目标与原因；不绕过工具审批。
- 与知识库衔接：项目文档描述当前系统及交付状态；Obsidian 按本页自动知识回写章节沉淀验证过且可复用的决策、踩坑和解决方案，以链接关联规范文档和证据，避免维护多份互相矛盾的全文。没有实质文档影响时说明“已检查，无需更新”，不刷时间戳、不重复造笔记。
- 校验与交付：检查文档差异、文件路径、链接/锚点、命令与配置一致性、状态和敏感信息；按项目已有能力运行文档检查。最终答复简述更新了哪些文档、核验结果及待同步项；代码与文档完成状态分别报告。此流程随开发任务执行，不是后台定时同步；Git 交付依据根规则第 7 节的独立持续授权，不授权修改 Issue 状态、发布或群通知。
