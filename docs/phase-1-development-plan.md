# OnlineJudge 首期开发计划

日期：2026-10-25。版本：1.1。状态：M0 实施中；0A 工程骨架已完成。持久化/租约核心与 Linux 沙箱分项已有证据，完整 M0、M1、M2 尚未通过验收，见[M0 实施记录](m0-experiment.md)。

首期目标是交付可供真实用户使用的个人训练平台。按 0B 关键技术验证、1A 训练试用、1B 完整训练推进，先完成可靠判题，再交付账号、题库、编辑提交与运行保障，最后补齐承诺的语言和检查模式。

本计划用于拆分开发任务、识别依赖和记录验收。发布范围以[精简交付基线](delivery-plan.md)为准，业务规则以[需求与验收](requirements.md)及各架构专题为准；本计划不修改原有需求。具体日历工期在试用目标、Linux 环境和 0B 实验结果明确后估算。

## 当前基础

当前工程包含 Go/Gin API、React/TypeScript/Vite 前端、独立 Worker 命令入口、健康接口契约、构建和测试命令。API 仅实现进程健康检查及基础错误响应；Worker 提示尚未接入任务和沙箱后退出。

数据库、实验提交及任务租约核心已实现并有真实 PostgreSQL 测试；GNU++17 沙箱已在独立本机 VM 完成受限编排、租约守护及真实结果回报分项验证。领取/材料客户端已通过双控制端及真实执行联合测试。材料 v2 已固定实验环境，v1 保持未验证；下一步接入 Worker 入口，账号、题库、完整 Worker 生命周期与部署待实现。组件精确版本以配置和锁文件为准，生产准入须补齐安全/许可与容量检查。验证见 [README](../README.md)、[M0 记录](m0-experiment.md)与[交付记录](delivery-log.md)，不计为完整业务 AC 通过。

## 首期范围

| 阶段 | 用户能够完成的流程 | 发布边界 |
| --- | --- | --- |
| 0B 关键技术验证 | 用实验夹具走通固定题目版本、提交持久化、认证节点执行与结果查询 | 隔离实验，不向真实训练用户开放 |
| 1A 训练试用 | 获准用户登录、浏览已审核授权题目、单文件编辑或上传、本地草稿、真实判题、结果及本人历史查询 | 默认从 GNU++17 文本题起步，具体语言和题型在 P0 冻结 |
| 1B 完整训练 | 完整日常账号流程，全部首批语言及文本、浮点、SPJ，实际需要的题目录入能力 | 完成本计划对应训练子项后，进入战队训练阶段 |

1B 语言范围为 GCC C17、GNU++17、GNU++20、Java、Python；工具链基线见[前端与沙箱设计](architecture/frontend-sandbox-options.md)，补丁、构建版本与资源参数须经实测固定。首期仅标准输入输出题，不支持部分分。

首期管理侧提供题目验证、审核发布、必要账号与节点管理、受控重判和故障处理入口。管理动作须有权限和必要审计，采用满足实际用例的最小界面或受控工具，不提前建设通用后台平台。

战队、题单任务、训练赛、正式校赛、AI 出题、外部同步、成长和名额管理属于后续阶段。多文件/ZIP 提交、自定义输入测试、服务端草稿与跨设备恢复另行排期。题目包导入与选手 ZIP 提交是不同能力：前者按真实题库来源选择，不能因后者延期而一并取消。

日常注册仍须验证邮箱后激活。邀请制或管理员发号试用尚未确认；未确认替代方案时按既有邮箱规则实施，不以缩小试用范围为由跳过验证。正式比赛的完整断外网、约 300 人容量和赛务演练保留到比赛阶段，首期仍须验证已引入功能的权限、持久化与恢复。

核心路径为 P1 → P2 → P4 → P5 → P6 → P7。P3 的会话验证可与判题实验交错推进，生产身份权限必须在题目和训练接口开放前接入。P0 的事项按使用节点解决，不要求等待正式比赛全部环境信息才能开发训练功能。

实现沿用模块化单体＋独立 Worker：身份模块拥有用户和会话，题库模块拥有版本、材料与审核，提交判题模块拥有源码、任务、尝试与结果。HTTP 层调用应用用例，数据库、文件存储和沙箱通过必要的小接口接入；跨模块不直接改写私有表。模块随功能建立，不提前创建空分层或通用事件平台。

### M0 关键技术验证通过

- P1、P2 完成，P3 的会话存储关键实验完成；取得可复现的 GNU++17 文本题提交到结果证据。
- 至少两个 API 和两个 Worker 验证跨实例幂等、竞争认领、租约、身份撤销、重复及迟到回报。会话实验验证跨 API 撤销、名额原子性与故障恢复。
- 验证材料不可读或损坏、数据库事务失败、节点失联和受限执行；失败不得伪装为成功判题或选手错误。
- 输出组件准入结论、资源测量、失败及恢复记录。实验通过不等于可以开放训练，同机多实例不证明主机高可用。

### M1 训练试用可交付

- 真实用户数据写入前完成独立备份恢复验证，开放前完成预定负载及过载恢复测试。
- 交付安装配置、迁移、启动、备份恢复、故障处理及回退说明；发布仍由用户决定。

### M2 完整训练可交付

- 完整日常邮箱注册、激活、登录、找回及会话管理可用；真实邮件投递与开发收件器测试分开记录。
- 完成首期训练验收子项并列明后续范围，不以单语言、单样例或构建成功宣布首期完成。

## 开发包与完成条件

### P0 范围与环境

| 待补信息 | 提供者 | 使用节点 |
| --- | --- | --- |
| Linux CPU、内存、磁盘、系统、网络、管理员权限、容器能力和可用时段 | 学校管理员或测试环境提供者 | P2 沙箱及容量实验前 |
| 试用人群、目标日期、语言与题型、首批题目及授权、账号入口 | 用户与出题人 | M1 范围冻结前 |
| 域名、HTTPS、SMTP 条件与目标邮箱 | 用户与管理员 | 对应账号和入口对外开放前 |
| 并发使用模型、突发提交量、接收和排队时限、错误与拒绝容忍值 | 用户提出目标，实施方验证 | 各阶段容量测试前 |
| 可接受数据丢失量 RPO、恢复时限 RTO、独立备份位置和值守人 | 用户与运维人员 | 真实用户数据写入前 |

输出环境清单、版本范围清单和有数值的测试目标。未确定项保留为阻塞条件，不将跑出的结果反过来定义为通过标准。这里只收集资源和权限条件，不将密码、私钥等秘密写入文档。

### P1 提交持久化与任务协议

依照[总体架构](architecture/system-design.md)和[接口与 Worker 协议](architecture/api-worker-design.md)，接入真实 PostgreSQL、sqlc/pgx、Goose。实现最小提交、任务、执行尝试、结果和材料版本引用模型，并先定义 OpenAPI 输入、输出、错误及幂等语义。

交付内容包括提交与任务同事务写入、原子认领、续租、有限重试、结果条件更新和接收状态查询。调度状态与判定结果分别建模；重判代次、尝试编号和恢复代次不能混用。0B 使用受控测试主体和固定材料夹具，产品开放前接入 P3/P4 的真实权限和发布流程。

完成条件：

- 同键同内容返回原提交，同键不同内容拒绝；事务失败不留下半份提交或孤立任务，未知回执能按原幂等上下文核验。
- 多 Worker 不产生冲突的有效认领；失联任务有界恢复，旧租约或旧代次不能改写有效结果；重复回报得到一致确认，不同内容重复回报显式冲突。
- 关键 SQL 有查询计划或等价验证，连接池及领取批量有预算，执行程序期间不持有数据库锁。
- 试用开放前落实跨 API 共享的用户/全局额度与训练用户公平调度，依节点能力和资源预算领取任务；密集提交不能长期挤占其他用户，已接收任务不能被覆盖或静默丢弃。
- 迁移作为独立步骤执行并持有明确锁，API 只检查模式兼容性；验证并发迁移、失败处理与回退边界。

### P2 GNU++17 文本判题

依照[判题设计](architecture/judging-design.md)和[存储设计](architecture/storage-design.md)，在专用隔离 Linux 节点验证 go-judge、固定工具链和文本检查器。建立节点身份，优先验证 mTLS；服务端对领取、续租、材料下载和回报逐次授权。

Worker 只取得当前任务所需材料，不持有数据库或邮件凭据。材料按固定版本和哈希校验，缓存损坏后可重建，选手程序不能访问标准答案、节点凭据或整个缓存。源码、题目、语言与检查器环境随提交或尝试固定。

完成条件：

- 覆盖 AC/WA/CE/RE/TLE/MLE/OLE/SE，未知或冲突证据归 SE；不能按错误文本猜测结果，也不能把程序正常退出当作 AC。
- 文本比较覆盖 token、空白、默认 ASCII 大小写不敏感及按题显式敏感规则；多余或缺少 token 按规则拒绝。
- 每次尝试编译一次，固定顺序逐点使用新隔离环境；首个选手失败立即停止，其余点标未执行；系统故障有限恢复。
- 编译、运行、检查、输出、进程、内存及临时磁盘均有预算；验证越界访问和网络限制，不在业务进程或普通开发宿主直接执行选手程序。
- 注入节点退出、租约到期、撤销身份、材料缺失/损坏和回报确认丢失，检查结果有效性、进程终止及资源释放。

### P3 账号与权限

按[会话与账号设计](architecture/session-design.md)实现 Argon2id、登录退出、期限、名额、凭证轮换、撤权、角色及资源权限、Cookie/CSRF。Redis 仍为既有基线，PostgreSQL 会话只作对比验证；不在实施中静默替换，也不同时维护两份权威会话。

M0 先做存储与并发实验；M1 交付冻结范围所需的完整普通账号规则；M2 补齐全部日常账号流程。若启用邮箱注册/找回，则同时交付令牌、限流、防枚举、可靠邮件任务和敏感载荷保护，不能将依赖的安全规则后移。

完成条件：

- 两个 API 下验证登录、退出、过期、会话名额、改密/重置、封禁和撤权竞态；轮询不无限保活，故障和旧备份恢复不能使已撤销会话复活。
- 未验证账号不能提交，普通用户不能调用管理接口，主体认证成功不自动取得题目、源码或节点资源权限。
- 邮箱功能按既定有效期、重发间隔、有效链接数量及重试窗口验证；并发消费最多一次成功，找回申请本身不改变密码和会话。
- 密码、完整验证记录和令牌不入日志；邮件任务仅引用业务 ID，判题 Worker 不承担邮件投递。开发收件器、真实 SMTP 投递分别验收。

### P4 题库与发布

按[题目包设计](architecture/problem-package-design.md)实现内部题目模型、不可变版本、材料清单、来源与使用依据、验证报告、审核和发布。首批实际来源决定先做手动录入或受支持题包子集之一，不将两个入口同时作为试用前置。

提供试用需要的题目列表、明确检索、详情及受控附件访问。题面预览与选手页面共用 Markdown/公式配置；API 不执行参考程序、生成器或检查器，相关验证在受限环境运行。

完成条件：

- 失败或未知验证、缺少材料、无法忠实表达的判定语义阻止发布；非作者终审及已有紧急授权边界不因首期而取消。
- 材料完整写入并校验后才发布数据库引用；并发、中断、空间不足不暴露半文件或无效版本；改题创建新版本，不覆盖历史引用。
- 直接请求、列表计数、筛选项、图片及材料下载均不能泄漏私有题目、标准答案、参考程序或未发布题解。
- 如选择题包导入，交付实际支持矩阵、差异报告与安全解析测试；导入成功只生成草稿，不自动发布。

### P5 训练前端闭环

按[前端设计](architecture/frontend-sandbox-options.md)按需接入路由、查询缓存、CodeMirror、idb、Markdown/KaTeX 和 UI 组件。页面包括账号入口、题目列表/详情、编辑提交、结果详情及本人历史，管理页面随 P3/P4 的实际操作引入。

完成条件：

- 单文件编辑/上传明确处理大小、类型和覆盖未保存内容；草稿按账号、题目、比赛上下文及语言隔离，事务成功后才显示已保存。
- 覆盖刷新恢复、容量不足、升级受阻、多标签冲突、退出清理及迟到保存；自然过期后同账号恢复，不承诺跨设备保存。
- 提交超时沿用原幂等键核验；写操作不盲目重试。排队与执行结果明确区分，终态停止对应轮询。
- 切换账号清理私有查询缓存并隔离迟到响应；客户端缓存不能替代服务端授权。
- 真实浏览器验证加载、空数据、失败、成功、键盘操作、焦点及窄屏；样例复制保留原文，题面禁原始 HTML，公式错误局部显示。

### P6 试用运行与验收

依照[运维设计](architecture/operations-design.md)落实同源入口、HTTPS、健康与就绪状态、结构化日志、节点状态、队列积压和系统错误可见性。资源限额与日志从 P1/P2 开始建设，完整发布验收在 P3—P5 后执行。完整监控套件按值守目标接入，不作为第一条判题路径的前置。

完成条件：

- 在预先确定的资源及负载模型下记录接收/拒绝/超时、时延分位数、最长排队、资源峰值和恢复时间；过载在接收事务提交前拒绝，不丢弃已接收提交。
- 从独立故障域的备份恢复数据库与匹配材料，核验引用和哈希，恢复历史源码并重新判题；旧会话、令牌和租约按恢复规则失效。
- 验证发布排空、独立迁移、健康检查和兼容回退；不能恢复旧数据库覆盖新提交来冒充普通回滚。
- 核心记录保留期未定前不自动销毁；缓存/临时文件清理有容量及占用保护，不能误删历史、在途或备份引用。
- 训练试用可按实测使用单 API，跨实例协议实验仍须完成；部署、备份和故障说明中写明实际拓扑及限制。

### P7 完整训练补齐

在 M1 闭环上逐项接入 C17、GNU++20、Java、Python，保留 GNU++17 回归；再补齐浮点和 SPJ。每项都固定工具链、检查器及配置版本，覆盖正确、错误、超限、系统故障、历史重判和多节点一致性。

- 浮点验证逐题绝对/相对容差及 OR、等于边界、零与负数、科学计数法、非法/非有限值、混合文本；非法标准答案或配置阻止发布。
- SPJ 按既定 ICPC 协议及 testlib 验证路线区分原始结果与适配结果；检查器崩溃、超时、非法协议归 SE，诊断按权限提供。
- 补齐完整日常邮箱账号流程及真实投递验证；按真实题库需求增加录入入口，不为填满功能表实现无人使用的管理能力。
- 回归 M1 的权限、幂等、恢复和浏览器流程；单项失败保留为未通过，不降低需求来完成里程碑。

## 首个实施批次

下一批次限定为 M0 的 GNU++17 文本判题实验，按以下顺序拆分为可独立审查的任务：

1. 核验测试数据库与隔离 Linux 环境，固定实验资源及组件准入清单。
2. 定义最小 OpenAPI、数据模型、迁移、材料清单及测试夹具。
3. 实现提交/任务同事务与幂等核验，运行真实数据库集成测试。
4. 按单功能 PR 拆分：mTLS 认证认领/续租/合成回报、材料授权/哈希、固定环境、受限编排、租约守护与中止确认已验证；本次完成真实结果摘要及 mTLS 回报。下一项贯通领取/材料客户端，再接 Worker 入口。证据及未覆盖项见 [M0 记录](m0-experiment.md)。
5. 用真实请求及最小结果页面贯通提交到结果，标明实验范围。
6. 注入重复、回执不明、失联、迟到、撤销与材料异常，完成双 API/双 Worker 验证；完成会话关键实验。
7. 整理 M0 报告，评估组件准入、预算及未解决问题，再细化 M1 工期。

Linux 条件未满足时可先完成契约、纯规则与数据库工作，但不得将模拟执行记为真实判题。0B 验证失败时依据证据修正实现或评估既定备选，不绕过隔离、权限或验收要求。
