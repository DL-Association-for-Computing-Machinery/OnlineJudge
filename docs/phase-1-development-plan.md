# OnlineJudge 开发与交付计划

本页统一维护发布范围、组件引入时机、开发包和里程碑，合并原交付基线。当前实施状态与证据统一见 [M0 记录](m0-experiment.md)，历史交付见[交付日志](delivery-log.md)；文档修订以 Git 历史为准。

首期目标是交付可供真实用户使用的个人训练平台。按 0B 关键技术验证、1A 训练试用、1B 完整训练推进，先完成可靠判题，再交付账号、题库、编辑提交与运行保障，最后补齐承诺的语言和检查模式。

本计划用于拆分开发任务、识别依赖和记录验收。发布范围以下文阶段表为准，业务规则以[需求与验收](requirements.md)及各架构专题为准；本计划不修改原有需求。具体日历工期在试用目标、Linux 环境和 0B 实验结果明确后估算。

本机（含本机隔离 VM）就是开发阶段的功能验收环境。按[本机功能验收](development-workflow.md#本机功能验收)跑通阶段范围内的实际流程即可完成开发验收；验证多 Worker 时在本机多开终端，分别启动真实 Worker 进程模拟多个节点，沿用既有判题隔离流程。试用服务器部署、实际容量和试用开放按上线计划单独验收。

| Tailwind / shadcn/ui、Router、Query | 保留方向，当前无多页面、复杂组件或查询缓存需求，按需引入 | 第一条相应产品功能，不同时引入第二套同职责方案 |
| CodeMirror、idb、Markdown / KaTeX | 随题目、编辑和草稿功能引入 | 用户界面及异常路径验收，不自研通用编辑器或解析器 |
| River / SMTP | 可靠邮件功能时引入，不自研通用队列代替成熟库 | 实际邮件流程、事务与投递验证；不赋予判题 Worker 邮件凭据 |
| Outbox | 保留可靠事件原则，随首个异步消费者落地 | 普通同步调用不强制事件化；训练结果查询先直接读取权威结果 |
| Prometheus / Grafana / Alertmanager | 分阶段引入，不要求完整套件先于首条判题路径 | 先有结构化日志、健康、积压/错误可见性，再按值守和告警目标接入 |
| pgBackRest / restic | 保留后续优先验证方向，不无条件作为骨架前置 | 先确定 RPO/RTO、独立介质和实际恢复验证；小规模试用可比较逻辑备份＋材料清单，不承诺 PITR |
| Resolver / 离线查重 | 比赛阶段先做受控导出、外部运行与结果留痕 | 工具许可、格式、语法及真实赛务演练；不先重做完整工具界面 |

不引入微服务、Kubernetes、消息代理、独立搜索服务、第二套 ORM、第二套会话实现或对象存储实现。未来新增须有当期功能或实测瓶颈依据。测试工具属于开发工具，不按常驻服务计数。

## 发布阶段与边界

| 阶段 | 交付目标 | 不代表什么 |
| --- | --- | --- |
| 0A：工程骨架（历史起点） | 启动 API、前端连通、Worker 入口、契约、构建和自动检查 | 无真实判题、登录、数据库或生产部署 |
| 0B：关键技术验证 | GNU++17 文本题，提交/任务同事务、认证节点认领、受限执行、有效租约回报；验证重复、失联、迟到和材料异常 | 不是可公开使用的训练产品 |
| 1A：训练试用 | 获准用户登录、已审核授权题目、单文件编辑/上传与本地草稿、真实判题、结果和本人历史；关键权限、恢复及基本运维 | 不宣称完整语言/题型、战队或校赛支持 |
| 1B：完整训练 | 补齐 GCC C17/GNU++17/GNU++20、Java、Python 及文本/浮点/SPJ（必须支持 Testlib），完整日常账号流程；实际需要的录入入口 | 不把尚未实现的 ZIP、多文件或正式赛事能力报告为完成 |
| 2：战队训练 | 战队邀请、题单/任务、训练赛与历史访问；其计分/参赛权限等依赖随训练赛交付 | 不等待阶段 3 才实现训练赛实际需要的比赛核心 |
| 3：正式比赛 | 报名、专用账号、计分封榜、答疑气球、查重、重测审核、滚榜；断外网、容量、故障恢复与一次完整比赛演练 | 同机多副本不等于主机高可用 |
| 4：辅助能力 | AI 出题、外部数据同步、成长画像、名额管理 | 不与训练闭环和首次完整比赛演练争抢开发优先级 |

2026-11-13 用户确认 1A 按约 100 人同时在线、GNU++17 和已获授权且通过审核的 Library Checker 文本题推进。[试用验收默认值](#试用容量和恢复默认值)供现场验收；具体试用人群、日期、题目版本、授权与终审记录仍须核定。1B 的完整语言承诺保持。首期多文件/ZIP 提交与至少 10 文件目标移出 1A/1B 必需范围，保留后续扩展需求，在首个实际需要它们的版本单独排期；内部文件集模型可保留，不提前做完整文件管理界面。

日常个人账号仅邮箱登录、昵称可重复，整个邮箱忽略大小写匹配、保留原始显示且不合并点号/加号别名（2026-10-31 用户确认）。2026-11-13 用户确认 1A 采用公开邮箱注册、验证与找回，真实邮件投递须单独验收；未验证邮箱不得提交训练。内部映射支持范围见[会话设计](architecture/session-design.md#77-个人邮箱映射与原子初始化)。比赛会话及换机管理随比赛场景接入；已经交付的普通账号规则必须完整满足本版约定。

2026-11-03 用户确认首批采用 Library Checker，官方 ICPC 赛事包扩充，爬虫补充；先完成[十题离线私有候选准备](problem-sources.md)，再接 P4 来源适配和统一草稿流程。手动录入不同时成为试用前置。版本不可变、来源、审核、受限验证和私有材料保护不延期。试用版不包含自定义输入调试服务；自测随后续训练增强单独验收。

首期仅标准输入输出题，不支持部分分；语言工具链及资源参数须经实测固定。服务端草稿与跨设备恢复另行排期。题目包导入与选手 ZIP 提交是不同能力，不能因后者延期而取消前者。

首期管理侧提供题目验证、审核发布、必要账号与节点管理、受控重判和故障处理入口。管理动作须有权限和必要审计，采用满足实际用例的最小界面或受控工具，不提前建设通用后台平台。

## 分阶段验收归属

保留 AC01—35 及细化条款，不删除原验收。每个版本将跨阶段 AC 拆为可执行子项：标记本版必需、后续、待验证；不得将部分通过记作整个 AC 通过。发布范围变更须同步此矩阵及对应专题。

| 发布范围 | 对应验收及拆分原则 |
| --- | --- |
| 0A | 构建、HTTP 契约/错误、前端真实连接和失败状态、Worker 诚实标识；均为骨架检查，不记 AC01—35 通过 |
| 0B / 1A | AC06/17/20/21/22/23/24/28/29/30 中已引入的题目版本、授权、持久化、单文件、会话、任务和恢复子项；邮箱账号上线时必验 AC01/25 对应部分；文本相关 AC05 与判题细化条款 |
| 1B / 训练增强 | 补齐全部首批语言、浮点/SPJ、日常账号与题库相关 AC；选择标准导入时执行题包兼容验收；多文件、ZIP、自测启用前分别完成 AC30 对应部分 |
| 2 | AC02/03/04/07/13/33/34 及训练赛所需计分、可见性和重测子项；成长奖励暂未引入，不能因此伪造奖励验收 |
| 3 | AC06—13/16/18/19/20/26/27/29/31/32 的正式比赛与运维部分，比赛账号/封榜/赛后权限等跨条款子项 |
| 4 | AC05 的 AI 辅助部分、AC14/15/35 与成长、外部来源、名额部分；之前已完成的核心验证继续回归 |

多 API / 多 Worker 协议从关键实验验证；日常试用可按实测部署单 API，不宣称已提供高可用。已引入功能的安全、数据一致性、故障恢复与必要测试不能以后续阶段为由跳过。

核心路径为 P1 → P2 → P4 → P5 → P6 → P7。P3 的会话验证可与判题实验交错推进，生产身份权限必须在题目和训练接口开放前接入。P0 的事项按使用节点解决，不要求等待正式比赛全部环境信息才能开发训练功能。

实现沿用模块化单体＋独立 Worker：身份模块拥有用户和会话，题库模块拥有版本、材料与审核，提交判题模块拥有源码、任务、尝试与结果。HTTP 层调用应用用例，数据库、文件存储和沙箱通过必要的小接口接入；跨模块不直接改写私有表。模块随功能建立，不提前创建空分层或通用事件平台。

### M0 关键技术验证通过

2026-11-03技术核对：下列条件在固定合成环境内逐项满足，范围与来源归[限定验收记录](m0-acceptance.md)。这不代表全部P1/P2、用户产品验收、试用开放或部署；试用前额度/公平调度及各后续节点继续保留。

- P1、P2 完成，P3 的会话存储关键实验完成；取得可复现的 GNU++17 文本题提交到结果证据。
- 至少两个 API 和两个 Worker 验证跨实例幂等、竞争认领、租约、身份撤销、重复及迟到回报。会话实验验证跨 API 撤销、名额原子性与故障恢复。
- 验证材料不可读或损坏、数据库事务失败、节点失联和受限执行；失败不得伪装为成功判题或选手错误。
- 输出组件准入结论、资源测量、失败及恢复记录。实验通过不等于可以开放训练，同机多实例不证明主机高可用。

### M1 训练试用可交付

- 冻结的 1A 范围及 P3—P6 对应子项通过；首批题目完成来源授权、验证和审核。
- 从浏览器完成登录、看题、编辑或上传、草稿恢复、提交、查看结果及历史；桌面和窄屏覆盖成功、加载、空数据和失败状态。
- 真实用户数据写入前完成独立备份恢复验证，开放前完成预定负载及过载恢复测试。
- 交付安装配置、迁移、启动、备份恢复、故障处理及回退说明；发布仍由用户决定。

### M2 完整训练可交付

- P7 全部完成，每种承诺语言和检查模式单独留存验收证据，M1 核心流程继续通过。
- 完整日常邮箱注册、激活、登录、找回及会话管理可用；真实邮件投递与开发收件器测试分开记录。
- 完成首期训练验收子项并列明后续范围，不以单语言、单样例或构建成功宣布首期完成。

### P1 提交持久化与任务协议

已验证子项：[跨 API 共享积压准入](submission-backlog.md)按主体跨训练上下文统计 queued＋running，超额仅拒绝新增，同键保留原回执；[训练虚拟时间](submission-backlog.md#训练虚拟时间)采用 DOMjudge 的思路，在固定材料 Store 内按版本和主体分配领取顺位。生产限额、提交频率、真实身份、比赛/团队策略和试用混合负载验收仍待完成，不据此标记整个 P1 或试用准入通过。

依照[总体架构](architecture/system-design.md)和[接口与 Worker 协议](architecture/api-worker-design.md)，接入真实 PostgreSQL、sqlc/pgx、Goose。实现最小提交、任务、执行尝试、结果和材料版本引用模型，并先定义 OpenAPI 输入、输出、错误及幂等语义。

交付内容包括提交与任务同事务写入、原子认领、续租、有限重试、结果条件更新和接收状态查询。调度状态与判定结果分别建模；重判代次、尝试编号和恢复代次不能混用。0B 使用受控测试主体和固定材料夹具，产品开放前接入 P3/P4 的真实权限和发布流程。

完成条件：

- 同键同内容返回原提交，同键不同内容拒绝；事务失败不留下半份提交或孤立任务，未知回执能按原幂等上下文核验。
- 多 Worker 不产生冲突的有效认领；失联任务有界恢复，旧租约或旧代次不能改写有效结果；重复回报得到一致确认，不同内容重复回报显式冲突。
- 关键 SQL 有查询计划或等价验证，连接池及领取批量有预算，执行程序期间不持有数据库锁。
- 试用开放前落实跨 API 共享的用户/全局额度与训练用户公平调度，依节点能力和资源预算领取任务；密集提交不能长期挤占其他用户，已接收任务不能被覆盖或静默丢弃。
- 迁移作为独立步骤执行并持有明确锁，API 只检查模式兼容性；验证并发迁移、失败处理与回退边界。

### P2 GNU++17 文本判题

Worker 实施状态、故障证据与执行端恢复缺口统一见 [M0 记录](m0-experiment.md)。以下完成条件是验收要求，不代表已经全部实现。

依照[判题设计](architecture/judging-design.md)和[存储设计](architecture/storage-design.md)，在专用隔离 Linux 节点验证 go-judge、固定工具链和文本检查器。建立节点身份，优先验证 mTLS；服务端对领取、续租、材料下载和回报逐次授权。

Worker 只取得当前任务所需材料，不持有数据库或邮件凭据。材料按固定版本和哈希校验，缓存损坏后可重建，选手程序不能访问标准答案、节点凭据或整个缓存。源码、题目、语言与检查器环境随提交或尝试固定。

完成条件：

- 覆盖 AC/WA/CE/RE/TLE/MLE/OLE/SE，未知或冲突证据归 SE；不能按错误文本猜测结果，也不能把程序正常退出当作 AC。
- 文本比较覆盖 token、空白、默认 ASCII 大小写不敏感及按题显式敏感规则；多余或缺少 token 按规则拒绝。
- 每次尝试编译一次，固定顺序逐点使用新隔离环境；首个选手失败立即停止，其余点标未执行；系统故障有限恢复。
- 编译、运行、检查、输出、进程、内存及临时磁盘均有预算；验证越界访问和网络限制，不在业务进程或普通开发宿主直接执行选手程序。
- 注入节点退出、租约到期、撤销身份、材料缺失/损坏和回报确认丢失，检查结果有效性、进程终止及资源释放。

### P3 账号与权限

按[会话与账号设计](architecture/session-design.md)实现 Argon2id、登录退出、期限、名额、凭证轮换、撤权、角色及资源权限、Cookie/CSRF。Redis 仍为既有基线，PostgreSQL 会话只作对比验证；不在实施中静默替换，也不同时维护两份权威会话。

M0 先做存储与并发实验；M1 交付公开邮箱注册、验证和找回所需的普通账号规则，同时交付令牌、限流、防枚举、可靠邮件任务和敏感载荷保护，不能将依赖的安全规则后移。M2 补齐其余日常账号流程。

会话已验证子项、环境及剩余恢复缺口统一见[会话实验 README](../tests/sessionexperiment/README.md)；正式账号产品仍须满足以下完成条件。

[训练账号资格](architecture/session-design.md#125-训练账号资格)已在真实 PostgreSQL 验证：邮箱激活后旧代次失效，当前验证账号才可通过；停用和恢复切换与业务事务协调。本人历史、状态、详情及训练提交存储入口均复用此门禁；面向已发布题目的训练提交接口仍须核对材料权限和联验。

完成条件：

- 两个 API 下验证登录、退出、过期、会话名额、改密/重置、封禁和撤权竞态；轮询不无限保活，故障和旧备份恢复不能使已撤销会话复活。
- 未验证账号不能提交，普通用户不能调用管理接口，主体认证成功不自动取得题目、源码或节点资源权限。
- 邮箱功能按既定有效期、重发间隔、有效链接数量及重试窗口验证；并发消费最多一次成功，找回申请本身不改变密码和会话。
- 密码、完整验证记录和令牌不入日志；邮件任务仅引用业务 ID，判题 Worker 不承担邮件投递。开发收件器、真实 SMTP 投递分别验收。

[普通终审契约](architecture/problem-package-design.md#41-普通终审的交付边界)拆分为版本绑定的送审与授权证据读取、批准／退回和独立发布。已实现[作者送审回执](problem-drafts.md#作者送审回执)、[审核人分配与证据摘要](problem-drafts.md#审核人分配与证据摘要)、[固定材料读取](problem-drafts.md#审核材料读取)、[退回／变更材料后重送](problem-drafts.md#审核退回与重送)、[首个对拍差异和固定修订的读取](problem-drafts.md#审核对拍详情)、[只读批准阻断](problem-drafts.md#批准准入状态)及[作者确认冻结标程](problem-drafts.md#作者确认标程)。准入已采信十题 v6 的输入校验和九道非卷积题的独立小用例，卷积仍须通过本站对拍。指定审核人可读十题的单一错误解对照，覆盖门禁保持。审核还可读取十题相同内容版本的历史渲染证据，已接入当前分配下的[非作者题面语义确认](problem-drafts.md#审核人确认题面语义)，仅与可信渲染同时满足时解除题面质量阻断。

准入读取、批准、同材料退回与题意确认共用材料锁。批准入口默认关闭；启用且[准入快照](problem-drafts.md#批准准入状态)通过后，页面可提交决定并按原键回读。生产检查器和目标节点的真实证据继续阻断新批准；实际非作者终审及独立发布仍待完成。

审核材料页可提交[退回决定和查询原回执](problem-drafts.md#审核退回与重送)。作者可在草稿的本机送审记录中查看对应理由，并按现有材料约束变更后重送。

作者也可在同一记录中[查看并确认冻结标程](problem-drafts.md#作者确认标程)。确认结果未知时按原送审键查询，不会重新提交；该步骤不替代非作者终审。

[本人审核分配](problem-drafts.md#本人审核分配的存储与回退)允许审核人用真实会话发现并选择当前分配的审核项，打开材料仍逐项授权。历史分配、其他审核人和作者本人的送审不进入结果；该能力不授予终审或发布权限。

[输入覆盖盘点](problem-sources.md#输入覆盖盘点)分别记录原 v6 十题和单题修订的规模、值域及结构见证。[Z 算法](problem-sources.md#z-算法规模边界修订)的 31 点计划纳入两端长度，[A+B](problem-sources.md#ab-值域边界修订)的 17 点计划纳入五个值域边界，[并查集](problem-sources.md#并查集最小规模修订)的 20 点计划纳入最小规模的查询与合并，[关联数组](problem-sources.md#关联数组规模与键值上界修订)的 22 点计划纳入最小操作数和键值上界。原 v6 计划和历史证据保持原绑定。[只读准入](problem-drafts.md#批准准入状态)已为精确绑定的 A+B 17 点修订采信覆盖、错解区分、输入校验、独立小用例及预览等价的历史渲染。覆盖须当前正式 AC 且材料未退回；题面质量仍须当前非作者语义确认。下一步推进生产检查器、目标环境与其余题目的覆盖；批准写入与独立发布仍待实现。

[并查集 20 点修订](problem-sources.md#并查集最小规模修订)的精确审核绑定已采信输入校验、独立图遍历小用例、十项非样例覆盖及等价题面的历史渲染。覆盖包含四种错解区分和本机低效解对照；题面仍须当前非作者确认，生产检查器和目标环境仍待准入。

[静态区间最小值](problem-sources.md#静态区间最小值单次查询与初值上界修订)的 28 点计划纳入一次查询两个初值上界的非样例，并检查半开区间两侧的较小值不影响答案。

[静态区间和](problem-sources.md#静态区间和最小规模与初值边界修订)的 13 点计划纳入最小规模及初值的两个端点，并为整段查询提供非样例见证。

[后缀数组](problem-sources.md#后缀数组重复半段与交替串修订)的 52 点计划分别纳入相同的非恒定半段和两半不同的严格交替串。

[单点加与区间求和](problem-sources.md#单点加与区间求和初值和增量边界修订)的 23 点计划纳入单次查询、初值和增量的两个端点，并覆盖累加到 3×10⁹ 的结果。

[素性测试](problem-sources.md#素性测试单次查询与上界修订)的 15 点计划纳入素数与上界合数的单次查询，为上界提供非样例见证。

[卷积](problem-sources.md#卷积左右系数上界修订)的 55 点计划分别纳入左、右向量系数上界的非样例，并保留原独立对拍语料。

[Z 算法交替串修订](problem-sources.md#z-算法交替串修订)在原 31 点之外追加一个非样例，六项输入观察均有非样例见证。同一冻结计划的输入校验、独立小用例、覆盖和等价题面的历史渲染证据已接入审核预检。其他修订保持各自绑定；当前非作者题意确认、标程确认、生产检查器、目标环境和终审仍有各自的门禁。

[A+B 固定材料隔离判题阶段](checker-admission.md#ab-固定材料隔离判题)按候选和正式计划生成有序清单；受控入口对同一清单的正确、错误及超长 token 合成提交分别得到 AC、WA、OLE。生产 Worker 与发布、目标节点准入及真实非作者终审仍待交付。

[Ubuntu 独立判题实验](checker-admission.md#ubuntu-独立判题实验)在本地专用客体复核同一 17 点材料，使用独立档位、清单和恢复入口。真实 AC、WA、OLE 和停止回执已验证；目标节点和生产准入仍待交付。

[A+B 归档报告复核](checker-admission.md#ab-归档报告复核)重新核对三份固定本机报告，并在精确匹配时向指定审核人返回摘要；不会解除生产或目标环境门禁。

[目标节点交接](checker-admission.md#ab-目标节点交接)已在本地验证 Desktop 和专用 Ubuntu 两个独立档位，核对固定材料及返回报告。维护者仍须独立确认实际节点身份、候选制品和现场运行；其他档位需要新的执行适配。

[交接报告回执](checker-admission.md#封存与复核报告回执)用于在报告核验方与后续复核方之间传递固定修订和报告摘要。回读须独立提供回执摘要、交接摘要及预期目标；生产检查器、目标节点及普通终审继续分别验收。

[A+B 现场准入记录复核](checker-admission.md#生产检查器与目标节点记录复核)可离线核对独立取得的目标运行、生产检查器和交接回执是否匹配同一修订与 Worker 制品。只输出人工复核所需的绑定，仍须由负责人员核对实际节点、构建和生产行为；不产生终审或发布。

[发布材料准备](architecture/problem-package-design.md#42-发布材料准备)从冻结修订封存确定的题面、样例和静态图片制品，并验证有序私有材料的完整性。不同导入修订不复用版本；材料缺损、错配或不支持的静态图片不会产生可用引用。独立发布事务及公开题目读取仍待交付。

同一准备能力可从可信引用重新核对展示对象的原始字节、版本和完整正式计划。缺损或绑定变化必须重新核对；该内部读回不打开公开题目或生产判题。

[Worker 材料绑定协议](architecture/api-worker-design.md#4-调度与过载)让领取、材料下载和执行共用任务固定的版本与清单摘要；未授权版本或错配不执行。后续须接入受信任的 A+B 执行版本及运行档位，验证目标节点、正式任务链路与历史版本可重判。

[A+B 租约链路联验](checker-admission.md#ab-租约链路联验)在临时 PostgreSQL 和固定断网参考槽接通材料登记、领取、逐次授权下载、执行与结果回报。运行配置及材料均显式固定；生产部署、正式身份提交、目标节点和实际终审仍待验收。

[本地 Ubuntu 租约联验](delivery-evidence/aplusb-leased-judging.md#ubuntu-arm64-专用客体)复用固定 17 点材料，核对版本与完整清单后才领取，三组真实结果和原槽停止已验证。

[A+B 历史重判联验](delivery-evidence/aplusb-restored-rejudge.md)验证固定 17 点提交随备份转运和恢复，同一提交以原材料清单进入第二个判题代次，第一次结果仍可读。[受控重判](rejudge.md)为已完成的个人训练提交提供受信维护命令和审计回执。现场独立故障域、比赛重判及榜单联动仍待验收。

[本地 Ubuntu 历史重判](delivery-evidence/aplusb-restored-rejudge.md#ubuntu-arm64-专用客体)通过同样的封存、接收和恢复检查；错档位和错清单不改变状态，同一提交保留第一次 AC 并生成第二次 AC。

完成条件：

- 失败或未知验证、缺少材料、无法忠实表达的判定语义阻止发布；非作者终审及已有紧急授权边界不因首期而取消。
- 材料完整写入并校验后才发布数据库引用；并发、中断、空间不足不暴露半文件或无效版本；改题创建新版本，不覆盖历史引用。
- 直接请求、列表计数、筛选项、图片及材料下载均不能泄漏私有题目、标准答案、参考程序或未发布题解。
- 如选择题包导入，交付实际支持矩阵、差异报告与安全解析测试；导入成功只生成草稿，不自动发布。

### P5 训练前端闭环

按[前端设计](architecture/frontend-sandbox-options.md)按需接入路由、查询缓存、CodeMirror、idb、Markdown/KaTeX 和 UI 组件。页面包括账号入口、题目列表/详情、编辑提交、结果详情及本人历史，管理页面随 P3/P4 的实际操作引入。

`/submissions` 接通可选的[本人训练历史和详情](../api/training-history.openapi.yaml)。展开进行中记录后更新状态，终态、收起、离开页面、隐藏或会话变化时停止。A+B 的本机提交和判题见[联验证据](delivery-evidence/p5-published-training.md)。

[个人训练提交事务](submission-backlog.md#个人训练提交事务)在存储边界复核账号、入队并保留原键。入口默认关闭，仅显式开启时接收当前本机已准入、已发布的精确版本。并查集及从未预登记的数列极差已验证固定 GNU++17 文本档位。新来源由题包和自动验题提供证据，保留既有 P4 人工确认与发布权限。多题混合队列与其他执行档位不在本次范围。单文件可载入编辑区，刷新后可在同标签页查询原回执。

[浏览器本地代码草稿](frontend-design.md#浏览器本地代码草稿)覆盖登录后的预览及本机已发布题的个人训练，两者使用独立上下文。已发布题的草稿绑定发布版本；刷新恢复、多标签冲突和账号隔离见[联验证据](delivery-evidence/p5-published-training.md)。比赛上下文未开放。

完成条件：

- 单文件编辑/上传明确处理大小、类型和覆盖未保存内容；草稿按账号、题目、比赛上下文及语言隔离，事务成功后才显示已保存。
- 覆盖刷新恢复、容量不足、升级受阻、多标签冲突、退出清理及迟到保存；自然过期后同账号恢复，不承诺跨设备保存。
- 提交超时沿用原幂等键核验；写操作不盲目重试。排队与执行结果明确区分，终态停止对应轮询。
- 切换账号清理私有查询缓存并隔离迟到响应；客户端缓存不能替代服务端授权。
- 真实浏览器验证加载、空数据、失败、成功、键盘操作、焦点及窄屏；样例复制保留原文，题面禁原始 HTML，公式错误局部显示。

### P6 试用运行与验收

依照[运维设计](architecture/operations-design.md)落实同源入口、HTTPS、健康与就绪状态、结构化日志、节点状态、队列积压和系统错误可见性。资源限额与日志从 P1/P2 开始建设，完整发布验收在 P3—P5 后执行。完整监控套件按值守目标接入，不作为第一条判题路径的前置。

维护者可读取[判题运维快照](architecture/operations-design.md#判题运维快照)，用于区分积压、失效租约以及近期收件中出现的系统错误。节点在线状态、高频监控、告警与现场负载仍待验收。

普通会话 API 的[就绪检查](architecture/operations-design.md#会话-api-就绪检查)反映数据库 schema、恢复开关和 Redis 可用性；与进程存活检查分开。正式判题、邮件及现场探针的验收独立。

试用上线验收条件（本机开发证据与现场检查分列于 [P6 清单](delivery-evidence/p6-trial-acceptance.md)）：

- 在预先确定的资源及负载模型下记录接收/拒绝/超时、时延分位数、最长排队、资源峰值和恢复时间；过载在接收事务提交前拒绝，不丢弃已接收提交。
- 从独立故障域的备份恢复数据库与匹配材料，核验引用和哈希，恢复历史源码并重新判题；旧会话、令牌和租约按恢复规则失效。
- 验证发布排空、独立迁移、健康检查和兼容回退；不能恢复旧数据库覆盖新提交来冒充普通回滚。
- 核心记录保留期未定前不自动销毁；缓存/临时文件清理有容量及占用保护，不能误删历史、在途或备份引用。
- 训练试用可按实测使用单 API，跨实例协议实验仍须完成；部署、备份和故障说明中写明实际拓扑及限制。

[捕获逻辑备份](architecture/storage-design.md#捕获逻辑备份)用同一快照封存数据库归档和材料，实测排除快照后的写入；[接收核验](architecture/storage-design.md#核验收到的逻辑备份)在还原前确认转运后的归档和材料与受信清单一致。[数据库与材料恢复回归](architecture/storage-design.md#7-备份与验收)覆盖固定合成夹具的历史源码、终态、排队任务和材料读回；本地离线专项已串联封存、接收核验、源库停止与还原，并由真实 Worker 重判同一提交。[恢复材料核验](architecture/storage-design.md#恢复材料核验)检查判题、草稿和冻结计划引用及哈希。[恢复提交租约](architecture/operations-design.md#恢复提交租约)验证真实归档恢复后旧在途租约失效及原任务重新领取；[恢复普通会话](architecture/operations-design.md#恢复普通会话)以维护命令重建 Redis 限流空间，并用真实双 API 验证拒旧、保留补回的封禁及新登录。[参考验证恢复回归](architecture/operations-design.md#回档后的旧参考验证授权)验证旧预留失效、原作者新会话取消并重新申请；[积压维护](architecture/operations-design.md#恢复参考验证积压)验证关闭代次中逐笔取消无法由本人处理的旧申请并保留证据。独立故障域、生产重判入口、试用环境恢复演练和邮件令牌仍待验收。

[兼容回退专项](architecture/operations-design.md#兼容回退专项)在同一个临时库切回旧版本后保留新版本完成的判题结果，并由旧 Worker 处理新版已接收的排队提交。同库实测从 schema 20 升至 25 再逐级回退，两版 API 分别拒绝不匹配的 schema。正式离线发布包及现场验收仍待验证。

[实验判题离线包](architecture/operations-design.md#实验判题离线包)在专用 Ubuntu VM 通过独立清单摘要核验，并在全新 Docker 与 containerd 存储中导入两份固定镜像、禁拉取判题。[本地冷 HTTPS 浏览器](../README.md#浏览器账号专项)已验证证书负对照、同源资源和真实账号登录。完整试用离线包、从空白系统安装运行时、校内 DNS／HTTPS／时间及现场断网流程仍待验证。

#### 试用容量和恢复默认值

2026-11-13 用户授权在缺少现场指标时采用合理默认值。下表是本项目 1A 的预定验收线，不是供应商承诺、通用标准或已有实测。测量采用 [Google SRE 的时延分位数与错误率方法](https://sre.google/sre-book/service-level-objectives/)；恢复目标定义参考 [NIST SP 800-34 Rev.1](https://csrc.nist.gov/pubs/sp/800/34/r1/upd1/final)。

| 场景 | 负载与通过条件 |
| --- | --- |
| 集中登录 | 100 个不同的合成账号，按 60 秒内均匀启动完整浏览器登录流程；从点击到会话核验 p95 ≤ 3 秒，至少 99 个在 10 秒内成功。意外失败（含限流、超时或服务器错误）合计 ≤ 1%。 |
| 混合训练 | 至少 100 个已登录主体，连续 15 分钟；每个每 10 秒发起一次题面、结果或本人历史读取，整体约 10 次读取/秒；每 5 分钟安排 30 人在 60 秒内各提交一次。使用已审核试用题集固定材料，包含小、中及最重候选，报告各类比例与版本。读取和提交确认分别 p95 ≤ 1 秒，意外失败各 ≤ 1%；提交到判题终态 p95 ≤ 60 秒，任一已接收提交 ≤ 180 秒且不丢失、不重复。选手正常 WA 等判定不计系统错误。 |
| 过载恢复 | 使用预先登记的试用配置把提交队列打满，记录拒绝、停止施压及排空的时间。超限新请求受控拒绝且不写入，已接收提交全部有可回读终态；停压后 5 分钟内恢复正常接收。原键重放不新增提交，拒绝后的原键重试可接收。无 OOM、进程异常退出或不可解释的提交丢失。 |
| 独立备份恢复 | RPO ≤ 24 小时：故障时点至最近可恢复且已离开主机的快照间隔不超过 24 小时。RTO ≤ 4 小时：从演练宣布源主机不可用，到恢复服务、校验材料、拒绝旧凭据并成功重判历史提交。使用可独立访问的另一台主机或存储服务，源主机关停或隔离；同主机的容器、卷或目录不计。实际备份位置、权限与值守人须演练前落地。 |

客户端通过实际同源 HTTPS 路径测量，记录每类有效样本数、p50/p95/p99、错误率、最长排队、CPU/内存/磁盘/连接峰值和恢复时间；桌面与窄屏另做完整人机流程。混合和过载至少各三轮，每轮均须满足对应目标。记录冷启动和公网带宽条件，不把回环测量当成公网验收。目标不达标时先定位和优化；变更阈值须在下一轮测试前留痕。

### P7 完整训练补齐

在 M1 闭环上逐项接入 C17、GNU++20、Java、Python，保留 GNU++17 回归；再补齐浮点和 SPJ。每项都固定工具链、检查器及配置版本，覆盖正确、错误、超限、系统故障、历史重判和多节点一致性。

C17 复用已发布本机文本题的冻结测试数据和审核权限，单文件使用固定 GCC C17 配置。本机 A+B 的 AC、WA、CE、TLE、MLE、OLE、本人回读及 GNU++17 回归已验证；另已验证同机双 Worker 并行及运行中退出后自然租约接管、历史提交重判。

GNU++20 复用同一已发布文本环境，固定 `g++ -std=gnu++20`。本机 A+B 的 AC、WA、CE、TLE、MLE、OLE 与本人回读，以及 C17、GNU++17 回归已验证；另已验证同机双 Worker 并行、SIGTERM 后自然租约接管和历史重判。

[Java 21](delivery-evidence/p7-java21.md) 使用单文件 `Main.java`、固定 JDK 制品和逐点 JVM。已发布 A+B 的浏览器提交、真实 Worker AC/WA/CE 与本人结果通过，C17、GNU++17、GNU++20 同镜像回归通过。另已验证 JVM 堆耗尽为 RE、沙箱总内存超限为 MLE，以及同机双 Worker 一致性、SIGTERM 后自然接管和历史重判。

[CPython 3.14](delivery-evidence/p7-python3.md) 使用单文件 `.py`、固定 CPython 3.14.10 和逐点解释器。已发布 A+B 的浏览器提交、真实 Worker AC/WA/CE/RE 与本人回读通过，C17、GNU++17、GNU++20 和 Java 21 同镜像回归通过。Python TLE/MLE/OLE、同机双 Worker 一致性、SIGTERM 后自然接管和历史重判均通过。

- 浮点验证逐题绝对/相对容差及 OR、等于边界、零与负数、科学计数法、非法/非有限值、混合文本；非法标准答案或配置阻止发布。

#### P7 的 Testlib SPJ 交付拆分

2026-11-03 用户要求支持 SPJ 库，以[洛谷 Special Judge 文档](https://help.luogu.com.cn/manual/luogu/problem/special-judge)中的 Testlib 检查器接口为兼容目标。SPJ 仍属于 1B/M2；P2 文本闭环与 M1 核心流程继续先行，不能将本次计划调整记作已实现。

以下列出按依赖顺序实现的功能；交付时按[根规则](../AGENTS.md#7-git-与审查)将同一阶段的功能组织为原子提交。契约与准入设计可先行，真实执行验收依赖已验证的隔离环境及题目版本/材料通路：

| 子项 | 交付内容 | 完成条件 |
| --- | --- | --- |
| P7-SPJ-1 库与构建准入 | 以洛谷文档引用的 Testlib 0.9.45、提交 `2d20123984e9479b8a56ebe0d6a51e23ad7c35b3` 为首个验证基线；核验许可、安全、GNU++17 兼容，固定头文件哈希、工具链与构建参数 | 在受限环境构建使用 `testlib.h` 的 `checker.cpp`；离线材料齐备且哈希可核验，编译失败阻止发布；基线通过前不宣称组件准入 |
| P7-SPJ-2 调用与结果适配 | 显式 Testlib 模式，按 `checker input output answer` 提供 `inf`/`ouf`/`ans`，规范化到既定 ICPC 边界 | 固定结果映射并覆盖正确/错误/格式错误、额外输出/意外 EOF、检查器失败、未知码及模式混用；首期不支持部分分，不能将不支持的结果猜成 AC/WA，详见[判题设计](architecture/judging-design.md#41-已确认的-spj-协议与-testlib-验证路线) |
| P7-SPJ-3 版本与受限执行 | 将源码/库/适配器/配置/构建制品绑定不可变题目版本，接入 Worker 及题目验证发布流程 | 编译/运行均有独立预算；选手不可读答案和检查器私有材料，检查器不可读凭据/网络/宿主；故障归 SE、失败验证阻止发布，旧版本可重判 |
| P7-SPJ-4 端到端验收 | 通过已有录入入口配置 SPJ，真实提交→Worker→结果/历史；维护代表性检查器及测试材料 | 非唯一答案的多种合法输出、浮点容差边界、严格整数混合、错误/畸形输出、检查器崩溃/超时/超限、历史重判、多节点和断外网回归均留证；M1 文本路径继续通过 |

无需改写为本站专用读写接口即可复用上述 Testlib checker 源码；不同编译标准、附加宏/参数及库版本须进入明确的支持矩阵。此目标不自动承诺完整洛谷题包导入、交互器、生成器、Hack/validator 或 `quitp` 部分分；这些能力单独排期。SPJ 源码及参考答案默认私有，检查器原始诊断仅经授权过滤后展示。
