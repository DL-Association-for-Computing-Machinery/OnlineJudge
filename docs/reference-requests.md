# 持久化参考验证申请

本页描述内部 Go 用例、PostgreSQL 申请账本与预期计划。它们提供申请、原键回执、取消和预期计划准备；专用参考 Worker 可通过默认关闭的节点接口领取短预留，并在有效期内下载与计划绑定的材料。`internal/problemvalidation` 继续负责维护验证。没有参考执行、续租、报告或作者 HTTP 管理入口，草稿 `not-run`、生产配置及发布阻断保持。

## 身份与可信配置

`NewCatalog`只接收维护装配层已通过`problem.LoadBundle`及显式受信来源锁验证的Prepared，保存脱离底层文件的ImportIdentity及由`problemvalidation.ResolveSource`产生的完整Profile。最多十来源且共用同一来源锁；允许空目录，以便退役全部来源后仍读取/取消既有申请。配置目录不持有Prepared或大材料文件，创建后修改输入map、关闭Prepared或移动材料目录不改变已保存的配置。

每份配置固定`source_id`、题目内容version、覆盖全部引用的import_revision、source_lock_sha256、`oj.reference-request.v1`及最多16KiB紧凑Profile原始JSON和SHA-256。Profile从封闭Resolver生成，调用者不能为某个申请指定预算。配置副本深复制字节，读取历史回执验证原字节摘要，不用当前Resolver重写旧Profile。`Specification.Valid`仅验证历史身份结构和字节一致性，不是Profile语义、材料或执行准入检查。允许受信合成锁验证持久化协议，不代表它可以通过实际Runner的固定来源锁门禁；现有Profile仅在固定Desktop维护环境验过，不能套用于未知服务器。

`Service.Enqueue(ctx, credential, requestKey, draftID)`只接受普通会话凭据、owner范围请求键及草稿ID；Receipt/Cancel只接凭据和原键。每次通过实际SessionReader取得当前ProblemActor，再由存储在同一READ COMMITTED事务重新核验恢复、账号和当前作者角色。凭据不入库；客户端不能提交主体、权限修订、来源锁、Plan/Profile或执行报告。单token退出在最后会话观察之后仍遵循已接受在途边界，不承诺Redis与PG原子撤回。

入库保存原`ProblemAuthorSnapshot`中的AuthGeneration、RecoveryID、RoleRevision及owner。以后受权准备、领取或接纳报告必须重新检查并比较完整快照；当前enabled不能使撤权后重授的旧任务复活。当前作者可读回/取消本人旧申请，回执和取消不把旧快照改成新权限。

## 事务、幂等与取消

锁序为恢复→账号→角色→本人草稿→policy→申请。problem公开窄`ReferenceAccess`适配器在调用方同一事务检查权限并锁定草稿身份；申请模块不引用problem或identity私有SQL。调用使用五秒context预算，另有独立一秒尽力回滚；不保证远端事务已结束。材料I/O及程序执行不在事务内。

申请先以owner/key无行锁查询原回执：相同draft_id返回原记录及原配置，不同draft_id为冲突。新申请才锁定本人草稿，再锁policy；取得policy后必须重新查询原键，最后才匹配当前目录与检查额度。第二次查询处理“并发赢家刚占满最后额度”的情况，不能将同键恢复误报为额度不足。原键恢复不依赖当前目录、额度或policy仍可用，也不会创建新记录。其他owner的键和不存在的键同为not-found。

当前只有`queued`和`cancelled`两种状态。取消先按owner/key只读定位，再按同样锁序锁草稿、policy和申请行，重读状态后原子更新queued→cancelled；重复取消返回同一状态和首次cancelled_at。它保留原ID、配置、授权快照及历史，不停止Worker，也不会重新排队。

新申请或取消在COMMIT回执失去且结果不确定时返回零结果及`ErrCommitUnknown`；保留原键，通过独立只读Receipt恢复。上下文在存储已成功后取消也按写回执未知处理。not-found仅是当次观察，不能证明另一个请求不在途；不使用新键绕过未知结果。只读回执失败不触发重写或清理。

## 有界排队与未完成边界

schema9默认创建空policy，缺失时拒绝新申请。只有显式受信维护调用`problemreference/postgres.Configure(ctx,pool,Limits)`才能设置额度，启动不会自动写入。`1≤Owner≤Global≤1024`，具体值是维护选择，不是硬件容量结论。下调额度不删除已接受记录；旧原键仍可恢复，新的不同键在超额时拒绝。

新增和取消都串行取得singleton policy行锁。计数沿用积压准入的MATERIALIZED窗口，最多读取Global条queued：达到窗口立即拒绝，未满时全局与本人计数均精确。部分B-tree `problem_reference_requests_queued_owner(owner_subject_id,id) WHERE state='queued'`排除终态历史，支持有界计数；每次入队和取消产生索引/WAL写入及存储成本，实际代价依分布而定。owner/key唯一索引支持回执，主键支持固定ID，配套真实查询计划归交付记录。

额度只限制 queued 数量，不限制历史增长、请求频率或正在执行的沙箱数量。永久撤权、账号禁用会留下仍占额度的 queued；本期没有隐式清理或绕过权限的维护取消。判题、维护参考验证与参考领取命令默认使用[同机共享执行槽](architecture/api-worker-design.md#同机共享执行槽)；后续参考执行须继续持有该门禁。两个独立队列限额不提供共享执行容量。

申请阶段不读大材料，不填Plan摘要、attempt、判定或Stop证明。内部 `Request.BindDraft` 可将回读的草稿元数据与 queued 回执绑定：核对草稿 ID、owner、私有状态、来源、版本和来源锁，按导入时的字节顺序对逻辑引用排序，并用原始文档字节和完整引用重新计算导入修订。版本相同但缺失、替换或新增证据引用也会拒绝。成功结果是独立副本；此操作不读数据库或对象存储，也不能用旧回执替代当前授权或当前申请状态。

## 从持久化对象冻结参考计划

内部 `Request.FreezeDraft` 使用已授权回读的草稿和申请。它先核对 queued 回执、完整导入修订，并要求原 Profile JSON 与当前受支持的完整 Profile 逐字相同；退役或变更的配置仍可读回执，但不可用新配置继续准备。调用方应在授权事务结束后用有期限的 context 调用，保存或执行计划前须重验实时申请状态及原授权快照。此方法不接管事务、租约或运行准入。

材料按 SHA-256 和长度从私有对象存储打开，不使用草稿的 bundle 路径。沿用固定来源布局和大小上限：校验完整的点目录与哈希清单，再依序冻结参考源码、允许的编译依赖及所有输入和答案。逐对象关闭存储快照，在 `MaxInFlight=1` 时也能工作。冻结文件为匿名临时文件；复制时复核实际长度和摘要，任何缺失、损坏或取消都不会返回部分计划。返回的 Plan 只含标识，摘要与同一导入的原维护路径一致；读取冻结字节不再访问存储或原 bundle。调用方须关闭快照以释放文件和进程内快照槽。

本路径包含一个冻结文件和至多一个正在复制的对象快照，两份临时文件分别使用进程临时目录和对象根。它与既有磁盘维护快照共享进程内单槽；这不是跨进程或判题/参考任务共享的执行槽。没有读取题面、图片、未选中的生成器或来源报告正文；其引用仍受完整导入修订约束。冻结成功不代表检查器域、运行环境、题源执行、报告接纳或发布通过。

## 实时复核与预期计划写入

内部 `PlanService.Prepare` 只接受普通会话凭据和原申请键。首次观察会话后，通过当前授权读取本人申请及草稿；冻结使用调用期限与三分钟准备上限中较短者。成功冻结并关闭快照后再次读取**同一凭据**，要求前后主体、账号授权代次和恢复代次一致。随后开启短 READ COMMITTED 事务，锁住恢复、账号、作者角色、本人草稿及申请行，核对实时授权快照与申请原快照相同（包括角色修订），再确认申请 ID、草稿修订、原 Profile 字节和 `queued` 状态未变化。材料 I/O、会话读取均在最终写入事务外；最后一次会话观察之后的单 token 退出仍遵循已接受在途合同。

预期计划由控制端冻结结果生成，写入原始 Plan JSON 与 SHA-256，长度上限 64 KiB，只有材料标识、顺序与来源身份，没有对象正文、凭据、判定或运行证明。申请行锁与取消串行化：取消先提交则不写计划；计划先提交则后续取消保留历史。计划不改变 queued 额度，因此不获取全局 policy 行锁。同一申请只能写入一行；重复准备仍须重新通过授权与状态检查，同字节幂等，不同字节拒绝且保留原值。

写入 COMMIT 结果不明时保留原键，调用只读 `PlanService.Receipt` 独立恢复。读取复核当前本人作者权、计划字节/摘要和申请身份；不会改写历史 Profile 或重新执行材料冻结。当前 Plan JSON 形状属于历史读取合同，变更字段或编码须保留兼容读取。读取校验不能替代执行准入。取消或重授后可在当前权限下读取既有计划，但不能用历史计划或回执恢复执行资格。

## 专用 Worker 领取

受信控制端配置 `OJ_WORKER_REFERENCE_NODE_ID` 后，指定且仍启用的节点可使用独立 URI SAN `spiffe://onlinejudge/reference-worker/{node_id}/{credential_version}` 调用[参考领取接口](../api/worker.openapi.yaml)。每次重验证书与节点状态；普通判题证书不能调用参考入口，参考证书也不能调用判题领取、续租、材料或回报。默认不启用。多个控制端使用同一数据库时，共享同一预留记录。

Worker 按申请 ID、固定来源和预期 Plan SHA-256 发起一次请求。先拿[同机宿主锁和对应物理槽锁](architecture/api-worker-design.md#同机共享执行槽)，忙或隔离时不发 HTTP；A+B 固定使用 primary，其余按来源对应固定档，不接双 M0 或槽别名。事务先锁节点，再以只读定位取得申请原作者，按恢复、账号、角色、草稿、申请、Plan 的顺序锁定并复核。只接受仍 queued、原授权代次和角色修订未变、草稿版本/导入修订匹配、当前固定来源锁及 Profile 原字节匹配、Plan 编码及请求摘要一致的申请。

数据库只保留一条全局参考预留，使用数据库时钟，30 秒内拒绝所有重复或其他领取；过期后才可重新复核并替换为新令牌。取消保持原预留期限，不重开执行权限，不更改草稿；丢响应可能已经占用预留，Worker 不自动重试。命令在同一宿主锁内领取并校验材料，结束即关闭匿名快照并释放宿主锁，不启动容器、不打印令牌。预留不能用来执行或回报；未来执行须持续持有同一宿主门禁并再次校验实时权限和 Plan。

## 有效预留内的材料下发

控制端同时配置 `OJ_WORKER_REFERENCE_MATERIAL_ROOT` 才启用参考 `assignment` 和 `material` 路由。该路径指向草稿入库使用的、已持久化的私有对象根；不会创建或修复目录，也不读取原 bundle。未配置时领取仍可用，但本版 Worker 的完整领取命令会因材料不可用而失败。材料访问使用同一专用 mTLS 身份，每个请求绑定申请、来源、预期 Plan 摘要和预留令牌；节点及凭据版本必须仍有效。

描述接口返回原 Plan 规范 JSON 的 base64 字节和保守剩余毫秒数，不传作者身份、完整草稿或存储路径。下载只能指定该 Plan 中的源码、固定编译依赖、测试目录/哈希清单或输入/答案的 SHA-256 与大小，不能任意读取对象根。每次操作沿用领取锁序复核原授权、queued 状态、草稿、当前 Profile/来源锁和预期计划，最后锁住唯一预留，再重新查询数据库时钟；等待行锁的时间也消耗预留。下载在事务外完整验证一个对象快照，然后用第二个短事务复核相同权限及计划，才允许写出。两次检查都不修改或延长预留，也不创建 attempt。

数据库剩余时间从事务开始的本地单调时刻换算为更保守的期限，约束对象读取与 HTTP 写出；写出同时设置连接 deadline，慢客户端不能无限占用材料槽。撤权或取消先于最终检查时不发送对象正文；晚于最终检查时可能已有授权字节在途，不保证立即撤回，后续对象会拒绝。传输失败保留截断响应，不追加 JSON。

Worker 从描述请求开始计时，用剩余时间减去完整请求耗时，避免依赖跨机墙钟。它复核操作员固定的摘要、规范编码、内置来源锁及固定布局/依赖/大小预算，再用相同目录解析器独立确认完整有序测试集合。逐对象校验长度和 SHA-256，顺序关闭网络对象，把源码、依赖和所有测试点冻结到共享单槽的匿名磁盘文件；不把整题材料保存在内存。损坏、缺失、截断、超时或最后对象失败都不返回部分快照。快照随调用取消/预留期限失效，须显式关闭释放文件；成功后不再读网络。这验证计划绑定的材料，不重新计算完整草稿导入修订或授予执行资格。

保留原 30 秒预留且没有续期。大题在低带宽下可能无法下载完成，失败并清理是预期行为；尤其不能由固定预算上限推断 3Mbps 目标服务器可在期限内完成。没有运行真实十题、服务器容量或部署验收。schema 仍为 11，无新表、索引或持久写入；新增查询只读取唯一预留行。

## 迁移与回退

二进制精确要求 schema 11。维护窗口排空并停止旧 API/Worker 及维护写入，独立 `migrate up` 后启动匹配版本；已运行旧进程不会因版本变更自动停止，不滚动混跑。此交付只在隔离临时数据库验证，没有改动持久化 localdev 或目标服务器。

迁移 11 新增单行预留表，读取申请与计划沿用主键，冲突检查用单行主键，不增加队列扫描。每次接受领取产生一次插入或更新及 WAL，活预留拒绝时不重写。Down11 按节点表、预期计划表、预留表加排他锁，仅空表可回退；即使唯一预留已过期，也不丢弃记录。

迁移 10 新增预期计划表，使用申请 ID 主键/外键定位，不改历史申请和队列索引。每个首次计划写入额外产生一条主键索引和 WAL，存储取决于实际 JSON 长度；重复同计划不重写。Down10 按申请表→计划表排他锁，仅当计划表为空才可回到 9，即使已有 policy 或申请也不改动它们。已有任何计划（含取消历史）须前向修复。

迁移9新增policy和requests，不修改既有草稿、角色、提交或材料引用。Down9按凭据表→申请表→草稿表→policy锁表，遵循实际首次表访问及删除外键触发器时所需父表锁，区别于业务行锁序；仅在**申请历史及policy均为空**时允许移除。已配置、queued或cancelled都拒绝，须前向修复，不能通过清表绕过。空库Down9/重Up9保留schema8及更早的既有资料；继续回退8/7/6分别按[草稿](problem-drafts.md#入库版本与迁移)和[积压](submission-backlog.md)合同执行。

普通Docker backend负责目录/服务单测及十种合成来源布局的冻结计划对照；四包sqlc及真实临时PostgreSQL验证所有权、并发最后额度、强制policy等待后的幂等、取消竞争、撤权锁、死事务、实际丢COMMIT回包、历史摘要损坏、查询计划及非空回退拒绝。冻结集成测试真实写入对象和 PostgreSQL，在移除合成 bundle 后重新打开二者并读取冻结计划。服务与真实PG的组合测试使用合成会话观察，不等同于 Redis、浏览器、实际十题大材料或 Worker 消费验收。命令归[README](../README.md#构建与测试docker-desktop)，结果归[交付记录](delivery-log.md)。
