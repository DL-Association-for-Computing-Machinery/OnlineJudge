## 单槽 Worker 生命周期

唯一目标为 P2、AC28/29 的执行端应用编排子项。`worker.New(claim, fetch, executor, reporter).Run(ctx)` 以四个小接口串联已有客户端与 `LeasedRunner.JudgeReport`；不依赖数据库、Docker 或日志全局状态，该模块不新增依赖、SQL、迁移、HTTP 契约和环境变量。宿主检查/传输/停止适配器由调用方提供并独占；命令接线见下节。

每槽一次只处理一题，必须等待回报确认才领取下一题。明确无任务时等待 1 秒再轮询；领取回执未知、材料失败、执行失败和回报拒绝立即停止。仅 `ErrReportUnknown` 允许最多 3 次总发送，每次间隔 1 秒，原租约令牌与冻结结果保持不变；不会重跑程序、重新下载或领取替代任务。重试耗尽后停止，无持久待回报队列，进程死亡或未确认结果依赖下节控制端任务自动恢复；执行端自身仍不自动重启。

实例为单次运行，重复或并发 Run 返回 `ErrStarted`，避免异常后复用旧槽。取消传给当前请求/执行器，不启动下一阶段；执行取消等待 LeasedRunner 完成停止确认和排空，保留 `ErrStopUnconfirmed`，不能只因 HTTP 已取消就释放容量。Run 返回后由调用方关闭传输，恢复前必须重新核验沙箱并创建新执行器。该取消策略会中止当前任务，产品级“停止领取但完成当前题”的平滑下线另行实现。

2026-10-28 验证：`GOPROXY=off make go-check db-test`（复用已有模块缓存）通过格式、vet、race、构建与真实临时 PostgreSQL/双控制端/双 API 回归。单元测试覆盖串行顺序、相同结果重报、11 类失败、重试耗尽、限速空轮询、并发/重复启动拒绝、各阶段取消及执行排空时停止失败保留。

`OJ_SANDBOX_EXPERIMENT=1 make report-test` 新增 `worker-lifecycle` 联调：两个真实 TLS handler、临时 PostgreSQL 和专用离线 Linux 沙箱中，一个 Worker 连续执行 AC、WA，首回报提交后丢弃响应，另一控制端重报；核验总计 3 次领取（最后为空）、3 次发送、2 个不同结果、5 次沙箱调用（编译/测试点），并逐题回读持久结果。原 8 项真实回报回归继续通过。实验提交与沙箱生命周期仍由测试驱动控制，两个 TLS handler 同进程；停止确认/排空失败在本次采用单元注入，不冒充真实节点故障或双 Worker 验收。

回退此应用编排子项无需数据迁移。完整命令、日志与环境收尾见[交付记录](delivery-log.md)。宿主适配器和命令入口已分别实现，后续验证双 Worker、恢复与会话，M0 未通过。

## 控制端任务自动恢复

唯一目标为 P1/P2、AC28/29 的控制端恢复调度子项。此前 `Store.Recover` 仅由测试手动调用，实际控制端进程不会将失联任务重新排队。`cmd/worker-api/recovery.go` 现将既有事务逻辑接入控制端生命周期，不改 SQL、迁移、协议、依赖或执行端行为。

配置/模式检查通过并成功绑定监听地址后，每个控制端启动一个串行扫描器，立即扫描，此后每轮结束等待 1 秒。每轮使用独立 5 秒上下文，复用 `Store.Recover` 最多 64 条事务批次；大积压分轮处理，失败同样等待，避免热循环。失败可能已经提交部分任务，只记录安全的恢复计数与通用告警，不输出数据库错误正文。停止或监听服务失败时取消并等待扫描结束，再关闭数据库池；无新管理接口或默认开放端口。

既有 SQL 以 PostgreSQL 时间判断过期，并覆盖节点撤销和凭据版本改变；`FOR UPDATE ... SKIP LOCKED` 允许多个控制端竞争，每次恢复保持源码、尝试历史和代次，第三次失败后任务为 `failed`、无选手 verdict。扫描是数据库级的，不限制材料版本；旧租约续租、下载和回报仍由既有授权与代次校验拒绝。扫描重新排队不证明旧选手进程已停止，也不清空执行端崩溃标记。恢复延迟受积压和数据库可用性影响，1 秒不是端到端恢复 SLA。

验证边界：单元/race 测试覆盖立即扫描、串行限速、失败后重试及脱敏计数、取消和等待在途扫描。真实临时 PostgreSQL 与两个控制端子进程覆盖启动前 65 条过期积压、有效租约不回收、重领唯一性、撤销/轮换、到期后旧回报拒绝及三次尝试上限；未调用手动恢复来代替调度。回报仍为合成值，本项没有运行选手程序、双 Worker 沙箱或会话测试。实际运行结果见交付日志。

回退控制端二进制即停止自动扫描，无数据库回滚；任务和结果保留，旧版本需受信任调用方恢复任务。未确认旧执行已停止的 Worker 继续保持隔离，不因数据库任务恢复而自动解封。

## 数据模型、边界与预算

提交模块拥有 `submissions`、`judge_tasks`、`judge_attempts`、`worker_nodes` 和实验材料注册表。HTTP 只调用提交用例；SQL 由 sqlc 生成到模块内部。题库模块尚未建立，`submission_materials` 仅用于 M0 固定夹具，不是正式题库发布接口。`fixture` 是显式命令，API 启动不会写材料或执行迁移。

提交固定源码、语言、版本与材料清单哈希。JSON 字段顺序不影响幂等摘要，源码空格/换行影响摘要并原样持久化。单文件源码上限 64 KiB；请求 JSON 上限 394240 字节，允许 JSON 字符转义的体积膨胀。空源码、NUL、非法 UTF-8、未配对的 JSON UTF-16 代理项、未知字段与尾随 JSON 被拒绝。解码前由标准库检查 JSON 语法，并单独检查代理项配对，避免 `encoding/json` 将非法代理项静默替换为 U+FFFD；合法代理对、字面量反斜杠及用户原本输入的 U+FFFD 仍允许。

任务状态与判定分开：`queued/running/finished/failed`；只有 `finished` 带判定，系统故障或节点失联耗尽重试后为 `failed`、`verdict=null`，不冒充选手 WA/RE。重判代次、恢复代次与尝试编号分开。每个尝试保存节点凭据版本、随机租约标识、截止时间及已接受结果摘要/载荷；旧代次和旧尝试不能覆盖有效结果。同代次已接受的历史重复回报可确认而不覆盖新尝试。重判及灾备恢复管理用例尚未实现，测试直接修改代次只证明更新条件的隔离能力。

M0 实验参数：每 API 连接池上限 4；连接/查询及操作超时 5 秒，锁等待 3 秒；每次仅领取 1 个任务，节点容量由管理员记录控制（默认 1，最多 8）；租约 30 秒，最多尝试 3 次，每次恢复最多 64 条且总超时 5 秒。`cmd/worker-api` 现自动调用恢复扫描，每轮完成后间隔 1 秒；任务恢复与执行端进程恢复分开验收。上述值是有界实验配置，**不是用户确认的吞吐、RPO/RTO 或生产容量目标**。

M0 领取暂用 FIFO；M1 前仍须实现既定参与者公平调度、用户/全局共享额度及资源能力匹配。持久化方法供受信任控制端使用，不能把 `NodeIdentity` 当成来自客户端的认证结果。Worker 执行端经 mTLS 领取任务，不持有数据库凭据。

索引：提交主键用于 ID 查询；`(subject_id, context_id, idempotency_key)` 唯一索引用于并发去重/回执定位；任务主键支撑一对一关联；材料联合唯一约束固定版本/哈希；尝试唯一约束防止同代次重复编号。活动节点、到期尝试、排队任务使用部分索引。代价是每次插入及状态变更维护索引、额外存储和 vacuum 压力；正式调度及大样本负载下需再测。回执的 `EXPLAIN (ANALYZE, BUFFERS)` 验证索引路径可用，测试为小夹具并显式关闭顺序扫描，不作为容量或延迟承诺。租约的真实并发测试验证行锁/条件更新；大队列查询计划与负载尚未验收。事务只覆盖数据库操作，编译执行不持有数据库锁。

`make worker-api` 或构建后的 `.local/bin/worker-api` 启动，SIGINT/SIGTERM 在 10 秒预算内排空连接。缺配置、无效证书或非 loopback 地址拒绝启动。TLS 最低 1.3、强制验证客户端证书链并禁用会话票据。客户端必须使用专用 CA 签发且用于 ClientAuth 的证书，唯一 URI SAN 为 `spiffe://onlinejudge/worker/<node_id>/<credential_version>`，节点 ID 仅 1—128 个字母、数字、下划线或连字符，版本为无前导零的正 int64。CN、请求体和代理头均不能提供节点身份。测试每次动态生成 CA/私钥，临时文件仅 owner 可读；仓库无静态证书或密钥。

每次请求重验证书链/有效期，每个数据库操作在原事务内锁定节点并校验启用状态和凭据版本。撤销提交后，原连接下一次操作也被拒绝；轮换版本后，旧证书及旧租约不复活。证书签发、续期和到期告警工具尚未交付；不实现 CRL/OCSP，当前即时撤销依据节点禁用/版本递增。专用 CA 变更需重启控制端，不能把这个实验称为生产 PKI。

三个 POST 入口 `/api/v1/worker/claim`、`renew`、`report` 分别接收 `{}`、`lease_token`、`lease_token + verdict + evidence_sha256`。JSON 上限 1024 字节，未知字段、null、尾随 JSON、无效令牌/结果拒绝；所有响应禁止缓存，租约令牌不放 URL。领取受管理员容量约束、无任务返回 204；续租和有效新结果仍受原租约到期与代次条件保护。相同已接受结果可确认，不同结果 409。503/断连不证明事务未提交：领取丢失响应可能占用容量，现由控制端到期扫描恢复；续租失败须停止执行，回报确认丢失沿用原租约原结果核验。执行中止的独立模块见下节；双 Worker 与完整 M0 仍待后续验收。

验证：`make go-check db-test` 在 macOS arm64、Go 1.26.10、PostgreSQL 14.19 通过；集成测试实际构建并启动两个 `worker-api` 子进程及两个 mTLS 客户端，覆盖竞争认领、跨控制端续租、异节点拒绝、重复/冲突回报、同连接撤销、轮换、到期及旧尝试。单元测试通过真实 TLS 验证无证书、错误 CA/用途、过期证书及非法身份拒绝，并用可控时钟验证连接建立后的过期。结果均为合成夹具，没有运行选手代码或宣称双 Worker 闭环。

回退：停止新增控制端即可恢复原进程组合，无数据库迁移或历史结果重写；已领取任务保留，须按现有有界恢复方法处理，不能删除任务清理。不要对有真实数据的数据库运行实验测试。当前只支持同机协议实验，跨主机认证及固定执行环境须独立验证。

## 有效租约限定的材料入口

2026-10-27，在已合并 PR #2 的 `4698b1f` 上新增单一功能：节点取得自己当前尝试的源码、固定清单和测试输入/答案。`POST /api/v1/worker/assignment` 接收 `lease_token`，返回原样源码、源码 SHA-256、固定清单哈希及清单规范字节的 base64；`POST /api/v1/worker/material` 额外接收 `test_id` 和 `kind=input|answer`，返回原始字节、`Content-Length` 和 `X-Content-SHA256`。令牌不放 URL，沿用 1024 字节请求预算和 no-store；清单限 16 KiB、64 测试点，源码仍限 64 KiB。无任意路径/哈希读取入口，详情见 [OpenAPI](../api/worker.openapi.yaml)。

提交模块拥有源码/清单授权的 `MaterialStore` 接口，`postgres.Materials` 按原节点 → 任务/尝试锁序校验节点状态、版本、尝试及双代次；取得锁后用数据库 `clock_timestamp()` 检查截止时间。`internal/materials.Service` 依赖该接口和仅按摘要打开已验证快照的 `Reader`，不直接依赖 PostgreSQL。文件 I/O 不持有数据库锁，校验完再次取得授权；响应释放前也重验证书。已完成、过期、异节点、旧凭据/尝试/代次返回 403/409；不在有效清单中的测试点返回 404；磁盘异常、哈希不符或未配置返回 503，不泄露内部路径，不转成选手 WA。客户端须完整接收并对照清单哈希校验，截断不可使用。

本地适配器通过标准库 `os.Root` 限定根目录，仅以服务端选择的 64 位十六进制摘要为文件名，拒绝符号链接、FIFO、目录和非普通文件；不新增依赖。每文件最多 1 MiB，每控制端最多 4 个活动快照，超额立即 503。流式写入 0600 临时文件并立即 unlink，完整 SHA-256 校验后只发送该私有快照，原文件随后变化不影响已验证字节；成功/失败/取消/传输结束均释放句柄与额度。快照位于系统临时目录，最多约 4 MiB/进程，需可用磁盘；不是持久缓存。支持当前 Linux/macOS 环境，不能作为恶意宿主管理员或任意远程文件系统的安全边界。放行后传输不持续锁定授权记录，已经发送的字节不能撤回。

```sh
chmod 700 .local/materials
export OJ_MATERIAL_ROOT="$PWD/.local/materials"
.local/bin/migrate fixture
make worker-api
```

上述命令仍须已有 `OJ_DATABASE_URL` 和前节 TLS 配置。`fixture` 在配置根目录时先写四个合成文件，fsync 完整文件并通过不覆盖的原子 hard link 发布，再注册数据库引用；重复初始化核验已有文件，冲突不覆盖。文件/数据库不共享事务，失败允许留下未引用合成文件并重试；尚未验收断电一致性、磁盘耗尽和正式发布回收。未设置根目录时保留原数据库夹具初始化行为。控制端只打开已有目录，路径无效拒绝启动；未设置时材料接口 503，租约接口不变。同机副本必须使用同一持久化目录，不向执行节点暴露主控目录或数据库凭据。

## 受限执行编排

唯一目标为 P2、AC05/06/17/20 的固定 GNU++17 文本夹具编排子项。`execution.New(sandbox).Judge(ctx, descriptor, blobs)` 接收已由控制端授权的材料快照和按 SHA-256 索引的内容，再核验源码、规范清单和全部测试材料。只接受与内置 `m0-sum-v2` **逐字节一致**的清单及固定环境；v1、未知配置、缺失/损坏材料在编译前拒绝。该模块不代替有效租约授权，不自行领取或回报。

模块通过 `Sandbox` 小接口依赖执行设施，核心不依赖数据库或 Gin；`GoJudge` 负责 v1.13.3 REST 适配。每个 Runner 限一个活动尝试，忙时立即拒绝；没有后台无界排队。每次编译一次，编译制品仅在本次尝试内复用，每点独立 `/run`，只有前点 AC 才启动后点。参考答案留在编排侧，不传入编译器或选手运行环境。未运行点为 `NOT_RUN`、usage 为空；编译统计独立，汇总取实际运行点最大 CPU 和峰值内存，无运行点时汇总为空；输出截断明确标记。

适配器必须注入受信任宿主检查器和传输；先核验实际 image ID、内核、编译器、外层容器隔离，再检查 REST 版本、cgroup v2、cpu/memory/pids 和 seccomp。不存在默认网络传输。当前 `tests/sandbox` 通过既有固定 Docker context、`docker exec` 和容器 loopback REST 驱动真实编排；它是实验驱动，不是已部署 Worker 客户端。参考版本定义见 [go-judge v1.13.3 模型](https://github.com/criyle/go-judge/blob/v1.13.3/cmd/go-judge/model/model.go)。

编译非零退出或已证实的预算超限为 CE；编译器异常信号、文件/设施错误为 SE。运行资源结果映射为 TLE/MLE/OLE，非零退出、信号及受限系统调用为 RE；正常零退出才比较答案。未知、矛盾、缺字段和响应超限为 SE。REST 总响应限 128 KiB；输出超限必须有 `CollectSizeExceeded` 结构化证据，按[固定版本收集器](https://github.com/criyle/go-judge/blob/v1.13.3/envexec/file_collect.go)处理保留的上限 + 1 字节，普通文件错误仍为 SE。运行 stderr 单独超限的归因未纳入公布的 stdout 规则，保守返回 SE。JSON 可能把非法 UTF-8 字节变为 U+FFFD，因此解码文本预算最多为原字节预算三倍；固定数字答案不会与该替换字符匹配，实际 4096 个非法字节回归为 WA。这不是通用二进制保真输出协议，扩展题目之前须改用保真传输并另验。

编译/运行请求分别有固定墙钟预算加 5 秒传输余量，环境检查 10 秒，制品删除使用独立 5 秒上下文。成功、CE、运行失败和取消路径均尝试删除已知制品；清理失败改为 SE。开始编译后的传输、协议、取消或清理错误会将 Runner 标为不可复用，避免远端执行状态不明时释放容量后继续投递；必须由节点所有者确认恢复后重建 Runner。HTTP 取消不证明远端进程已终止，丢失响应可能留下未知制品，本轮不承诺远程 kill 确认或节点自动恢复。

验证：macOS arm64 / Go 1.26.10 的 `GOPROXY=off make go-check go-build` 通过（Make 参数指定已有 Go 缓存，无依赖下载）。`OJ_SANDBOX_EXPERIMENT=1 GOPROXY=off make sandbox-test` 在专用 `oj-m0` VM 通过新增 10 项真实编排验收及原 12 项隔离回归。新增覆盖 AC、首/末点 WA、CE、RE、TLE、MLE、OLE、非法 UTF-8 输出和逐点文件隔离，并逐例核验制品清空。异常材料、环境、协议、取消、容量与清理失败通过单元注入验证；不冒充真实租约中止或双 Worker 联调。

本轮不改变 API、数据库、依赖、默认配置和 `cmd/worker` 行为。回退本模块及实验测试无需迁移或重写历史任务；实际节点出现未知在途状态时须先停止接收并确认执行/制品清理，不能仅重建 Runner 宣称恢复。

## 租约守护与中止确认

唯一目标为 P2、AC28/29 的租约执行生命周期子项。`execution.NewLeased(sandbox, renew, stop).Judge(ctx, token, descriptor, blobs)` 独占底层 Runner 与沙箱；调用方必须把同一有效租约授权取得的材料交入。`workerclient.NewRenewer(endpoint, roots, certificate).Renew` 可作为 renew 回调，仅使用显式 HTTPS、专用 CA 和节点证书，TLS 最低 1.3、不跟随重定向、单主机单连接、3 秒请求预算、1024 字节响应上限，不把令牌、响应正文或 URL 放进错误。无自动续租重试，无新增依赖或公共 HTTP 契约变化。

执行前必须成功续租；执行中每 5 秒续租。依据现有控制端固定 30 秒续租契约，从**请求发出前**的本机单调时间保守计 25 秒有效预算，不用跨主机墙钟直接比较 `lease_until`，网络往返占用预算。每次请求最多 3 秒且不能越过上次本地截止；失败、拒绝、超时及迟到成功均停止执行。服务端租约时长若改变，必须同步调整此策略并验证；数据库时钟跳变、宿主长时间挂起和生产时钟治理仍须专门实验。

失效、取消或执行基础设施错误后，先取消上下文，再以独立 10 秒上下文调用 `StopSandbox`。该回调必须停止**整个独占沙箱**并阻止后续请求，仅取消 HTTP 不符合契约。停止失败返回 `ErrStopUnconfirmed`；无论确认成功与否，旧 LeasedRunner 永久停用。等执行与清理返回后才结束调用，所有适配器必须遵守上下文；不允许共享沙箱，不自动恢复。正常编译失败/选手失败仍是正常结果，不停止健康容器。失去租约时总体结果强制 SE 且带错误，禁止当作可回报结果；最终数据库回报仍必须单独核验租约。

实际证据分层：单元/race 测试注入编译/运行期间的撤销、到期、传输失败、超时、迟到响应，验证周期续租跨过初始预算、未执行点、清理/停止期间容量、取消与完成竞争、永久停用和停止失败。真实双控制端＋PostgreSQL 测试使用新客户端验证跨实例续租、异节点和已完成租约拒绝。`TestLeasedExecutionConfirmsHostStop` 在专用离线 VM 观测真实休眠选手 PID 后取消，用固定容器 ID 执行 KILL，检查 `Running=false/Pid=0/Restarting=false` 及 VM `/proc/<pid>` 消失，后续点保持 NOT_RUN，旧 Runner 不能复用。测试恢复容器后重跑原 10 项编排与 12 项隔离回归，全部通过。

本节首次验证时停止适配器为 `tests/sandbox` 实验驱动，后续已接入前述可信宿主；续租在该真实沙箱用例中为注入成功响应，不能称为数据库撤销到沙箱的完整联调或生产节点驱动。KILL 行为依据 [Docker 官方文档](https://docs.docker.com/reference/cli/docker/container/kill/)，停止事实以上述实际状态/PID 检查为准。首次 PID 核验因 Colima SSH 继承无挂载的宿主仓库目录而失败，驱动固定 `/tmp` 后重跑通过，没有放宽断言。真实回报、领取/材料客户端现已在下节独立验证；执行端自动恢复、双 Worker 与完整 M0 未完成。

复现：`GOPROXY=off make go-check db-test`；已有专用 VM/容器按前置启动后，`OJ_SANDBOX_EXPERIMENT=1 go test -race -count=1 -tags=sandbox ./tests/sandbox -v`。本机依赖复用缓存，具体命令/日志见交付记录。无迁移/配置变化；回退本次代码即可，实验容器恢复必须在旧请求排空后重新核验环境，数据库任务与历史保留。

## 真实结果回报

唯一目标为 P2、AC28/29 的真实结果归属与可靠确认子项。`LeasedRunner.JudgeReport` 在执行前核对提交 ID、租约格式及正数代次/尝试号；复用已验证材料与租约守护，只有执行和制品清理成功才返回 `submission.Result` 值。执行、清理、租约、取消或停止确认错误均不生成可发送结果，交由控制端有界恢复处理；现由上述自动扫描调度。客户端不能把本地错误转换成选手失败，也不会在失去授权后发送 SE。

`m0-execution-evidence-v1` 的固定结构 JSON 摘要绑定提交、判题/恢复代次、尝试号、材料版本、语言、源码/清单哈希、最终判定、编译状态/退出/资源/截断证据、有序逐点状态/资源/截断及峰值。清单哈希绑定环境、检查器和测试顺序。凭据、源码正文、答案、原始输出、临时制品 ID 不进入摘要对象；回报正文仅发送租约令牌、判定与摘要，不输出令牌到错误或日志。摘要结构演进须更换 schema 标识；服务端仍按现有结果指纹进行去重，HTTP/SQL/迁移保持兼容。摘要是可信节点的证据指纹，不是对恶意节点的远程证明；详细证据归档仍待实现。

`workerclient.NewReporter(...).Report(ctx, token, frozenResult)` 使用独立 mTLS 客户端连接预算，沿用续租的显式 HTTPS/CA/节点证书、3 秒超时、禁止重定向。只把 204 当作确认；401/403 为节点失效，409 的有界 Problem Details 区分租约失效与结果冲突；断连、超时、503、异常状态/正文均返回 `ErrReportUnknown`。无隐式重试；调用方保留原租约和已冻结结果原样重报，不能重新执行以重算摘要。当前仅返回内存值，无磁盘待回报队列、崩溃恢复或自动重试调度。执行结束至回报的授权竞态由数据库最终校验；已经接受的完全相同历史回报仍可确认。

验证：`OJ_SANDBOX_EXPERIMENT=1 make report-test` 建立独立临时数据库，先运行既有双 API/双控制端回归，再通过专用离线 Linux 沙箱、真实 mTLS 续租、两个 TLS handler 和 PostgreSQL 跑 8 项联合用例。AC/WA/CE/RE/TLE/MLE/OLE 均真实执行并持久化；服务端提交后主动断开响应，另一控制端原样重报通过，修改摘要返回冲突、错误节点拒绝；真实 AC 在节点撤销时拒绝，另一个真实 AC 到期后不生效。逐项回读数据库中的 verdict 和摘要。2026-10-28 已将领取/材料准备替换为下节客户端并重跑通过；两个 handler 仍在同一测试进程内，独立控制端子进程另由 `db-test` 验证，不能称为双 Worker 端到端交付。

单元/race 覆盖摘要归属、用量、未执行点、私有临时信息排除、清理失败/失租/取消不生成回报、未知响应/重定向/超时及原样重试。未引入依赖、公共配置或数据库变更；回退新增调用方即可，保留已接受的历史结果与任务。领取/材料客户端见下节；Worker 入口和控制端扫描现已实现，生产停止驱动、执行端自动恢复、详细证据保存、双 Worker 与会话仍未交付。

## 领取与材料客户端

2026-10-28，基于 PR #8 合并提交 `64b9992` 的独立 `codex/claim-material-client` 分支，完成 P2、AC22/28/29 的单一子项。`workerclient.NewAcquirer(endpoint, roots, certificate)` 提供 `Claim(ctx)` 与 `Fetch(ctx, lease)`，复用既有专用 CA、TLS 1.3、禁止重定向的传输配置；独立单连接预算，不阻塞已有续租/回报客户端。不新增依赖、SQL、迁移、HTTP 接口或运行配置。

`Claim` 每次只发一个 POST，校验 32 位十六进制提交 ID、64 位租约令牌、正整数双代次/尝试及有效时间格式。204 返回 `ErrNoTask`，401/403 返回 `ErrNode`；断连、超时、非预期响应或不完整回执返回 `ErrClaimUnknown`，不自动重领。未知结果可能已占节点容量，须由后续受信任恢复机制处理，不能断言事务失败。截止时间只作记录，实际执行仍依赖 `LeasedRunner` 前置续租和单调时限。

`Fetch` 仅支持与执行器一致的规范 `m0-sum-v2`，先校验任务归属、源码与清单哈希及固定环境，再按清单顺序下载四个文件。每次请求带原租约并由服务端重新授权；要求 octet-stream、明确长度、摘要头及实际 SHA-256 一致。源码限 64 KiB，清单为固定规范字节；JSON 响应限 `6*MaxSourceBytes+32768`（兼容转义/base64），文件限 `judging.TextBudget`（1 MiB），合计最多 4 MiB。单请求最多 3 秒，整次 Fetch 最多 15 秒；无重试、无磁盘缓存，错误不暴露响应正文、URL 或凭据。任何失败均返回空描述和 nil 材料，不能把部分材料交给执行器或回报选手判定。代价是每次重新下载，尚不支持通用题包或大材料。

同一命令的 8 项真实沙箱联合用例已用新客户端完成领取/下载，再调用已有租约执行器并回报；参考答案未加入选手执行请求。实验提交与沙箱生命周期仍由测试驱动控制，两个 TLS handler 同进程，独立双控制端测试不等于常驻双 Worker。未重跑未修改的独立隔离/中止专项，既有证据保留为历史；无本地前端变更或重测。回退只撤销新增调用方，保留租约、任务、结果和材料，无数据库回滚。

## 撤销与材料故障联调

`OJ_SANDBOX_EXPERIMENT=1 make worker-fault-test` 对应 P2、AC28/29 的有限故障阶段，只使用既有 primary 槽、临时私有 PostgreSQL、临时测试 CA/节点和合成材料。先运行原数据库/双 API 回归；随后每种故障启动两个真实 mTLS 控制端，Worker 仅通过协议领取/下载/回报，不持有数据库凭据。

四种情形：观察到运行中选手 PID 后禁用节点或递增凭据版本；删除或损坏最后一个答案文件，使前三份有效材料无法形成完整集合。检查故障 Worker 非零退出、容器 `Running=false/Pid=0/Restarting=false`、已观察 PID 消失、尝试无结果载荷/选手 verdict，且排队的下一题未被领取。

测试驱动修复自己创建的临时材料，显式重启原容器并重新核验固定环境，再启动新的 Worker。禁用场景使用另一节点；轮换场景使用同节点新版本证书。实际控制端扫描回收旧尝试；材料故障等待固定 30 秒租约自然到期，不修改时间戳或手调 Recover。原题在判题/灾备代次均为 1 的第 2 次尝试真实 AC，后续题也完成。将新尝试结果配旧身份/令牌向两个控制端回报，均拒绝且新结果字节不变；这是授权探针，不表示故障节点曾冻结结果。

边界：续租间隔 5 秒、单点 wall 上限 2 秒；运行中撤销可能在受限执行结束后的回报阶段被拒绝。本专项证明故障不生效及最终停止，不证明数据库撤销瞬间杀进程，亦不替代长编译期间续租取消的专项证据。材料失败不执行半套数据的直接调用计数由既有客户端/Worker 单元测试覆盖；本次进程级检查不靠“未观察到 PID”断言从未执行。没有业务代码、协议、SQL 或依赖变更；回退专项测试和命令即可，无迁移。实际执行结果与日期见[交付日志](delivery-log.md)。

执行端自动重启/解封、持久结果队列、SIGKILL/网络分区/跨主机故障、会话和完整 M0 仍待独立验收；普通 PR CI 不运行该特权实验。
