# P6 试用值守手册

本手册用于经授权的试用发布、故障处置和独立恢复演练。先填写本轮实际环境和负责人；本页没有指定可操作的试用服务器。桌面或单宿主 VM 的回归只能作为预演证据。完成情况登记到 [P6 验收清单](delivery-evidence/p6-trial-acceptance.md)。

## 演练前登记

| 记录 | 开始前应能回答 |
| --- | --- |
| 责任与时间 | 谁负责入口、数据库、Worker 和备份；谁能暂停、批准回退及重新开放；维护起止、最长等待和停止条件是什么？ |
| 拓扑与预算 | 哪个入口是唯一公开 HTTPS 写入端？DNS、校内 CA 和时间源是否可断外网使用？实际 API 副本、Worker 槽位、进程托管、连接与磁盘预算是什么？ |
| 版本与回退 | 已核验的发布清单摘要、上一版制品、各自兼容的 schema、已审题目及材料档位是什么？哪一步以后只允许前滚？ |
| 故障域与权限 | 源、备份、恢复端实际宿主及底层存储是什么？源端不可用后，谁能从独立位置读取副本、解封必要配置并管理恢复端？ |
| 验收与证据 | 哪些合成账号、已审材料和历史提交用于验收？如何收集应用、代理、Worker、数据库及存储证据？保存哪份发布与拓扑摘要？ |

使用[发布清单核对](../README.md#核对同一批试用制品)、[只读空间预检](../README.md#试用服务器只读盘点)和[恢复拓扑登记](architecture/operations-design.md#试用恢复计时与证据)。真实配置和密钥通过独立受控渠道交接。未确认任何写入目标、权限、回退路径或必要证据时，不进入操作窗口。

## 发布、排空和兼容回退

1. **冻结入口写入。** 对实际使用试用 Nginx 模板的入口启用[暂停写入标记](../README.md#试用入口暂停写入)。覆盖每个公开入口和 API 副本，并独立暂停可绕过入口的维护端写入。用合成探针确认新请求被拦截；保留已经接收的 ID、原键回执及排队数。若某请求回执未知，按原键核对后再决定重试。
2. **排空执行。** 对已确认支持排空的 Worker 按 [SIGUSR1 流程](../README.md#worker-排空下线) 下线，控制端留到回报结束。确认各 Worker 与执行槽确已停止、无在途宿主控制操作，再停止控制端、API、发信和其他写进程。使用[判题快照](../README.md#判题运维快照)辅助对账；租约失效或运行数为零不能替代进程和执行槽停止证据。排队提交可以保留。超时或停止不明时保持入口关闭，按原槽恢复流程排查，不手动清除占用标记。
3. **独立迁移。** 记录当前库名、实际连接端点、schema 和已接收回执；确认无人继续写同库。用已登记版本的迁移工具按 [CI/CD 迁移规则](ci-cd.md#迁移恢复与比赛保障) 执行，迁移前后都用 [schema 只读回读](../README.md#迁移前后回读-schema)记录实际版本。超时或断连先回读，并确认上一迁移进程已经退出；不盲重试，不修改迁移版本表。
4. **隔离验证后切流。** 只启动兼容该 schema 的 API、控制端和 Worker。依次核对进程存活、普通会话就绪、预期 Host/证书、合成登录、正式题面、本人训练提交终态及原键回读；确认维护前接收的回执仍可读，再解除入口限制。多副本逐个核对共享库、Redis 与会话配置，避免双写入端。只读就绪成功不能替代真实流程。
5. **回退判断。** 冒烟失败时重新冻结写入并排空。若旧版与当前 schema 兼容，可在同一数据库切回原制品；如需向下迁移，必须满足该版本对已验证的门禁，先确认受保护账本及实际库状态。重判审计或邮件账本非空且门禁拒绝、状态未知或无经过验证的版本对时，保持维护并前滚修复。已接收的新提交和历史结果须逐笔对账，不能用覆盖现库的旧快照完成普通回退。

## 独立故障域恢复

1. 演练前把[一致性备份](architecture/storage-design.md#捕获逻辑备份)转入已登记的独立位置，独立交接源端完成清单摘要。从恢复端实读、[核验整套归档和材料](architecture/storage-design.md#核验收到的逻辑备份)，记录 `offsite_copy_verified` 的 UTC 时点。副本依赖源宿主或源存储、摘要不符或权限不足时，不启动计时演练。
2. 宣布故障、记录 UTC 时点，确认源端与所有旧写入进程隔离，并保持到复判完成。在另一已登记的隔离目标还原到空库，布置与清单匹配的材料；用[恢复材料核验](architecture/storage-design.md#恢复材料核验)检查恢复库的引用和哈希。材料缺失、还原状态未知或双写可能存在时，停止开放。
3. 在恢复副本中按[恢复提交租约](architecture/operations-design.md#恢复提交租约)隔离旧在途任务，按[恢复普通会话](architecture/operations-design.md#恢复普通会话)换代关闭、完成账号对账并初始化新的专用 Redis。重新开放会话门禁前处理[旧参考积压](architecture/operations-design.md#恢复参考验证积压)。邮件按[旧邮件授权与密钥用量约束](architecture/operations-design.md#回档后的旧邮件授权)核对，未通过时发信执行器保持关闭。
4. 在仍隔离的入口验证旧 Cookie、已启用邮件能力对应的旧令牌，以及旧 Worker 在途租约被拒绝。验证允许账号重新登录、历史源码与旧结果原样读回，再用[受控重判](rejudge.md)对同一历史提交产生新代次并保留原结果。独立确认源端仍隔离；任一应验证的能力缺证据时，不宣布通过、不向用户交还服务。
5. 留存七份脱敏原始观察、备份清单和预登记拓扑摘要，运行[恢复证据核对](../README.md#核对-m1-恢复证据)。保留 RPO、RTO 和失败项，人工确认实际故障域、隔离和重判。完成演练不自动授权部署或切换。

## 当班故障处理

| 现象 | 先确认 | 处理及恢复条件 |
| --- | --- | --- |
| 存活但未就绪、登录失败 | 入口 Host/证书和 API 就绪；schema、恢复门禁及 Redis 的实际状态 | 暂停开放并定位故障；恢复后用新合成会话验证。不得为通过探针关闭 TLS、来源验证或恢复门禁。 |
| 队列积压、SE 增多、运行无有效租约 | 只读快照、控制端与 Worker 事件、槽位是否确实停止、原回执和资源读数 | 保留已接收记录，按原键处理未知回执；已满时受控拒绝新请求。恢复后读回原任务终态，并按[过载记录要求](delivery-evidence/p6-trial-acceptance.md#过载恢复记录核对)验证新键接收。 |
| 磁盘字节或 inode 不足 | 实际设备、配额、共享卷、写入状态及占用保护 | 停止可延后的后台工作与新写入；只按批准的保留流程处理确认可重建且未被引用的内容。复测字节和 inode 余量后再放行，不删除核心提交、历史材料、在途任务或备份引用。 |
